# S0 · 立项与边界

> 上游：无（体系起点）· 下游：S1 取证 · 门禁：G0 · 档位：A/B/C 全必做

## 一句话

用不超过 2 小时，把「为谁解决什么问题、这一版明确不做什么、要复刻的那一份字节到底是哪一个」写成三页纸；此后每个阶段只从这三页纸取约束，不再重新讨论范围。

## 输入

S0 是唯一没有上游产物的阶段。它的输入是**人的口述**加**一份目标制品**。

| 从哪来 | 内容 | 缺了就不许开工的判据 |
|---|---|---|
| 产品官口述 | 想复刻哪个应用、为什么不用原版、给谁用 | 说不出「为什么不用现成的」，只说得清「好用/顺手」→ 不许开工 |
| 目标制品 | 安装包 / DMG / EXE / 线上 URL / 自己账号的访问权 | 只有应用商店页面链接、没有一份可固定哈希的制品 → 不许开工 |
| 本机环境 | Python 3、`shasum`、`file`、`plutil`/`otool` 或浏览器 | 环境跑不起来 → 先解决环境，不要先写文档 |

**不接受**「网上都说这个 App 好用」「我想要一个像 X 那样的东西」——那是选题不是输入。选题要落到一个具体制品上才能进 S0。

## 动作序列

### 1 · 生成项目骨架（5 分钟）

```bash
# 在体系根目录（本文件所在目录的上一级）执行
./scripts/new-project.sh ../rebuild --target "目标应用 8.x" --tier A
```

创建 22 个目录、复制模板到项目根、生成 `.replica/gate.manifest.yml`，并首跑一次 G0（预期失败，模板还没填）。判据：存在 `PROJECT.md`、`REDLINES.md`、`AGENTS.md`、`STATE.md`、`.replica/gate.manifest.yml`、`BLUEPRINT/`、`SPEC/`、`TEST/`、`REPORT/`。

### 2 · 档位判定（10 分钟，答四个问句）

| # | 问句 | A 的答案 | B 的答案 | C 的答案 |
|---|---|---|---|---|
| Q1 | 除了你，还有谁会打开这个东西？ | 只有我 | 2–5 个身边的人 | 不认识的人 |
| Q2 | 它需要出现在别人的安装列表、商店、域名里吗？ | 不需要 | 私有分发即可 | 需要公开 |
| Q3 | 出问题时谁承担后果？ | 我自己 | 我负责但不收钱 | 收了钱、对外承诺过 |
| Q4 | 有没有别人一眼能认出的品牌资产要切割？ | 不需要 | 建议切 | 必须切干净 |

**判定规则**：任意一题给出「B 或 C 的答案」，档位取最高那一档。**只能上调，不能下调**；确需下调必须写一行 `D-` 决策，写明「下调理由 + 谁接受这个风险」。

档位要落两处且必须一致：`PROJECT.md` 勾选段、`.replica/gate.manifest.yml` 的 `tier:`。两处不一致是 G0 机器判定项，直接 FAIL——档位写歪，S11 会做错一半的事。

### 3 · 写一句话定位（10 分钟）

句式固定，逐空填，不许改句式：

```
为 <谁>，解决 <什么场景下的什么问题>，方式是 <形态>。
```

合格判据三条：① 主语是**人**，不是「用户」「大家」；② 「问题」带**场景和频次**；③ 「形态」说清平台与交付方式。

| 反例 | 为什么不合格 | 改法 |
|---|---|---|
| 做一个更好的目标应用 | 没有「谁」没有「场景」，无法判定范围 | 为我，解决「下班前把今天没做完的任务挪到明天、原版要点 6 次且日期常改错」的问题，方式是 macOS 本地桌面应用 |
| 为职场人提供高效任务管理 | 主语是群体标签，场景缺失 | 为我（单人），解决「早上 5 分钟排好当天 20 条任务」的问题，方式是本地桌面应用 |

### 4 · 写不做清单 ≥5 条（20 分钟，本文件最重要的部分）

每条四段式，缺一段不算条目：

```
不做 <能力> ；因为 <具体理由> ；替代做法是 <用户实际怎么完成> ；重议条件 <什么情况下才允许重议>。
```

合格示例：

| # | 不做 | 因为 | 替代做法 | 重议条件 |
|---|---|---|---|---|
| 1 | 多设备云同步 | 本地自用；同步要引入账号、冲突合并、服务器三份成本 | 导出/导入 + 手动备份目录 | 真正出现第二台常用设备时 |
| 2 | 会员/配额/解锁 | 本版全解锁；适配会员会污染 4 张表的字段语义 | 无（全部解锁） | 永不（范围外） |
| 3 | 系统级通知推送 | 需签名与系统权限，A 档 ad-hoc 签名下不可靠 | 应用内提醒窗口 + 常驻定时器，界面明写限制 | 升到 B 档且做签名 |
| 4 | 原版 AI 功能 | 原版 AI 主逻辑在远端 WebView，客户端不可见 | 不做任何 AI 入口 | 有独立可验证方案时 |
| 5 | 主题/深色模式 | 15 套主题会把设计令牌翻 15 倍 | 只做浅色，令牌集中以便未来换肤 | 令牌体系稳定之后 |
| 6 | 农历/节气数据维护 | 原版 145 条节日数据有年份边界 | 内置已覆盖年份 JSON，未覆盖年份不显示 | 跨年后 |

**不合格写法（出现即打回）**：「不做同步」（无理由无替代无重议）；「暂时不做，以后再说」（不可判定）；「按原版为准」（用不确定的东西定义范围）；「不做性能优化」（性能属 R12 红线，不是功能项）；5 条全同类（凑数——必须覆盖数据/平台能力、商业能力、原版独有资产、交互形态四类）。

### 5 · 取制品身份（名称 + 版本 + SHA-256）（15 分钟）

不许写「最新版」。按平台取值：

```bash
# macOS：版本从 Info.plist 读，不从文件名猜
plutil -extract CFBundleShortVersionString raw "/Applications/目标应用.app/Contents/Info.plist"
# 对安装包本体算哈希，不对目录算
shasum -a 256 "/path/to/installer.dmg"
file "<installer>"
lipo -archs "<app>/Contents/MacOS/目标应用"
codesign -dv --verbose=4 "<app>" 2>&1 | head -5
```

Web/DMG 不可固定时，用「URL + 采集时间 + 页面快照 SHA-256」三件替代。

完整身份证写进 `PROJECT.md` 与 `evidence/artifact-identity.txt`：名称与版本、安装包 SHA-256、平台与形态（原生 Mach-O / .NET 托管 / Electron-Web）、架构、签名状态、取证日期（ISO 8601 带时区）。

**形态判定先证伪再下结论**：存在 `app.asar`/`.mjs` → Electron；存在 CLR 头/`#Strings` 堆 → .NET 托管；存在 Mach-O + `__objc_classlist` → 原生。只写「看起来是原生」不算结论，必须附命令与输出片段。

### 6 · 写 DECISIONS.md 前 3 条（10 分钟）

| 序 | 决策对象 | 典型内容 |
|---|---|---|
| `D-001` | 档位 | 「本项目定 A 档」+ 四题答案 + 为什么不往上升 |
| `D-002` | 制品 | 「复刻对象锁定为 <名称> <版本>，SHA-256 <值>」+ 为什么不用另一份 |
| `D-003` | 数据所有权 | 「数据只在本地 SQLite，路径 <路径>」或「数据在云端，风险是 <风险>」 |

格式 `| ID | 日期 | 决策 | 理由 | 影响范围 | 状态 |`。**只追加不改行**；推翻时新增一行写「推翻 D-00x，原因」。

### 7 · 确认 REDLINES.md 与 AGENTS.md（10 分钟）

- `REDLINES.md`：**R1–R20 一条都不许删**。A 档可把某条标「本版不触发」并写理由（如 R9 只在有反编译资产时触发），删除即违规。
- `AGENTS.md`：目录约定、写作用域规则、汇报格式（00 §7.3 六段）。
- 两份都要有一行「本版裁剪说明」。

### 8 · 跑 G0（5 分钟）

```bash
python3 gates/run.py --stage G0 --project ../rebuild
```

退出码 `0` 才算 S0 结束；`1` 按修复指引改；`2` 是环境问题，不是通过。

## 细节级产出

| 文件 | 最小内容 | 判定它「够细」的标准 |
|---|---|---|
| `PROJECT.md` | 一句话定位、档位（含四题答案）、为什么不用现成的（≥2 行）、目标制品身份、不做清单 ≥5 条四段式、验收人、完成定义 | 逐条读「不做清单」，每条都能回答「不做什么/为什么/替代/何时重议」四问；「目标制品」段的 SHA-256 复制出来重跑一次 `shasum -a 256`，值必须相同 |
| `DECISIONS.md` | `D-001` 档位、`D-002` 制品、`D-003` 数据所有权，带日期与理由 | 三条 ID 连续、日期 ISO 8601 带时区、每条「理由」非空且不是「因为这样比较好」 |
| `REDLINES.md` | R1–R20 全文 + 本版裁剪说明 | `grep -c '^| R[0-9]' REDLINES.md` ≥ 20；无一条被删；不适用条目有「本版不触发 + 理由」 |
| `AGENTS.md` | 一句话、目录约定、写作用域、汇报格式六段、红线索引 | 不含「视情况」「酌情」；汇报格式段能逐字抄进任务卡 |
| `.replica/gate.manifest.yml` | `project`/`tier`/`target`/`baseline_commit`/`thresholds`/`required`/`na_approved` | `tier` 与 PROJECT 一致；`target` 含版本号；`na_approved` 为空时写 `[]` |
| `evidence/artifact-identity.txt` | 六条命令原文 + 输出 + 取证时间 | 任何人拿这份文件重跑能得相同 SHA-256 |

## 执行入口

```bash
./scripts/new-project.sh <目标目录> --target "<应用名> <版本>" --tier <A|B|C>
shasum -a 256 "<installer>" && file "<installer>"
python3 <体系根>/gates/run.py --stage G0 --project .
python3 <体系根>/gates/run.py --stage G0 --project . --json   # 机读，便于贴进汇报
<体系根>/scripts/run-gates.sh G0                              # 自动定位项目根的包装
```

技能入口：`/replica-os`（主编排）、`/replica-recon` 的制品身份前置步骤（只做身份，不展开取证）。

## 门禁 G0

### 机器判定（`gates/rules/g0.py`，逐条独立报 PASS/FAIL/BLOCKED/NA）

| # | 检查项 | 期望 | 不通过的修复动作 |
|---|---|---|---|
| 1 | 必需文件存在 | `PROJECT.md`/`DECISIONS.md`/`REDLINES.md`/`AGENTS.md`/`.replica/gate.manifest.yml` 五个都在 | 重跑 `new-project.sh` 或按缺失清单补齐 |
| 2 | 无模板占位残留 | 五份文件里 `___`/`<目标路径>`/`TODO`/`待定`/`TBD` 命中数为 0 | 逐处替换为真实内容 |
| 3 | 一句话定位成立 | 命中 `为.*，解决.*，方式是.*` 且三段非空非占位 | 按步骤 3 句式重写 |
| 4 | 不做清单 ≥5 条 | 表格数据行 ≥5，每行四列非空 | 补到 5 条以上并补齐四段 |
| 5 | 档位明确且两处一致 | `tier` ∈ {A,B,C} 且与 `PROJECT.md` 勾选一致 | 改到一致；改档位要写 `D-` 决策 |
| 6 | 制品身份完整 | 名称、版本、SHA-256（64 位十六进制）三件齐；Web 目标允许 URL + 采集时间 + 快照哈希 | 按步骤 5 补齐；哈希位数不对视为缺失 |

### 人工判定（产品官，Agent 不得自批）

| # | 判什么 | 判定问句 | 通过标准 |
|---|---|---|---|
| 1 | 定位是否真是你的痛点 | 「这句话描述的场景，你上周实际发生过几次？」 | 说得出次数与具体场景 |
| 2 | 不做清单是否真敢不做 | 「删掉那条能力，你明天会不会立刻需要？」 | 每条都能接受「这一版就是没有」 |
| 3 | 档位是否选低了 | 「这东西你会发给别人吗？会收钱吗？」 | 与 Q1–Q3 答案自洽 |
| 4 | 有没有替 AI 编结论 | 「这条是你确认的，还是 AI 猜的？」 | 逐条能指到口述或命令输出 |

人工判定不通过 = 打回 S0，**不是**「先往下做，回来再补」。G0 之后所有阶段的裁剪都依赖档位与不做清单。

## 常见翻车点

| # | 症状 | 真因 | 对策 |
|---|---|---|---|
| 1 | 采证采到一半范围失控，收不了尾（失效模式 20） | 一开始没划「这一版做什么」，S1 见到什么记什么 | 不做清单 ≥5 条四段式；S1 每采一项先问「在不做清单里吗」；S1 收尾列出 skip 项及理由 |
| 2 | 门禁脚本写死某个项目的路径和数字（失效模式 16） | 阈值与方法散落在脚本里 | 阈值只写 `.replica/gate.manifest.yml`；`gates/run.py` 不出现任何项目名 |
| 3 | 三份模板三套编号，AI 各说各话（失效模式 14） | 没有单一事实来源 | 项目级只用 00 §4 的 ID 前缀与 00 §9 的 R 编号 |
| 4 | 分析数据库把真实数据搞坏（失效模式 07） | 直接对真实库操作 | AGENTS.md 第一条：数据库操作默认 `cp <真实库> /tmp/work.db`，真实库只读 |
| 5 | 上游英文技能规则与本档冲突（失效模式 13） | 上游禁止看源码，A 档允许本地自用分析 | AGENTS.md 写明「`skills/replica-local-source` 覆盖该条，其余照用」，冲突逐条列出 |
| 6 | 档位写 A、行为做 C（开始查商标、写商店文案） | 档位只写了一次，没进 manifest | 档位两处一致纳入 G0 机器判定；S11 按 `tier` 分流不按记忆分流 |
| 7 | 制品写成「最新版」，两周后复现不出来 | 应用自动更新或换了渠道 | SHA-256 + 取证日期 + 安装包留档；版本从 `Info.plist` 读，不从文件名猜 |
| 8 | 定位写完，S2 写契约时才发现「给谁用」不对 | 定位是抽象口号，没有场景与频次 | 定位必须带场景与频次；S3 审查会用「上周发生几次」复核 |

## 退出与交接

| 交接物 | 门槛 | 下一阶段（S1）怎么用 |
|---|---|---|
| `PROJECT.md` | G0 机器 6 项 + 人工 4 项全过 | 定位决定取证深度；不做清单决定 S1 哪些模块只记 `skip`；制品身份决定取证对象 |
| `.replica/gate.manifest.yml` | `tier` 与 PROJECT 一致 | S1 起每道门都读它取阈值，S11 按 `tier` 分流 |
| `evidence/artifact-identity.txt` | 六条命令 + 输出 + 时间 | S1 第一件事复算哈希，对不上立即停 |
| `DECISIONS.md` 前 3 条 | ID 连续、有理由 | S1 若观察到与 `D-003` 冲突（如数据其实在云端）→ 停，回产品官 |
| `REDLINES.md` / `AGENTS.md` | R1–R20 完整 + 裁剪说明 | 每个 Agent 开工前读 AGENTS.md；汇报格式照它执行 |

**交接状态要求**：G0 退出码必须为 `0`。G0 未过时 S1 一律不许开工——包括「先拍几张截图看看」也不行，因为取证结论会直接污染 S2 契约，返工成本是全项目最贵的一段。

**下一个接手的人需要知道的唯一一句话**：这一版只做 `PROJECT.md` 里那 5 条以外的东西，其余一律不做。
