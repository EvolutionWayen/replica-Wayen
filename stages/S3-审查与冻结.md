# S3 · 产品官审查与冻结

> 上游：S2 全部产物 · 下游：S4 架构 · 门禁：G3（全流程最硬的人工门槛）

## 一句话

产品官一屏一屏地过，把「AI 拆出来的行为」逐条判成**确认 / 改 / 不做**，判词当场写进 `DECISIONS.md`，再给整份蓝图算哈希锁起来；此后改一个字都要走变更单。

## 输入

| 从 S2 拿什么 | 文件 | 缺了就不许开会 |
|---|---|---|
| 契约全集 | `BLUEPRINT/contracts/*.md`（must 每功能一份，16 节齐） | 任一份缺节或含「待填」→ 停，会上变成「一起猜」 |
| 菜单树 | `BLUEPRINT/menus.csv`（三条件齐） | `menu_walk.py --check` 有问题 → 无法判「该灰的灰了没」 |
| 联动矩阵 | `BLUEPRINT/linkage.csv`（六面无空格） | 有空格 → 无法回答「这个联动要不要做」 |
| 流程与点击数 | `BLUEPRINT/flows.md` | 无点击数 → 无法判「这个操作值不值得优化」 |
| 未知/现状/决策 | `unknowns.csv`/`STATE.md`/`DECISIONS.md` | 缺任一 → 待决清单少一半，新决策无法续号 |

**开会前置检查（AI 做，产品官不看过程）**：`blueprint_lint.py` 0 问题 + `gates/run.py --stage G2` PASS + 联动矩阵渲染备好。

## 动作序列

### 1 · AI 生成待决清单（开会前 1 小时）

待决清单**不是把蓝图再抄一遍**，只收三类必须由人拍板的项：

| 类型 | 从哪来 | 为什么必须人判 |
|---|---|---|
| A 阻断未知 | `unknowns.csv` 中 `blocking=yes & status=open` | 不拍板 S4 无从下手 |
| B 取舍冲突 | 同一件事有两种合理解释（原版行为 vs 你的习惯） | AI 不知道你要哪一种 |
| C 范围裁剪 | `linkage.csv` 里「贵但不影响主流程」的联动 | 只有你能判断值不值 |

**按影响面排序**（核心步骤，不许按文件顺序排）。影响面 = 受影响功能数 × 3 + 受影响联动数：

```bash
python3 - <<'PY'
import csv
rows=list(csv.DictReader(open('BLUEPRINT/unknowns.csv',encoding='utf-8')))
for r in rows:
    if r['blocking']=='yes' and r['status']=='open':
        fs=r['impact'].count('F-'); ls=r['impact'].count('LK-')
        print(f"{r['unknown_id']}\t功能={fs}\t联动={ls}\t影响面={fs*3+ls}\t{r['description'][:40]}")
PY
```

清单固定格式：

| 序 | ID | 一句话问题 | 候选项（≤3） | AI 倾向 + 理由 | 影响面 | 影响谁 |
|---|---|---|---|---|---|---|
| 1 | `U-007` | 「清除日期」是否同时清提醒与重复？ | ①全清 ②只清日期 | 倾向①：「没日期就没提醒」更符合直觉，但无直接证据 | 高（3 功能/6 联动） | `C-F-DATE-EDIT` §11、`C-F-REPEAT` §9、`LK-001..006` |

排序后**砍掉末尾**：影响面低且 AI 有把握的项不进会，会上一次性批量确认（「下面 12 条低影响项，你扫一眼有异议就说」）。

### 2 · 会前把材料摆成一屏一屏（30 分钟）

产品官不应该在会上翻文件。材料预先组织成屏：

`第 0 屏` 这次确认什么、总条数、预计时长、哪些已由 AI 自行决定 → `第 1 屏起` 每个 must 功能一张卡，按影响面从大到小排（不按 ID） → `倒数第 2 屏` 联动矩阵全图，一眼看六面哪格空着 → `末屏` 不做清单复核 + 冻结哈希预览。

一功能一卡的标准格式（必须一屏内看完，超了就是没整理好）：

```markdown
### F-DATE-EDIT · 修改任务日期与时间          [must] 影响面 高
**入口（3 个）**：①点详情日期块 ②日历拖拽 ③快捷键 ⌘D
**核心行为**：点选项立即落库（无确认按钮）；仅改 dueDate，保留时分；Esc 取消不落库
**三条件**：显示=任务未删除 / 可用=有有效任务且未在冲刷 / 选中=按草稿值高亮
**联动（6 面）**：列表(改该行) 角标(重算3个) 详情(改) 日历(重排2格) 搜索(失效缓存) 提醒(重算)
**需要你拍板（1 条）**：清除日期时提醒一起清吗？ → U-007
**AI 已有证据**：evidence/shots/S02-date-menu-01..06.png
```

### 3 · 逐条确认（会议主体，60–120 分钟）

逐条确认不是逐条念文件，是让产品官在三判词里选一个。三判词有严格定义：

| 判词 | 含义 | 落到哪 | 后续 |
|---|---|---|---|
| **确认** | 接受 AI 的理解 | `STATE.md` 该契约 → `APPROVED`；该 `U-` → `resolved` | 无 |
| **改** | 理解不对，按我说的改 | `DECISIONS.md` 加 `D-`（改什么+为什么） | **立即改契约**，改完当场复核 |
| **不做** | 本版不做 | `DECISIONS.md` 加 `D-` + `features.csv` 该行 `scope=out` + `PROJECT.md` 不做清单加一行 | 联动标 `skip`，测试号作废 |

机械化要求（防「他说确认了」变口头承诺）：

- 每条确认落一行到确认记录表（ID / 判词 / 时间 / 原话摘要）。
- 「改」的条目**当场改完看一眼**，不许会后异步改（会后改＝没确认）。
- 「这个先这样吧」「大概可以」→ **不算确认**，必须追成三者之一。体系里没有「大概通过」这个状态。

确认记录表（会上实时填，列固定为 `# | 对象 ID | 类型 | 判词 | 产品官原话摘要 | 时间 | 后续`）。三条真实样子：

| # | 对象 ID | 类型 | 判词 | 原话摘要 | 后续 |
|---|---|---|---|---|---|
| 1 | `U-007` | A 阻断未知 | 改 | 「清除日期就只清日期，提醒留着，我可能只是想过期」→②只清日期 | 改 `C-F-DATE-EDIT` §11 |
| 2 | `F-TASK-COMPLETE` | 契约 | 确认 | 「就这样」 | 无 |
| 3 | `LK-006` | C 范围裁剪 | 不做 | 「提醒这一版不做重算，先手动」 | `DECISIONS` 加行 + `linkage` 标 skip |

### 4 · 写进 DECISIONS.md（会议结束前 15 分钟，当场做）

每条「改」与「不做」必须当场变成一行：

```
| D-007 | 2026-10-23 | 清除日期只清 dueDate，不清 remindTime 与 repeat | 产品官判定：用户可能只是想把任务标为过期但保留提醒 | C-F-DATE-EDIT §11、U-007 | 已定 |
```

规则：**只追加不改行**（推翻时新增一行写「推翻 D-00x，原因」）；「影响范围」列必须是具体 ID；`U-` 关闭时在 `unknowns.csv` 的 `notes` 写 `D-0xx`。

### 5 · 阻断级未知清零（冻结前最后一关）

```bash
python3 - <<'PY'
import csv
rows=list(csv.DictReader(open('BLUEPRINT/unknowns.csv',encoding='utf-8')))
bad=[r for r in rows if r['blocking']=='yes' and r['status']=='open']
print(f"阻断级未清：{len(bad)}")
for r in bad: print(' ', r['unknown_id'], r['description'][:50])
PY
```

必须输出 `阻断级未清：0`。三条合法路径：会上补验了（`resolved` + 补契约）／会上拍板了（`resolved` + 有 `D-`）／判本版不做（`out-of-scope`，必须有 `D-` 批准记录）。`accepted-risk` 只给 `blocking=no` 的项。

### 6 · 冻结：算哈希、写 BLUEPRINT-LOCK（20 分钟）

```bash
for f in recon.md features.csv screens.csv menus.csv flows.md linkage.csv \
         state-machines.md data-dictionary.md unknowns.csv; do
  printf '| BLUEPRINT/%s | %s |\n' "$f" "$(shasum -a 256 "BLUEPRINT/$f" | cut -d' ' -f1)"
done
for f in BLUEPRINT/contracts/*.md; do
  printf '| %s | %s |\n' "$f" "$(shasum -a 256 "$f" | cut -d' ' -f1)"
done
```

输出贴进 `BLUEPRINT/BLUEPRINT-LOCK.md` 哈希表（结构见 SCHEMAS §11），同时填五项：蓝图版本 `v1.0`／冻结时间（ISO 8601 带时区）／确认人（Wayen）／**确认方式（写清到底审了什么**：逐条审阅 `features.csv` must 行 + `contracts` 16 节 + `menus` 三条件，不许写「已审阅」）／门禁结果 `G1 PASS / G2 PASS`。

`STATE.md` 里把对应条目从 `DRAFT` 改成 `APPROVED`——**这是 `APPROVED` 唯一合法来源**，Agent 不得自置。

### 7 · 冻结后怎么走变更单（永久规则）

```
发现新细节 / 产品官指出误解
  → 写变更单 BLUEPRINT/CHANGES/C-001.md（改什么、为什么、证据）
  → 定位影响面：关联 F- / M- / SM- / DATA- / LK- / T-
  → 产品官确认取舍（DECISIONS.md 加一行）
  → 蓝图版本 +1（v1.0→v1.1），重算全文件哈希，更新 BLUEPRINT-LOCK
  → 才允许改实现
  → 受影响的 T-xxx 全部重跑
```

变更单必备三段：**改什么**（一句断言「把 A 改成 B」，不许用「优化/调整」）／**影响面**（逐项列契约、菜单、联动、测试的 ID，无「相关模块」）／**复验要求**（受影响的 `T-` 全列出，S8 照此重跑）。三类禁止动作（00 §8）：改代码顺手改契约让门变绿；改测试断言让它通过；跳过受影响的联动测试。

## 细节级产出

| 文件 | 最小内容 | 判定它「够细」的标准 |
|---|---|---|
| `BLUEPRINT/BLUEPRINT-LOCK.md` | 版本号、冻结时间、确认人、确认方式、门禁结果、逐文件 SHA-256 表、确认要点勾选 | 哈希覆盖 SCHEMAS §11 的 9 个文件 + 全部 `contracts/*`；重跑 `shasum` 逐个**完全一致**；「确认方式」写的是具体审了哪些项 |
| `DECISIONS.md` | 每条「改/不做」都有对应 `D-` | 确认记录里判词为「改」或「不做」的条数 = 新增 `D-` 行数，可脚本核 |
| `BLUEPRINT/unknowns.csv` | `blocking=yes & open` 条数 = 0 | 脚本验 0；每条 `out-of-scope` 在 `DECISIONS.md` 有批准行 |
| `STATE.md` | 被确认契约 `DRAFT` → `APPROVED`，附证据路径与时间 | 每条 `APPROVED` 的「证据路径」指向 `BLUEPRINT-LOCK.md`；无跳态 |
| `BLUEPRINT/CHANGES/` | 冻结后每次变更一个 `C-xxx.md` | 每单的影响面全是具体 ID；有产品官确认行与时间 |

## 门禁 G3

### 机器判定（`gates/rules/g3.py`）

| # | 检查项 | 期望 | 不通过怎么修 |
|---|---|---|---|
| 1 | `BLUEPRINT-LOCK.md` 结构完整 | 版本号/冻结时间/确认人/确认方式/门禁结果五项齐且非占位 | 按 SCHEMAS §11 补齐 |
| 2 | 哈希覆盖完整 | 覆盖 9 个蓝图文件 + 全部 `contracts/*.md` | 补算缺失文件 |
| 3 | 哈希实算一致 | 逐文件重算与记录值完全相同 | 文件被改过 → 回退，或走变更单后重算**全部**哈希 |
| 4 | 阻断级未知归零 | `blocking=yes & open` = 0 | 会上补验/拍板，或降级并写 `D-` |
| 5 | `out-of-scope` 有批准 | 每条在 `DECISIONS.md` 能找到对应 `D-` | 补 `D-` 行或改状态 |
| 6 | `STATE.md` 态合法 | 只有七态枚举；`APPROVED` 行有证据路径 | 改非法态；补路径 |
| 7 | 冻结后无未登记改动 | 哈希不符则必须在 `CHANGES/` 有变更单且 LOCK 版本号已 +1 | 走变更单，重算哈希 |
| 8 | 确认记录非空 | `DECISIONS.md` 中引用 `U-`/`C-F-`/`LK-`/`F-` 的 `D-` 行数 ≥1 | 会上没记就补记，按真实时间，不许编 |

### 人工判定（产品官本人，全流程唯一不能委托的门）

| # | 判什么 | 判定问句 | 不合格的样子 |
|---|---|---|---|
| 1 | 核心行为理解是否正确 | 「这张卡描述的行为，和你用的时候一样吗？」 | 「差不多吧」→ 必须追成「一样」或指出哪不一样 |
| 2 | 三条件是否可信 | 「这个菜单项什么时候是灰的？你同意 AI 的判断吗？」 | 产品官自己说不出 → AI 也没拆清 |
| 3 | 取舍是否真是你的取舍 | 「AI 倾向 A，你也可以选 B，你选哪个？」 | 「你定就行」→ 不算确认，必须给两个具体后果 |
| 4 | 不做清单是否要更新 | 「会上砍掉的这几条，要不要写进 PROJECT.md？」 | 砍了没进不做清单 → S6 会被重新提出来 |
| 5 | 是否有人在替你签字 | 「这些确认记录是你说的原话吗？」 | 出现 AI 编的「原话」= R20 的变体违规 |

> **G3 的本质**：不是检查文档，是检查「人是否真的看过了」。所以它无法自动化，也不允许被自动化。

## 常见翻车点

| # | 症状 | 真因 | 对策 |
|---|---|---|---|
| 1 | 蓝图冻结了还在改（失效模式 18） | 没有冻结记录与哈希 | `BLUEPRINT-LOCK.md` + G3 实算比对；改必走 `CHANGES/` |
| 2 | 文档说「已确认」，实际没人确认（失效模式 17/15） | 确认只有口头没落记录 | 确认记录表 + `D-` 一一对应（G3 机器判定 8）；AI 不许代写原话 |
| 3 | 会前 40 分钟都在讨论小事 | 待决清单按文件顺序排 | 按影响面排序，低影响项批量确认 |
| 4 | 会开完 `blocking=yes` 还剩一堆 | 开会没聚焦阻断项 | 待决清单只收 A/B/C 三类；第一屏就报阻断项条数 |
| 5 | 「改」的条目会后异步改，改错了没人发现 | 没当场复核 | 改完当场看一眼，确认表标「已复核」 |
| 6 | 产品官说「大概可以」，AI 记成「确认通过」 | 三判词没强制收敛 | 三判词之外无第四种；含糊必须追问到具体 |
| 7 | 冻结后改一个文件，忘了重算全部哈希 | 只更新了改动那一行 | G3 查覆盖完整性 + 逐文件比对；改一个也要整表重算 |
| 8 | `out-of-scope` 无批准记录，S4 又翻出来 | 没写 `D-` | G3 机器判定 5 强制要求 |
| 9 | 审查会开成「AI 汇报会」，产品官全程在听 | 材料没组织成一屏一屏 | 每屏一张卡，卡上必须有「需要你拍板」栏，没有则跳过 |
