# S6 · 逐屏重建

> 上游：冻结蓝图 + 设计系统 + 架构 · 下游：S7 后端 / S8 测试 · 门禁：G6（联动门，最严）

## 一句话

按 `WP-` 工作包一屏一屏地建，但**每建完一个功能就立刻过联动门**：六个面逐面点一遍、断言一遍、留下证据；页面做出来不算做完，六面都跟着变才算做完。

## 输入

| 从哪来 | 文件 | 缺了就不许开工 |
|---|---|---|
| 冻结蓝图 | `BLUEPRINT-LOCK.md`（v1.0）+ `contracts/*.md` | 契约不是 `APPROVED` → 停。你在按未批准的行为写代码 |
| 联动清单 | `BLUEPRINT/linkage.csv`（每行有 `test_ref`） | 缺 → 建完无法自检联动，G6 必然失败 |
| 设计系统 | `SPEC/DESIGN/tokens.json` + `components.md` | 缺 → 会硬编码色值，S9 界面分必然掉 |
| 架构 | `SPEC/ARCHITECTURE.md` 构建顺序（`WP-`）、`TRACEABILITY.csv` | 缺 → 不知道先建哪个，也不知道每屏落在哪个命令 |
| 数据接口 | S4 命令清单的稳定签名 | 缺 → 界面会直接连数据库，S7 换真实现时要改界面（禁止） |
| 执行约束 | `AGENTS.md`、`REDLINES.md` | 缺 → R18 无人守 |

## 动作序列

### 1 · 建工作包（每屏/每功能一个，15 分钟）

按 `ARCHITECTURE.md` 的 `WP-` 顺序，逐个写 `BUILD/WORK-PACKAGES/WP-00x.md`（模板见 `templates/engineering/WORK-PACKAGE.template.md`）。每包含七项，缺一不许开工：

| 项 | 内容 | 判定 |
|---|---|---|
| 目标 | 一句话可判定 | 不含「完善」「优化」 |
| 允许改的路径 | 具体到目录/文件 | 与其他 WP 的路径不重叠（写作用域隔离） |
| 依赖 | `WP-` / 数据接口签名 | 依赖未完成不许开工 |
| 验收标准 | 含量化指标 | 每条能被脚本或人一眼判定 |
| 测试 | `T-` 号清单 | 与 `linkage.test_ref` 一致 |
| 交付证据 | 截图/测试输出/落库查询 | 路径写死 |
| 禁止项 | 不许碰的文件、不许做的优化 | 明确到文件名 |

### 2 · 先落数据接口的「假实现」（30 分钟，本阶段第一个动作）

**在建任何界面前**，把 S4 命令清单里的签名先以假实现落地：

```
DetailViewModel.SetDueDateAsync(taskId, date, keepTime) -> Task<WriteResult>
  假实现：写入一个内存 Map，返回 WriteResult.Ok
  真实现（S7）：写入 SQLite，返回 WriteResult.Ok / Retryable / Conflict / DiskError
```

判据：换真实现时**不改界面代码一行**（00 §2.1）。这是 S6 与 S7 能交错的前提。

### 3 · 逐屏建：每屏的固定动作序列（每屏 2–4 小时）

对每一屏，严格按此顺序：

1. **对组件**：把设计稿里的控件逐个映射到 `components.md` 的组件。映射不到的 → 回去加组件规格（不许临时手搓样式）。
2. **铺三态**：有数据 / 空 / 加载 / 错误四态必须都实现（S1 的 `screens.csv` 有列）。
3. **接命令**：控件的每个动作都调 S4 的命令（假实现阶段）。**不许直接读写数据库。**
4. **过联动门**（下一步，每功能做一次，不是每屏做一次）。
5. **记 `build-log.md`**：状态齐否 / 联动接没有 / 欠什么。

### 4 · 联动门自检清单（本阶段的核心，每功能必跑）

对每个功能，把 `linkage.csv` 里 `source_id` 等于它的行全取出来，**逐行按下表动作验收**。每个面都要「点哪里、看什么、断言什么」：

| 面 | 点哪里 | 看什么 | 断言什么 |
|---|---|---|---|
| **主列表** | 在详情面板改一个字段（如把日期从 10/23 改成 10/24） | 主列表该行的日期徽标文字 | ① 该行文字变成「10/24」或「明天」；② **其他行一个字都没变**；③ 若当前视图是「今天」，该行消失且焦点落到下一行 |
| **侧栏/标签角标** | 同上，改完立刻看左侧「今天」「明天」「最近7天」 | 三个角标数字 | ① 今天 -1、明天 +1（数值断言，不是「变了」）；② 角标总数与列表实际行数一致（不许硬截断）；③ 切换视图后再看一遍，数字不回跳 |
| **详情面板** | 改完日期后看详情面板本身 | 日期块文本 + 标题框 + 滚动位置 | ① 日期块同步更新；② 标题草稿**没被覆盖**；③ 面板滚动位置未跳动 |
| **日历/时间视图** | 切到日历视图，看原日期格与新日期格 | 两个格子的任务条目 | ① 任务从 10/23 格消失、出现在 10/24 格；② 视图**没有自动跳月**（除非契约规定要跳）；③ 跨月改日期时两格都在正确的月份 |
| **搜索结果** | 在搜索框输入该任务标题 → 改日期 → 再看搜索结果 | 结果行的日期徽标 + 命中集合 | ① 结果行日期同步更新；② 按旧日期作为关键词再搜，结果集已变；③ 搜索词与滚动位置保留 |
| **提醒调度** | 给任务设 1 分钟后提醒 → 改日期到明天 → 等 1 分钟 | 是否弹出提醒 | ① 原提醒**不再弹**（这是最常漏的一条）；② 新提醒已按新日期注册（查调度表或日志）；③ 删除任务后不再弹（孤儿提醒检查） |

**每跑完一面，立刻做两件事**：把 `linkage.csv` 该行 `status` 从 `pending` 改 `wired`；跑对应 `T-` 并落测试结果文件。六面全 `wired` 且 `T-` PASS 之后，该功能才能标 `done`。

**用键盘替代鼠标的等价动作**也要跑一遍（Tab 到控件、Enter 触发、Esc 取消），因为键盘路径经常绕过某层刷新。

### 5 · 识别并消灭「假联动」（5 种典型表现）

「假联动」指：看起来联动了，实际没有真正传导到数据层或其他面。五种形态，逐条对照排查：

| # | 假联动的样子 | 怎么识破（具体动作） | 真因 | 修法 |
|---|---|---|---|---|
| 1 | **只改了内存没落库**：列表上日期变了，重启后变回原值 | 改完立刻 Cmd+Q → 重开 → 查该行日期 | 写操作是 fire-and-forget，或只更新了 ViewModel 的内存属性（失效模式 03） | 写进串行链 + 暴露可 await 完成信号（R2）；测试断言「关连接重开读到新值」（R4） |
| 2 | **只刷新当前页**：主列表变了，切到日历视图发现还是旧位置 | 改完立刻切到日历视图（不重启、不刷新） | 刷新只作用于当前视图，没有事件广播或缓存失效 | `refresh_timing` 写清时点；用事件/失效通知而非「刷新当前视图」 |
| 3 | **角标硬算**：角标数字 ≠ 列表实际行数 | 同一屏里数角标与列表行数，两者比对 | 角标用「已加载页数」或 `Take(N)` 硬截断，与列表查询口径不同（失效模式 01/19） | 角标走全量 `COUNT`；加断言「分页累计 == COUNT 总数」 |
| 4 | **日历不重排**：任务日期改了，日历格子没动 | 改日期后不切走视图，直接看日历区域 | 日历读的是自己的缓存快照，没订阅日期变更 | 日历订阅同一事件；改完即重排两个格子；断言两格的条目集合 |
| 5 | **搜索索引未更新**：改了标题/日期，搜索还按旧值命中 | 改完立刻搜旧值（应搜不到）+ 搜新值（应搜到） | 索引是启动时建的一次性快照，写入后没失效 | 写入后失效缓存；下次查询重算；断言「旧值 0 结果、新值 1 结果」 |

识别假联动的通用手法：**「不改窗口、不重启，就在同一会话里跨视图看」**。多数假联动只在「切走再切回」时才暴露——因为切视图会触发全量重载，掩盖了失效缺陷。

## 常见翻车点

| # | 症状 | 真因 | 对策 |
|---|---|---|---|
| 1 | 页面做出来了，内部不联动（失效模式 01 / R18） | 只按「屏幕」建，没按「功能 + 六面」验 | 每功能跑联动门自检清单；G6 机器判定 1 强制 `verified` |
| 2 | 只改了内存没落库，重启就变回去（失效模式 03） | fire-and-forget 写；界面直接改 ViewModel 属性 | 写进串行链 + 完成信号（R2）；测试断言「关连接重开读到新值」 |
| 3 | 测试全绿但用户一用就崩（失效模式 04） | 测试用 `sleep` 猜完成、用内存库测持久化 | R1/R4/R5；真文件 + 完成信号 + 故障注入（S8 落实） |
| 4 | 改 A 结果 B 被改（失效模式 05） | 命令读「当前选中」而不是入队时捕获的 ID | 命令签名强约束（S4 已定）；S6 实现时不许改签名 |
| 5 | 界面建完才发现契约不可实现，回头改契约 | 建的时候图省事改了行为 | 发现契约问题 → 停 → 走 `CHANGES/` 变更单；不许边建边改行为 |
| 6 | 每屏都能跑，但换真数据层时界面要大改 | 界面直接连库，没走稳定签名 | 第一步先落假实现；换真实现不改界面代码 |
| 7 | 角标与列表数字对不上 | 角标硬算/硬截断 | 角标走全量 COUNT；断言「分页累计 == COUNT」 |
| 8 | 提醒永不触发（零调用点） | 定时器定义了但没接线；测试直接调 `TickAsync()` 绕过 | 接线契约测试：断言 `timer.IsEnabled == true`；只驱动真实控件事件 |

## 示例

### 示例 1 · 联动门自检的实跑记录（改日期这一个功能）

| 面 | 实际动作 | 观察结果 | 断言 | 结论 |
|---|---|---|---|---|
| 主列表 | S-02 详情里把日期 10/23 → 10/24 | 该行显示「明天」 | 其他 19 行文字未变 | PASS |
| 角标 | 同一时刻看侧栏 | 今天 917→916、明天 42→43 | 916+43 与视图切换后一致 | PASS |
| 详情 | 看日期块 | 显示「10/24 · 明天」 | 标题草稿仍在输入框里 | PASS |
| 日历 | 切到月视图 | 10/23 格少一条、10/24 格多一条 | 未自动跳月 | PASS |
| 搜索 | 搜标题「给客户回电」 | 结果行显示 10/24 | 搜「10/23」0 结果、搜「10/24」1 结果 | PASS |

## 退出与交接

| 交接物 | 门槛 | S7 / S8 怎么用 |
|---|---|---|
| `src/` 界面层 | 每屏四态、六面接线（假实现） | S7 把假实现换成真持久化，**不改界面代码** |
| `linkage.csv` | 已建功能 `wired`/`verified` | S8 按 `test_ref` 补端到端用例 |
| `build-log.md` | 每屏一行、缺什么列收敛为「无」 | S8 从「难在哪」列找测试重点 |

| `clone-screens/` | 同尺寸截图 | S9 的 `imgdiff` 输入 |
| `TEST/results/*.json` | 联动用例运行结果 | G6/G8 读最新结果文件 |

**交接状态要求**：G6 退出码 `0`。勾选 `done` 的功能，六面全部 `verified` 且有测试证据；键盘可完成主流程；控制台 0 错误。

**下一个接手的人需要知道的唯一一句话**：凡是标了 `done` 的功能，六个面都点过、断言过、留了证据；没证据的都还在 `partial`。
