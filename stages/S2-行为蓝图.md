# S2 · 行为蓝图（核心）

> 上游：S1 全部产物 · 下游：S3 审查与冻结 · 门禁：G2 · 本阶段最耗时、最值钱

## 一句话

把「用户点一下会发生什么」拆到**一个不了解这个应用的人照着写代码也不会错**的程度：每个菜单叶子有显示/可用/选中三条件、每个功能有 16 节契约、每处改动有六面联动与刷新时点；拆不出来的进 `unknowns.csv`，**绝不用「按原版」糊过去**。

### 2 · 菜单穷举法（占总工时 30%，三步顺序不能换）

#### 2.1 截图法 —— 每层展开都截

硬规则：

1. **每展开一层截一张**。不许只截最底层——中间层的 hover 高亮、子菜单指示箭头、分隔符位置都只在中间层。
2. **同层截两张**（悬停某项 / 不悬停）：悬停态才能看出「哪些项有子菜单」。
3. 文件名带层级：`evidence/shots/M-DATE-SUB-03-weekly-01.png`；截图必须含周边上下文（窗口左右边界至少可见 1/3），否则无法判断菜单从哪个控件弹出。
4. **同一菜单在不同上下文各截一张**：任务详情里的日期菜单 ≠ 日历视图里的日期菜单。

实操序列（照做）：

```
1. 打开任务详情 → 点日期块 → 截图：一级日期菜单
2. 鼠标移到「重复」→ 等二级定格 → 截图：二级重复菜单
3. 鼠标移到「每周」→ 等三级定格 → 截图：三级星期选择
4. 移开再点一次 → 截图：重新打开时默认选中项在哪
5. 在「已完成」任务上重复 1 → 对比菜单条目少了什么（→ 显示条件）
6. 在「已删除」任务上重复 1 → 对比（→ 显示条件第二边界）
```

六张截图就能定出「重复」子菜单显示条件的大部分边界。

#### 2.2 逐层记录表 —— 边截图边写，不许事后回忆

每展开一层就往 `menus.csv` 写行，15 列按 SCHEMAS §4。现场记法与易错点：

| 列 | 现场怎么记 | 最容易记错 |
|---|---|---|
| `node_id` / `parent_id` | 按层级编 `M-DATE` → `M-DATE-SUB` → `M-DATE-SUB-03`，`-SUB` 专指有子层；顶层父节点填 `ROOT` | 用数字顺序当层级信息；漏填父节点 → 树断裂 |
| `path` / `order` | `›` 连接完整路径；同级可见顺序从 1 起，隐藏项也占位 | 用 `>`/`/` → 脚本解析失败；隐藏项不占位 → 重排后顺序全错 |
| `type` / `label` / `shortcut` | 六种类型之一；标签原文照抄；快捷键照抄符号（`⌘⇧W`），无则 `-` | radio 与 action 混 → 无法判断「点完关不关」；漏记快捷键 = §1 缺一条入口 |
| 三条件 | 见 2.3 | 见 2.3 禁止写法 |
| `command` / `contract_ref` | 能对应契约写法的动作 ID；`contracts/C-F-xxx.md` | 写「设置重复」（描述不是 ID）；只有 separator/label 允许 `-` |
| `screens` | `;` 分隔 | 漏记「同一菜单多处出现」→ 联动漏测头号原因 |
| `default_item` | 打开菜单时默认高亮哪一项（填 `M-xxx`），无则 `-` | 与 `checked_cond` 混为一谈——默认项是**首次打开的焦点落点**，选中条件是**当前值是否匹配**；两者可以完全不同 |

#### 2.3 条件反推法 —— 从「这个选项什么时候是灰的」反推 enabled_cond

**核心问句：制造边界，看它变不变。** 对每个非 `label`/`separator` 叶子跑五组探针，观察结果直接写进对应列：

| 探针 | 怎么造 | 观察到什么 → 写进哪列 |
|---|---|---|
| P1 上下文切换 | 在「正常任务」和「已删除任务」各开一次同一菜单 | 条目增减 → `visibility_cond`；条目在但变灰 → `enabled_cond` |
| P2 只读/冲刷态 | 触发 Cmd+Q 在冲刷过程中再点菜单 | 全菜单变灰 → `enabled_cond` 写「退出冲刷阶段整体禁用」 |
| P3 空数据 | 新建空清单、新建无日期任务，再开菜单 | 依赖数据的项变灰 → `enabled_cond` 写清前提 |
| P4 选中态对照 | 先设 A 值看选中项，再设 B 值看一次 | 选中标记位置 → `checked_cond` 写具体持久值/草稿值 |
| P5 快速移开 | 悬停展开二级后立刻移开 | 消失/保持与延迟 → §3「打开关闭行为」 |

**反推的正确姿势**：观察到「任务有日期时『重复』亮，无日期时灰」→ 反推 `enabled_cond: dueDate 非空` → **必须真做一步验证**（点「清除日期」后再开菜单），否则你只是把相关性当因果。

记录写法（三行互不重复）：`visibility_cond: deleted != 2` ／ `enabled_cond: dueDate 非空；退出冲刷阶段整体禁用` ／ `checked_cond: repeat.rule == 'WEEKLY' && byday 覆盖周一至周五`。

**禁止写法**（G2 逐条 FAIL）：`视情况`｜`按原版`｜`同前`｜`看是否有数据`｜`默认选中当前值`（循环定义）｜`一般都可点`。改成：具体字段 + 取值 + 真值表达式。

### 3 · 三条件分离（三个独立事实，不是一句话的三种写法）

| 条件 | 判定问句 | 问错了会怎样 |
|---|---|---|
| 显示 `visibility_cond` | 「它什么时候**存在**？不存在时空出的位置和焦点去哪？」 | 混进可用条件 → 该灰的项直接消失，用户找不到入口 |
| 可用 `enabled_cond` | 「它明明在，为什么**点不动**？禁用理由要显示给人看吗？」 | 混进显示条件 → 该点的点不了且无解释 |
| 选中 `checked_cond` | 「它现在是**哪一种**？状态存在哪个字段？改了没保存时显示哪个？」 | 混进可用条件 → 勾了没反应/勾了显示错项 |

**九个 真实场景（每类三个，判定问句决定记录要点）**

| 类 | # | 场景 | 判定问句 | 记录要点 |
|---|---|---|---|---|
| 显示 | D1 | 「重复」子菜单在「已删除」任务里整块消失 | 正常态/垃圾箱态各开一次，条目差几项？消失后有无补位，焦点跳到哪？ | 条目增减数 + 焦点落点 |
| 显示 | D2 | 「提醒」区只在有日期时出现 | 清空日期后消失还是变灰？消失后下方控件上移多少？ | 布局位移必记（进 §15 布局稳定） |
| 显示 | D3 | 日历视图右键菜单比列表视图多「新建任务到此日」 | 同一菜单在不同屏幕出现时条目集是否相同？ | `screens` 列必须写全 |
| 可用 | E1 | 无日期任务上「重复」是灰的且悬停无提示 | 为什么点不动？界面有任何解释吗？没有解释算不算缺陷？ | 有提示照抄原文，无提示记「无提示」并进 `U-` |
| 可用 | E2 | 退出冲刷阶段所有菜单变灰 | 禁用态持续多久？期间点击是静默还是给提示？ | 冲刷窗口 + 点击反馈 |
| 可用 | E3 | 已完成重复任务实例上「编辑重复规则」禁用 | 同一规则对模板可编辑、对实例不可编辑，依据是哪个字段？ | 写清是 `isTemplate` 还是 `parentId` 非空 |
| 选中 | C1 | 「每周工作日」勾选由 `byday` 是否恰好覆盖周一至周五决定 | 手动加周六后这一项还亮吗？ | 必须写真值表达式 |
| 选中 | C2 | 优先级「高」由 `priority==5`，但「中」是 3 还是 0（默认映射） | 未设优先级的新任务，菜单里哪一项亮？ | 默认值映射是最高频错误来源，必须实测 |
| 选中 | C3 | 日期弹层里「今天」的选中态读**草稿值**而非持久值 | 改了没点确定按 Esc 取消——亮的还是原值吗？ | 记清读草稿还是持久值（进 §14） |

### 4 · 六面联动（每功能都过一遍，不适用也要写理由）

对每个面问三个问题，然后记四个字段。

| 面 | 要问的 3 个问题 | 要记的字段 |
|---|---|---|
| **主列表** | ① 受影响的是哪几行（不是「全部刷新」）？② 该行移出（筛选不再满足）、移入、还是原地改？③ 移出后焦点落哪行？ | `affected_control`=「主列表行日期徽标」；`refresh_timing`=「提交成功后同步」；`state_handling`=「保留选中；若移出，焦点落到下一行」 |
| **角标计数** | ① 哪几个角标变（今天/明天/最近7天/清单）？② 计数是全量 `COUNT` 还是「已加载页数」（两者会不一致）？③ 会不会被硬截断（如 `Take(500)`）？ | `affected_control`=「侧边栏『今天』角标数字」；`data`=「COUNT(*) WHERE dueDate 落在今天」；`refresh_timing`=「与列表同一事务后重算」 |
| **详情面板** | ① 哪几个字段跟着变？② 正在编辑的草稿会否被覆盖？③ 面板是否重载（丢滚动位置）？ | `affected_control`=「详情日期块文本与相对描述（『明天』）」；`state_handling`=「不重置草稿，仅同步非编辑中字段」 |
| **日历/时间视图** | ① 从哪个日期格消失、出现在哪格？② 跨月/跨年要不要自动跳转？③ 全天与定时任务位置是否变化？ | `affected_control`=「月视图 10/23 与 10/24 两格」；`refresh_timing`=「写入提交后重排；不自动跳月」 |
| **搜索** | ① 索引即时更新还是下次查询重算？② 按旧日期还能否搜到？③ 结果行日期显示同步吗？ | `affected_control`=「搜索结果行日期徽标 + WHERE dueDate 匹配集」；`refresh_timing`=「写入后失效缓存，下次查询重算」 |
| **提醒调度** | ① 原提醒取消、新提醒注册了吗？② 已到点的提醒会否误触发？③ 删除任务后提醒是否还弹（孤儿提醒）？ | `affected_control`=「调度队列中该任务的条目」；`data`=「`remindTime` + `deleted`」；`refresh_timing`=「写入后立即重算下次触发时刻」 |

`linkage.csv` 硬规则：`affected_control` **不许写「界面刷新」**（要写具体控件 + 它显示什么）；`refresh_timing` 必须四选一（**提交成功后同步 / 事件广播 / 下次进入时 / 定时**，「实时」不算）；每行必须有 `test_ref` 并在 S2 就起草用例；`status` 初始 `pending`，S6 接线后 `wired`，验证后 `verified`。

```bash
python3 tools/linkage_matrix.py --project . --markdown   # 功能 × 六面矩阵
```

判据：每个 `must` 功能的六面格子都有值（`pending` 也算），空格必须补理由。

### 5 · 写 16 节契约（每个 `must` 功能一个文件）

标题**逐字**匹配 SCHEMAS §8，缺一节即 FAIL（不适用写 `N/A：` + 理由）。每节最容易糊弄的地方与反例：

| 节 | 最容易糊弄成 | 反例 | 该怎么写 |
|---|---|---|---|
| §1 目标与入口 | 「可从任务详情修改日期」 | 漏右键菜单、快捷键、日历拖拽三个入口 | 全部入口 + 快捷键 + 替代路径 + 前置上下文 |
| §2 界面与层级 | 「弹出日期选择器」 | 不写弹出方向、遮挡、尺寸 | 控件顺序层级 + 浮层/子菜单关系 + 可滚动区 + 尺寸策略 |
| §3 每个菜单选项 | 「有今天/明天/自定义」 | 漏分隔符位置、漏默认项、漏「点完关不关」 | 每叶：完整路径+顺序+类型+默认项与当前项+打开关闭行为+鼠标跨层与键盘行为 |
| §4 显示条件 | 「视情况显示」 | 无 | 出现条件 + 隐藏后布局与焦点处理 |
| §5 可用与选择条件 | 「可用时可用」 | 可用与选中混成一句 | 可用条件+禁用解释+互斥组合+最大选择数+取消选择+选中态来源值 |
| §6 筛选条件 | 「按日期筛」 | 不写 AND/OR、不写时区、不写角标口径 | AND/OR 嵌套优先级+包含排除+空值+边界日期与时区+排序+分组+分页+角标口径 |
| §7 业务实现逻辑 | 「调用日期服务」 | 只写调用不写规则 | 求值顺序+默认规则+参数+校验+算法边界（能被具体输入复算） |
| §8 具体效果 | 「界面更新」 | 不给可复算例子 | 每步后文案、数值、位置、列表成员、计数、反馈 |
| §9 状态变化 | 只写 happy path | 不写保存中/失败/冲突/取消 | 原状态→事件→条件→目标状态→副作用；含加载/保存中/失败/冲突/重试/取消/撤销 |
| §10 数据读取 | 「读数据库」 | 不写查询条件与新鲜度 | 字段来源+查询条件+派生值+数据新鲜度+空库与异常库行为 |
| §11 数据写入 | 「更新记录」 | 不写事务范围、不写完成信号 | 命令与参数+精确字段+事务范围+约束+写入时点+完成信号+失败保留+必须不变的字段 |
| §12 跨页面联动 | 「同步刷新」 | 无刷新时点、不指 `LK-` | 六面各自影响+刷新失效机制+时序一致性+对应 `LK-xxx` |
| §13 并发与生命周期 | 「已考虑并发」 | 无 | 连点/重复提交/A→B 切换/迟到结果/防抖/关窗/退出/重启/睡眠唤醒 |
| §14 撤销与恢复 | 「支持撤销」 | 不写窗口期、不写连续编辑 | 恢复哪些值+窗口期+连续编辑+保存失败重试+误操作保护 |
| §15 体验标准 | 「体验流畅」 | 违反 R11 不可验收 | 输入法组合+焦点返回+Esc/Enter+可访问性+布局稳定+动效+性能起止点与数值 |
| §16 测试与证据 | 「测试通过」 | 用截图代替落库证明 | 正常/负向/边缘/跨页面/立即退出重启的用例号与断言值 |

**同一句的两种写法**（§11 为例）：

不合格：「用户修改日期后，更新任务的日期字段并保存。」——哪个字段变、哪些绝不能变、事务多大、何时算完成、失败怎么办，全不可判定。

合格：

```
命令：Cmd.SetTaskDueDate{taskId, date, keepTime}
参数：taskId 为入队时捕获的不可变 ID（不读「当前选中行」）；date 为本地日期；keepTime=true 时保留原 remindTime 的时分。
写入字段：仅 TaskModel.dueDate 与 modifiedTime；必须不变：title/content/priority/projectId/status/deleted。
事务范围：单行 UPDATE，无跨表写入。写入时点：点选项后立即提交，无确认按钮。
完成信号：PendingSave 可 await；成功后列表与角标同步刷新；失败保留草稿并显示红字「保存失败：<脱敏原因>」+ 重试入口。
```

### 6 · 状态机与流程（20% 工时）

- `state-machines.md`：每个有生命周期的对象一个 `SM-`（任务/重复规则/提醒/清单），三表结构见 SCHEMAS §9，每机 ≥1 条非法转换。
- `flows.md`：每个 `FL-` 四段（目标/起点/路径/点击数 + 正常路径/失败与取消/边界/恢复）。
- **点击数必须记**：它是 S9 行为 diff 的唯一量化基线（失效模式 19）。

### 7 · 未知怎么处理（不猜，进表，给动作）

**核心纪律：不猜。** 一条规则不确定时只有三条合法出路：

| 出路 | 何时用 | 具体动作 |
|---|---|---|
| ① 补验（首选） | 有办法观察到 | 立刻执行 `verification_action`，观察结果补进证据与契约 |
| ② 登记阻断未知 | 无法验证且影响核心行为 | `unknowns.csv` 加 `blocking=yes`；契约该节写 `N/A：见 U-0xx，待补验` |
| ③ 接受为风险 | 影响很小或不影响本版范围 | `blocking=no` + `status=accepted-risk`，`DECISIONS.md` 记谁接受 |

**不允许的第四条路**：写「按原版」/「同原版逻辑」/「视情况」然后继续。G2 把这些词当 FAIL。

`verification_action` 写法对照：

| 不合格 | 合格 |
|---|---|

## 门禁 G2

### 机器判定（`gates/rules/g2.py`）

| # | 检查项 | 期望 | 不通过怎么修 |
|---|---|---|---|
| 1 | must 契约覆盖率 100% | `priority=must & scope=in` 的行，`contract_ref` 指向的文件都存在 | `contract_scaffold.py` 批量生成后逐个填实 |
| 2 | 契约 16 节齐且非空 | 二级标题与 SCHEMAS §8 逐字一致，16 节都在，正文非空或以 `N/A：` 开头 | 按节补写；`N/A` 必须带理由 |
| 3 | 菜单叶子有命令与契约 | `type != separator|label` 的节点，`command`、`contract_ref` 均非 `-` | 补命令 ID 与契约引用 |
| 4 | 三条件非空且无禁用词 | 三列非空；不含「视情况/按原版/同前/一般/通常」 | 改写真值表达式或明确上下文 |
| 5 | linkage 每行有刷新时点与测试号 | `refresh_timing` 属四选一明确表述；`test_ref` 非空 | 补时点与 `T-` 号（S2 就起草用例） |
| 6 | `affected_control` 不含「界面刷新」 | 逐行检查 | 改成具体控件 + 它显示的内容 |
| 7 | features 每行有契约与验收引用 | `scope=in` 行 `contract_ref`、`acceptance_ref` 非 `-` | 补齐；`scope=out` 可 `-` 但 `notes` 要有理由 |
| 8 | 菜单树父子闭合 | 每个 `parent_id` 在表内存在或为 `ROOT` | 补父节点或修正 ID |
| 9 | 无占位残留 | BLUEPRINT 全目录无 `TODO`/`待定`/`TBD`/`待填`/`___` | 逐处替换；未定转 `unknowns.csv` |

### 人工判定（产品官，Agent 不得自批）

| # | 判什么 | 判定问句 |
|---|---|---|
| 1 | 三条件是否真分开 | 随便指一个菜单项：「它什么时候出现、什么时候点不动、什么时候显示选中——是三句不同的话吗？」 |
| 2 | 六面是否有漏 | 随便指一个 `must` 功能：「改完之后角标会变吗？搜索还搜得到吗？日历会跳吗？」 |
| 3 | §11 是否够具体 | 「这条写完后，另一个 Agent 照着写会不会写错？」 |
| 4 | 未知是否诚实 | 「有哪一节你自己写得不踏实但没登记？」 |
| 5 | 点击数可信 | 「你说改日期 6 次点击，能当场重数一遍吗？」 |

> 人工判定 1 是 S2 的**核心关卡**。三条件答不成三个独立答案，S6 一定做出「该灰的不灰」，那时返工是整个菜单树。

## 常见翻车点

| # | 症状 | 真因 | 对策 |
|---|---|---|---|
| 1 | 功能清单齐、做出来内部不联动（失效模式 01） | 只列功能，没列功能之间怎么互相影响 | 六面强制每功能六问；矩阵查空格；G6 联动门兜底 |
| 2 | 多层菜单选项不对/该灰的不灰（失效模式 02） | 显示、可用、选中混成一句「看情况」 | 三列强制分开 + 五组探针 + G2 禁用词判定 |
| 3 | 改了 A 结果 B 被改（失效模式 05） | 异步执行时读「当前选中」而非入队时捕获的 ID | §11 写死「命令携带不可变 `entityId/patch/revision`」；§13 写 A→B 切换用例 |
| 4 | 旧结果覆盖新选择（失效模式 06） | 读路径无 generation/queryId 校验 | §10 写「结果带 generation，过期丢弃」；§13 写迟到结果处理 |
| 5 | 边改边退，数据丢了（失效模式 03） | §11 没写完成信号，§13 没写关窗 | §11 必须有「完成信号」；§13 必须含关窗/退出/重启三项 |
| 6 | 冻结后还在改蓝图（失效模式 18） | 没意识到 S2 输出会进 S3 冻结 | S2 收尾即停止修改；新发现走 `BLUEPRINT/CHANGES/` 变更单 |
| 7 | 界面像了但用起来别扭（失效模式 19） | 只对视觉，没记操作步数与焦点行为 | `flows.md` 记点击数；`screens.csv` 记 `focus_restore`；§15 记焦点返回与 Esc/Enter |
| 8 | 契约很长但没法验收（R11） | 体验要求写成形容词 | §15 每条必须是数值或检查步骤，否则退回重写 |
| 9 | 菜单截图只截最底层 | 中间层信息（子菜单指示、分隔符、hover 态）丢失 | 每展开一层截一张；同层截悬停/不悬停两张 |
