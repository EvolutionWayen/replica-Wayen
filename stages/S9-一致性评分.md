# S9 · 一致性评分

> 上游：实现 + 原版截图 · 下游：S10 差异化 / S11 发布 · 门禁：G9

## 一句话

用**两个独立的分**说清「做到什么程度了」：功能分（原版有的、我做了多少）+ 界面分（放一起像不像）；两个分不互相抵消，缺失清单必须能被反驳。

## 输入

| 从哪来 | 文件 | 缺了就不许开工 |
|---|---|---|
| 功能进度 | `BLUEPRINT/features.csv`（`progress` 列） | 列与实现不符 → 先修（不许手填分数绕过） |
| 原版截图 | `screens/`（基准，同尺寸同缩放） | 缺 → 界面分无法量，停 |
| 自己截图 | `clone-screens/`（与基准同尺寸） | 尺寸不一致 → `imgdiff` 不可比，重拍 |
| 点击基线 | `BLUEPRINT/flows.md` 的「点击数」 | 缺 → 行为 diff 没有对照数字 |
| 有意差异 | `DECISIONS.md` 中所有「刻意不同」条目 | 缺 → 会把有意差异算成缺失，分数失真 |
| 测试结果 | `TEST/results/*.json`（最新） | 缺 → 功能分不能只靠 `progress` 列自查 |

## 动作序列

### 1 · 功能分（30 分钟，脚本算，不许手填）

```bash
python3 replica-skill/replica-diff/parity.py BLUEPRINT/features.csv
```

计价规则（来自上游 `parity.py`，本项目沿用）：

| 项 | 权重 | 说明 |
|---|---|---|
| `must` | 3 | 不做产品就没意义 |
| `should` | 2 | |
| `could` | 1 | |
| `progress=yes` | 满分 | |
| `progress=partial` | 半分 | |
| `progress=no` | 0 | |
| `scope=out` | **不计入分母** | 有意不做的不该扣分 |
| `original=no`（自己新增） | **不计入分子分母** | 差异化功能不加分也不扣分 |

判据：`parity.md` 里的功能分必须与 `features.csv` 实算一致。**手填分数是违规**——G9 会重算比对。

### 2 · 界面分（90 分钟，量像素不量感觉）

```bash
python3 replica-skill/replica-diff/imgdiff.py screens/S-01-main.png clone-screens/S-01-main.png --out diffs/S-01.png
```

`imgdiff` 把两张图转成边缘图比结构，忽略配色差异——所以「我换了品牌色」不会扣分，但「侧边栏宽度不对」会扣。

打分四件套（缺一不可）：

| 判据 | 机器可判 | 阈值 |
|---|---|---|
| ① 逐项打勾表通过率 | 是 | ≥90%，且 缺失项 = 0 |
| ② 关键尺寸误差 | 是 | 栏宽/行高/热区/按钮 ≤2px；弹窗宽高 ≤4px |
| ③ 关键色值 | 是 | 结构色 hex 相等；文字色 ΔRGB ≤3 |
| ④ 盲测 | 否（人） | 同尺寸 A/B 并排给 3 个独立评审，指出差异 ≤2 条且无结构性差异 |

**四项同时成立才给 90 分**。三项达标一项不达标 → 记 75–89，进差异清单。

打分档位（量纲 = 复刻保真度，不是「愿不愿意用」）：

| 分 | 含义 | 处置 |
|---|---|---|
| 90–100 | 放一起看不出差别 | 可交付 |
| 75–89 | 像，但能指出几处细节 | 记差异清单，P1 内收敛 |
| 60–74 | 大致像，明显便宜 | 进打磨循环，不得交付 |
| <60 | 不像 | 重做该模块 |

> **量纲警告**：`愿不愿意每天开`（6.5/10）与 `复刻保真度`（90/75/60）是两套量纲，不可换算、不可相加。每份报告必须标注用的是哪套。

### 3 · 行为 diff（60 分钟，最容易被跳过的一项）

界面像 ≠ 用起来像（失效模式 19）。逐流程比四项：

| 项 | 怎么比 | 只看视觉会漏掉什么 |
|---|---|---|
| 点击数 | 用 `flows.md` 的基线数字，实际重数一遍 | 原版 6 次点击，你做成 9 次 |
| 焦点行为 | 操作后焦点落在哪，键盘是否可继续 | 焦点丢失，用户得重新 Tab |
| 错误态 | 同一个失败场景，两边的提示文案与可恢复动作 | 原版可重试，你只能退出 |
| 记忆状态 | 切走再回来，选中/滚动/筛选是否保留 | 每次回来都回到顶部 |

不合格的写法：「操作体验接近原版」。合格的写法：「改日期：原版 6 次点击，本版 8 次；焦点在提交后回到标题框（原版回到日期块）」——这两条都是可判定的事实。

### 4 · 写缺失清单（按建设顺序排，30 分钟）

缺失清单不是按「重要度」排，是**按将来补做的顺序排**（谁不依赖谁，谁先做）。

```markdown
| # | 缺失项 | 类型 | 原版权威 | 影响评分 | 补做前置 | 预估 |
|---|---|---|---|---|---|---|
| 1 | 重复任务「此后全部」分支 | 功能 | FL-07 | 功能 -4 | 需先定计数口径（D-014） | 2 周 |
| 2 | 侧边栏与主区之间缺 1 条分隔线 | 界面 | screens/S-01 | 界面 缺失 项 | 无 | 1 小时 |
| 3 | 弹窗宽 300 vs 原版 260 | 界面 | screens/S-02-popup | 界面 近似 项 | 无 | 2 小时 |
```

规则：

- **必须能反驳**：每条给出「原版权威在哪」，别人可以说「这条不算缺」并给出理由。
- **每条标前置**：有 `D-` 依赖的写在「补做前置」列。
- **不许把「我不打算做」写进缺失清单**——那是 `scope=out`，在 `features.csv` 里，不参与扣分。

### 5 · 排除有意差异（20 分钟，这一步决定分数是否可信）

从 `DECISIONS.md` 取出所有「刻意不同」条目，逐条在评分里豁免并写明：

| 有意差异 | 豁免理由 | 记在哪 |
|---|---|---|
| 文字色抬亮（`#9B9B9B` → `#6E6E73`） | 原版 2.78:1 不达 WCAG；复刻不复制缺陷 | `DECISIONS.md` + parity 备注 |
| 无系统通知推送 | A 档 ad-hoc 签名下不可靠 | `DECISIONS.md` |
| 无深色模式 | 令牌集中，未来可换肤 | `DECISIONS.md` |
| 会员全部解锁 | 本版不做商业 | `DECISIONS.md` |

**不豁免的**：你说「这个做起来麻烦」而没写 `D-` 的项——那是纯缺失，照扣。

### 6 · 跑 G9（10 分钟）

## 细节级产出

| 文件 | 最小内容 | 判定它「够细」的标准 |
|---|---|---|
| `REPORT/parity.md` | 功能分（含算式）+ 界面分（四项分列）+ 缺失清单（按建设顺序）+ 有意差异豁免表 | 功能分能用手算复现；界面分四项各有「达标/未达标」与证据；缺失清单每条有「原版权威」与「补做前置」 |
| `diffs/` | 每屏 `imgdiff` 输出图 | 每张对应一屏；文件名含 `S-id` |
| 打勾表 | 逐项 一致/近似/缺失/多出/无法判定 | 通过率可算（一致 ÷ 总项）；无法判定 项不许猜，须重采 |
| `DECISIONS.md` 引用 | 豁免项都指到 `D-` | 每条豁免有 `D-` 编号 |

## 门禁 G9

### 机器判定（`gates/rules/g9.py`）

| # | 检查项 | 期望 | 不通过怎么修 |
|---|---|---|---|
| 1 | `parity.md` 存在且含三段 | 功能分、界面分、缺失清单三段都在 | 按报告结构补齐 |
| 2 | 功能分可复算 | 重算 `features.csv` 得到的分数与 `parity.md` 记录一致 | 删掉手填数字，改用脚本输出 |
| 3 | 双分不混算 | 报告里功能分与界面分是两个独立字段，且无「综合分」 | 拆开；综合分是禁止项 |
| 4 | 功能分达阈值 | 功能分 ≥ `manifest.thresholds.parity_feature`（默认 80） | 补 must 功能，不许调低阈值 |
| 5 | must 全绿才叫可交付 | must 功能 `progress` 全 `yes` | 未全绿时报告里必须写「不可交付」，不许写「基本可用」 |
| 6 | 缺失清单每条可反驳 | 每行有「原版权威」列且非空 | 补证据引用；补不了的删掉该条 |
| 7 | `diffs/` 覆盖已建屏幕 | 每屏一张 imgdiff 输出 | 补跑 |
| 8 | 有意差异有 `D-` | 每条豁免在 `DECISIONS.md` 能找到 | 补 `D-` 或取消豁免 |

### 人工判定（产品官，不参与计算但决定是否接受）

| # | 判什么 | 判定问句 |
|---|---|---|
| 1 | 「说不出差距」是否成立 | 「把你的和原版并排，你能指出几处？」（≤2 处且无结构性差异才算过） |
| 2 | 缺失清单是否诚实 | 「这几条你确定不打算本版做吗？」→ 说确定就移出缺失清单、进 `scope=out` |
| 3 | 界面分是否掩盖了功能缺失 | 「界面 88 但功能 72，你觉得这算做完了吗？」（答案必须是不算） |
| 4 | 是否接受带病交付 | 「剩下这 3 条 S3 你能接受吗？」（书面接受才放行） |

## 常见翻车点

| # | 症状 | 真因 | 对策 |
|---|---|---|---|
| 1 | 界面像了但用起来别扭（失效模式 19） | 只对视觉，没对操作步数与焦点行为 | 行为 diff 四项（点击数/焦点/错误态/记忆状态）必做 |
| 2 | 功能分虚高 | 手填分数或把 `partial` 记成 `yes` | G9 判定 2：重算比对；`partial` 只给半分，脚本算 |
| 3 | 界面分掩盖功能缺失 | 用综合分「平均」两个维度 | 双分制，禁止综合分（G9 判定 3） |
| 4 | 缺失清单写成「待优化项」 | 没有「原版权威」列，无法反驳 | 每条必须有 `screens/S-xx` 或 `FL-xx` 出处 |
| 5 | 把「我不做」也算进扣分 | 有意差异没走 `D-` | 豁免表 + `DECISIONS.md` 双向引用 |
| 6 | 截图尺寸不一致，diff 结果无意义 | 没遵守同尺寸同缩放 | 报告里记两张图的尺寸；不一致先重拍 |
| 7 | 打勾表里有「无法判定」却给了 90 分 | 「无法判定」应该重采而不是计入通过 | 「无法判定」项禁止猜；重采后重新算通过率 |
| 8 | 性能数字不可比（R12） | 只写「更快」 | 每个性能项带口径：起点/终点/环境/p50-p95 |

## 示例

### 示例 1 · parity.md 的功能分算式（可手算复现）

```
must   24 项：yes 18 / partial 2 / no 1 / out 3  → 计入 21 项，权重 3
       分子 = 18*3 + 2*1.5 = 57；分母 = 21*3 = 63        → 90.5
should  9 项：yes 6 / partial 2 / no 0 / out 1  → 计入 8 项，权重 2
       分子 = 6*2 + 2*1.0 = 14；分母 = 8*2 = 16          → 87.5
could   5 项：yes 2 / partial 1 / no 2 / out 0  → 计入 5 项，权重 1
       分子 = 2*1 + 1*0.5 = 2.5；分母 = 5*1 = 5          → 50.0

加权功能分 = (90.5*63 + 87.5*16 + 50.0*5) / (63+16+5) = 7351.5/84 = 87.5
```

这个例子本身就是一个教材：加权分 87.5 超过阈值 80，但 must 里有 1 项为 `no`、2 项 `partial` → **仍判「不可交付」**。分数达标与 must 全绿是两个独立条件，缺一不可。

算式必须能贴进报告——**能复算的分数才是分数**，否则是感觉。

### 示例 2 · 界面分四项的实样

| 判据 | 结果 | 证据 |
|---|---|---|
| ① 打勾表通过率 | 92%（一致 33 / 总 36，缺失 0，近似 3） | `diffs/S-01.md` |
| ② 关键尺寸误差 | 侧边栏 240 vs 239 = 1px 通过；弹窗宽 300 vs 260 = 40px 不通过 | 像素扫描记录 |
| ③ 关键色值 | 结构色全等；文字色 `#6E6E73` vs `#9B9B9B` ΔRGB 大 → 记为**有意差异**豁免 | `D-021` |
| ④ 盲测 | 3 个评审共指出 4 处（超 2 处）不通过 | `REPORT/blind-test.md` |

结论：②和④未达标 → 界面分 78（75–89 档），「像但能指出几处细节」，不得交付。

## 退出与交接

| 交接物 | 门槛 | S10 / S11 怎么用 |
|---|---|---|
| `REPORT/parity.md` | 双分 + 缺失清单 + 豁免表 | S10 从缺失清单找差异化机会；S11 用分数做发布判断 |
| `diffs/` | 每屏一张 | S11 的发布说明可引用 |
| 缺失清单 | 每条可反驳、按建设顺序 | S10 的改进项必须走 S2 契约补写，不能直接从这张表进代码 |
| `DECISIONS.md` | 豁免项都已登记 | S11 的发布说明写明「与原版的已知差异」 |

**交接状态要求**：G9 退出码 `0`；功能分 ≥80 且 must 全绿才允许称「可交付」；界面分单独记录不参与抵消；缺失清单能反驳。

**下一个接手的人需要知道的唯一一句话**：功能分和界面分是两件事，谁也不能替谁说话；must 没全绿时无论界面多像都不叫可交付。
