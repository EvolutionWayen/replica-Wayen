# S1 · 取证 recon

> 上游：S0 制品身份 · 下游：S2 行为蓝图 · 门禁：G1

## 一句话

把「这个应用到底有哪几个屏幕、从哪进、能做什么、数据长什么样」变成一张每条都能指到证据的地图；这一阶段不判断行为细节，只保证**没有一条结论是猜的**。

## 输入

| 从 S0 拿什么 | 文件 | 缺了就不许开工的判据 |
|---|---|---|
| 制品身份 | `PROJECT.md` 的目标制品段 + `evidence/artifact-identity.txt` | 无 SHA-256 或无法复算 → 停。取证对象不确定，后面全部白做 |
| 范围边界 | `PROJECT.md` 的不做清单（≥5 条四段式） | 没有不做清单 → 停。S1 一定会范围失控（失效模式 20） |
| 档位 | `.replica/gate.manifest.yml` 的 `tier` | A 档可读数据库副本与二进制；B/C 档不可。档位不明 → 不知道哪些取证手段可用 |
| 执行约束 | `AGENTS.md` + `REDLINES.md` | 缺 AGENTS.md → 取证 Agent 会顺手改进产品目录 |

开工前**必做的一步**：复算一次制品哈希，与 `evidence/artifact-identity.txt` 比对。

```bash
shasum -a 256 "<installer>"   # 与记录不一致 → 立即停，报告产品官
```

## 动作序列

### 1 · 建证据目录与命名约定（5 分钟）

```bash
mkdir -p evidence/{shots,db,api,dom} screens
printf '# 证据索引\n\n| 文件 | 采集方式 | 采集时间 | 对应 S-xx |\n|---|---|---|---|\n' > evidence/INDEX.md
```

命名规则写死并写进 `AGENTS.md`：`evidence/shots/<S-id>-<主题>-<序号>.png`，例 `evidence/shots/S02-date-menu-01.png`。**evidence/ 只加不改**——同一画面拍坏了重拍用新序号，不覆盖旧文件。

### 2 · 屏幕树盘点（60–90 分钟，最容易被做浅的一步）

**目标**：拿到完整的 `screens.csv` 与 `recon.md` 第 2 段。

操作序列：

1. **列出全部一级入口**。桌面端逐个走：主窗口、菜单栏（每个下拉都点开）、右键菜单、托盘图标、快捷键、深链、命令行参数。Web 端走：URL 路由表、页面内所有导航控件、直达链接、分享链。
2. 对每个入口**拍一张进入后的画面**，命名按约定。
3. 建立父子关系：谁是根、谁从谁进、谁能到哪去（`entry` 列写「怎么进来」，`exits` 列写「怎么离开」）。
4. **同一屏幕的不同形态算同一条**（例如任务详情展开/收起），但状态列要分开记。
5. 遇到进不去的地方（权限后、付费墙后、服务端渲染），**不要绕**，登记为「不可见区域」并进 `recon.md` 第 7 段。

判据：`screens.csv` 每一行的 `entry` 列都能在 `evidence/shots/` 找到对应截图；`recon.md` 第 7 段明确列出「看不到的部分」。

### 3 · 屏幕三态取证（每屏 3–5 分钟）

对 `screens.csv` 每一行，**必须**记齐四态：有数据（`state_filled`）、空（`state_empty`）、加载（`state_loading`）、错误（`state_error`）。无权限/禁用态记 `state_permission`，不适用填 `-` 并在 `notes` 写理由。

取不到的就**明确记 `no`**，不要留空、不要猜。G1 会检查这四列。

实操技巧：
- 空态最容易取：新建一个空清单/空项目，进去截图。
- 加载态最容易被忽略：在网络慢时点一下，或断开网络强制走超时分支。
- 错误态：能造的就造（例如把数据文件改成只读、断网、输入非法值）。

### 4 · 功能清单抽取（60 分钟）

**从屏幕和入口反推功能，不是从想象反推。**

对每个屏幕问三问：这里用户能做的**动作**有哪些？每个动作**改变了什么**？做完之后**哪里会变**？

写进 `features.csv`，11 列严格按 SCHEMAS §2。要点：

| 列 | 写法纪律 |
|---|---|
| `feature_id` | `F-<域>-<短名>`，全大写连字符。域用屏幕或模块名，短名用动词。例 `F-DATE-EDIT`、`F-TASK-COMPLETE` |
| `feature` | 动词开头一句话。写「修改任务的日期与时间」，不写「日期功能」 |
| `priority` | `must` 只给「不做这个产品就没意义」的功能，通常不超过总数 40% |
| `scope` | 在 `PROJECT.md` 不做清单里的，一律 `out`，并在 `notes` 写「不做清单第 N 条」 |
| `evidence` | 必须能指到 `S-xx` / `M-xx` / 证据文件路径。**指不到的不许进表** |
| `contract_ref` / `acceptance_ref` | S1 阶段留 `-`，S2 补。**不许提前编造 ID** |

判据：`features.csv` 每行 `evidence` 非 `-`；`scope=out` 每行 `notes` 有理由；`feature_id` 全表唯一。

### 5 · 数据模型观察（A 档重点，60 分钟）

只做**观察**，不做建模（建模是 S4）。观察手段按档位：

```bash
# A 档：数据库副本（绝不直接动真实库，失效模式 07 / 红线）
cp "/path/to/目标应用.db" /tmp/work.db
sqlite3 /tmp/work.db ".tables"
sqlite3 /tmp/work.db ".schema TaskModel"
sqlite3 /tmp/work.db "SELECT COUNT(*) FROM TaskModel;"
# WAL 未合并时主库可能读不到最新数据，先 checkpoint 再拷
sqlite3 "/path/to/目标应用.db" "PRAGMA wal_checkpoint(TRUNCATE);"
```

记录到 `data-dictionary.md` 的**草稿段**（正式定型在 S4）：实体名、字段名、类型、可空性、观察到枚举值的字段（如 `deleted` 实测出现 0/1/2 三种值 → 语义是 正常/垃圾箱/永久删除，**这个结论必须写成「观察到的取值 + 推测语义」两列**）。

要点：字段名的拼写错误要**原样保留**（例如 `dezcription`），这是证明字段来自真实制品而不是臆造的最好证据。

### 6 · 协议与外部依赖观察（可选，按不做清单裁剪）

只在功能确实依赖网络时做。手段：字符串常量表、端点常量类、浏览器开发者工具的网络面板（限自己的账号）。

**不做**：逆向加密协议、绕过付费墙、抓别人的账号。这些同时违反法律边界与红线 R9。

### 7 · 建 unknowns.csv（贯穿全程，收尾要清）

每当出现下面任一情况，**立刻**登记一条 `U-`，不要留在脑子里：

| 触发条件 | 例子 |
|---|---|
| 看到一个控件但点不出效果 | 「日期菜单里有『重复』二级菜单，鼠标移上去展开但快速移开就消失，取不到截图」 |
| 两条证据互相矛盾 | 「源码常量里有 `/api/v2/batch/*`，但网络面板只看到单资源请求」 |
| 只能看到结果看不到过程 | 「删除后 30 秒才从列表消失，不知道是定时器还是延迟提交」 |
| 系统行为相关无法复现 | 「跨时区旅行后提醒时间会不会变，本机没法造」 |

`unknowns.csv` 9 列严格按 SCHEMAS §6。**`verification_action` 必须可执行**，写「在 <屏幕> 用 <具体操作> 观察 <具体字段>，预期 <值>」，不写「再研究一下」。

`blocking` 列判定：**这个未知不解决，S2 就写不出契约的某节 → `yes`；只是影响体验细节 → `no`**。

### 8 · 证据归档与索引（20 分钟）

```bash
# 大文件（数据库副本、二进制切片）不入版本控制时，登记绝对路径 + 大小 + 哈希
shasum -a 256 /tmp/work.db >> evidence/INDEX.md
ls -la evidence/shots | wc -l
```

`recon.md` 第 9 段「证据索引」必须与 `evidence/INDEX.md` 一一对应。判据：随便抽 `recon.md` 里一条结论，能在 30 秒内找到它的证据文件。

### 9 · 规模判断与建议（20 分钟）

`recon.md` 第 10 段：S/M/L/XL + 理由 + 最难的三处。

| 规模 | 判据 |
|---|---|
| S | ≤5 屏、≤20 功能、无跨屏联动、单表数据 |
| M | 6–15 屏、21–60 功能、有 1–2 个跨屏联动域 |
| L | 16–40 屏、61–200 功能、多联动域、有状态机 |
| XL | >40 屏、>200 功能、或存在同步/多端/实时协作 |

「最难的三处」必须写成具体问题，例：「重复任务的『仅此一次/此后全部』分支会影响 3 个视图的计数口径，而原版对已完成实例的处理方式尚未观察清楚（见 `U-007`）」。

### 10 · 跑 G1（5 分钟）

```bash
python3 gates/run.py --stage G1 --project .
```

## 门禁 G1

### 机器判定（`gates/rules/g1.py`）

| # | 检查项 | 期望 | 不通过的修复动作 |
|---|---|---|---|
| 1 | `recon.md` 10 段齐 | 二级标题与 SCHEMAS §1 逐字一致，10 段都在 | 按模板补齐缺失段，标题不许改名 |
| 2 | `screens.csv` 列齐、ID 唯一 | 14 列名与顺序符合 SCHEMAS §3；`screen_id` 无重复 | 按模板重排表头；重复 ID 重编 |
| 3 | 屏幕三态齐 | `state_filled/empty/loading/error` 四列均为 `yes` 或 `-` | 补取证；取不到的填 `no` 并进 `unknowns.csv` |
| 4 | `features.csv` 列齐、ID 唯一、证据非空 | 11 列齐；`feature_id` 唯一；`evidence` 无 `-` | 补证据引用；指不到证据的功能移到 `unknowns.csv` 待验 |
| 5 | `unknowns.csv` 每条可执行 | 每条 `verification_action` 非空且不含「待定/再研究/进一步」 | 改写成「在 X 做 Y 观察 Z」 |
| 6 | `blocking` 与 `status` 合法 | `blocking` ∈ {yes,no}；`status` ∈ {open,resolved,accepted-risk,out-of-scope} | 按枚举改正 |
| 7 | 证据入版本控制 | `evidence/` 下存在受控文件（`git ls-files evidence/ | wc -l` > 0），且 `git check-ignore -v evidence/` 不命中全部 | 调整 `.gitignore`，至少纳入 schema/端点/结论文档（这是 本项目真实踩过的坑） |
| 8 | 无模板占位 | 各文件无 `TODO`/`待定`/`TBD`/`___` | 逐处替换或转 `unknowns.csv` |

## 常见翻车点

| # | 症状 | 真因 | 对策 |
|---|---|---|---|
| 1 | 功能清单齐，做出来内部不联动（失效模式 01） | 只列「有哪些功能」，没列「功能之间怎么互相影响」 | S1 就要在 `features.csv` 的 `notes` 里标出「此功能会影响哪些屏」；S2 转成 `linkage.csv` |
| 2 | 采证采到一半范围失控（失效模式 20） | 没划这一版做什么 | 每采一项先查不做清单；S1 收尾在 `recon.md` 列 skip 项及理由 |
| 3 | 分析数据库把真实数据搞坏（失效模式 07） | 直接对真实库执行 `UPDATE`/`VACUUM` | 一律 `cp` 到 `/tmp/work.db`；真实库只跑只读 `SELECT`；WAL 未 checkpoint 时主库读不到最新值（失效模式 12） |
| 4 | 界面像了但用起来别扭（失效模式 19） | 只拍了静态截图，没记操作步数与焦点行为 | `screens.csv` 的 `focus_restore` 列必须记；`flows.md`（S2）记点击数 |
| 5 | 结论漂亮但证据链断（失效模式 17/15） | 文档里写「已确认」但无出处 | 证据索引与文件一一对应；`git check-ignore` 确认证据真的进了版本控制 |
| 6 | 逆向读数乱码或半截字符串（失效模式 10） | 指针解码掩码取错宽度 | 任何指针解码结果都要抽样打印字符串验形，不能只看数值合法 |
| 7 | 静态找到方法就断定功能归属（失效模式 11） | 只证明了「类/方法存在」，没证明「有调用点」 | 静态结论必须补调用点证明（`__objc_selrefs` 槽位等）；与 S2 的菜单 `command` 列互相印证；证据等级 A 才进契约 |
| 8 | 反编译代码能编译但行为静默错（失效模式 08） | 大量方法体是空壳 | 还原码只当规格书读（R9）；S1 在 `unknowns.csv` 标注「此模块有空壳，行为不可信」 |
| 9 | 屏幕三态只记了「有数据」 | 空态/加载态/错误态要造场景才能看到 | 空态用新建空清单；加载态用断网或慢网；错误态改文件权限。取不到就填 `no` + 建 `U-` |

```markdown
（recon.md 第 7 段正文，标题为「## 7 可见区域与不可见区域」）

| 区域 | 能否看到 | 原因 | 影响 |
```
