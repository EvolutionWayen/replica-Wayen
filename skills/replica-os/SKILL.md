# replica-os · 复制重建体系（主编排）

> 一句话：**把一个别人的应用，按 12 个阶段拆透、冻结、重建、验证，产出「功能等价、
> 交互接近、代码与数据全自有、能长期本地用」的独立产品。**
>
> 这套东西的独特之处不是流程长，而是**每个阶段出口都有机器门禁，且不许自己给自己发奖**。
> AI 举证，产品官（Wayen）拍板。

---

## 0. 起步三问（没问清就别开局，30 分钟内必问）

| 问题 | 为什么非问不可 | 答不上来时的默认 |
|---|---|---|
| **1. 哪一个应用、哪个平台？** | 同名应用有多个版本、多端行为不同；版本号决定能不能锁定制品 | 追问到「名称 + 版本 + 平台」齐全，例：`目标应用 8.x / macOS` |
| **2. 这一版做哪个切片？** | 「复刻 Notion」不是项目，「Notion 的页面 / 块 / 分享」才是 | 默认取**核心闭环**：用户愿意为它付钱的那一条流程 |
| **3. 给谁用、到哪一档？** | 档位决定必做阶段与法律边界（见 §1） | 默认 **A 档本地自用**（只自己这台机器上用，不外发） |

另外必须当场确认的两件事（写进 `PROJECT.md`，后面不许口头改）：

- **不做清单 ≥5 条**（`S-` 范围外的事，逐条写理由）
- **档位**：A 本地自用 / B 半自用 / C 商业

⚠️ 起步最常见的翻车：用户说「我要做目标应用」，你就开始截图。**先确认切片。**
目标应用 638 个界面，全做是 L/XL（一个季度量级）；只做「任务增删改查 + 日期 + 重复 + 提醒 + 清单」
才是能做完的范围。

## 1. 档位：决定哪些阶段必做（开工第一件事）

| 档位 | 定义 | 必做 | 可裁剪 | 关键授权/限制 |
|---|---|---|---|---|
| **A 本地自用**（默认） | 只自己这台机器用，不外发 | S0–S9 + S11(本地打包) | S10 可简化为「自己骂原版什么」；S11 商业部分不做 | **可做源码分析 / 二进制逆向 / 数据库直读**，仅限本地自用与研究；还原代码**只当规格书**（R9）；数据库**默认操作副本** |
| **B 半自用** | 给身边几个人用，要安装包 | A + 安装/升级/卸载门 + 数据迁移演练 | 商业品牌、支付 | 同上，但**必须**做数据迁移演练 |
| **C 商业** | 对外卖 | 全部 + 品牌清扫 + 上架合规 + 支付对账 | 无 | A 档的逆向授权**不再适用**；必须有许可证与素材来源台账 |

**档位不是标签，是开关**：它直接决定第 3 个技能（`replica-local-source`）能不能用、
S11 做哪些门、法律风险谁承担。只写「自用」两个字不够，要写清「不外发」这个前提。

## 2. 12 阶段与门禁（全流程地图）

> 读法：**「细节级产出」那一栏没有的东西，不许进下一阶段。**
> 机器判定 = `python3 gates/run.py --stage G<n> --project .`；人工判定 = 产品官。

| # | 阶段 | 输入 | 细节级产出 | 门禁（机器判定摘要） | 用哪个技能/工具 |
|---|---|---|---|---|---|
| **S0** | 立项与边界 | 目标应用、为什么、给谁 | `PROJECT.md`（含不做清单 ≥5）、`DECISIONS.md` 前 3 条、`REDLINES.md`、`AGENTS.md`、档位判定 | **G0**：一句话定位成立 + 不做清单 ≥5 + 档位明确 + 目标制品身份（名称+版本+SHA-256） | 本技能 §0 |
| **S1** | 取证 recon | 目标制品、你的账号、公开文档 | `recon.md`(10 段)、`screens.csv`、`features.csv`、`evidence/` 原件、`unknowns.csv` | **G1**：每条结论可指到证据；屏幕四态齐；未知项登记且给出补验动作；证据入清单 | `replica-recon`(上游)、`replica-local-source`、`tools/evidence_manifest.py` |
| **S2** | 行为蓝图（**核心，最耗时最值钱**） | S1 全部产物 + 你的账号实操 | `menus.csv`（三条件）、`flows.md`、`contracts/C-F-xxx.md`（16 节）、`state-machines.md`、`data-dictionary.md`、`linkage.csv` | **G2**：must 契约覆盖率 100%；16 节无空项；每个菜单叶子有命令+契约；每条联动有刷新时点+测试号 | `replica-blueprint`（**必须加载**）、`tools/contract_scaffold.py`、`tools/menu_walk.py`、`tools/linkage_matrix.py`、`tools/blueprint_lint.py` |
| **S3** | 产品官审查与**冻结** | S2 全部 + 「待你决定」清单 | `BLUEPRINT-LOCK.md`（版本号+全文件 SHA-256+确认记录）、修订后的契约、`DECISIONS.md` 追加 | **G3**：产品官逐条确认；阻断级未知=0；哈希可复算；**未确认项不得伪造批准** | 本技能 §4（交接点） |
| **S4** | 架构 architect | 冻结蓝图 | `SPEC/ARCHITECTURE.md`、`schema.sql`、路由/命令清单、竖切优先的构建顺序、`TRACEABILITY.csv` | **G4**：每个 must 功能映射到表/命令/路由；高风险竖切跑通「建→读→重启还在」；无未决技术选型 | `replica-architect`(上游) |
| **S5** | 设计系统 | 原版截图 + 冻结蓝图 | `SPEC/DESIGN/tokens.json`、`tokens.css`、`components.md`（每组件全状态）、开源图标/字体替换表 | **G5**：对比度 0 失败；每组件有 default/hover/focus/disabled/loading/error；无原版素材残留 | `replica-design`(上游)、`contrast.py` |
| **S6** | 逐屏重建 | 冻结蓝图 + 设计系统 + 架构 | `src/` 逐屏代码、`BUILD/build-log.md`、`features.csv` 逐行勾选、`clone-screens/` | **G6（联动门，最严）**：勾 done 的功能其联动条目全 `wired` 且有测试通过证据；三态齐；键盘可完成主流程；控制台 0 错误 | `replica-build`(上游)、`tools/linkage_matrix.py --strict` |
| **S7** | 后端与本地能力 | 架构 + 已建界面 | `src/` 数据层、认证（本地可单用户）、存储、提醒、导入导出 | **G7**：真文件持久化（禁内存库）；关窗/退出冲刷有结构化结果；写失败不丢草稿；重启后数据在 | `replica-backend`(上游，**需本地化改造**) |
| **S8** | 测试 | 蓝图流程 + 已实现功能 | `TEST/test-plan.md`（每流程正/负/边缘）、`e2e/`、`TEST/bugs.md`（分级） | **G8**：S1/S2 缺陷=0；每条 must ≥1 条端到端断言；全量连跑 ≥3 次稳定 | `replica-test`(上游)、R1–R5 |
| **S9** | 一致性评分 | 实现 + 原版截图 | `REPORT/parity.md`（功能分+界面分+缺失清单按建设顺序）、`diffs/` | **G9**：功能分 ≥80 且 must 全绿才叫"可交付"；界面分单独记录**不参与抵消** | `replica-diff`(上游)、`tools/parity_score.py` |
| **S10** | 痛点与差异化 | 真实用户评价 | `REPORT/feedback.md`（带链接与计数）、改进项 → 新功能行进 `features.csv` | **G10**：每条痛点有链接与样本量；改进项必须**走 S2 契约补写**，不许直接进代码 | `replica-entrepreneur`(上游)、`reviews.py` |
| **S11** | 品牌与发布 | 通过 G8/G9 的构建 | A 档：`REPORT/release/local-runbook.md`（启动/备份/恢复/迁移/卸载）；C 档：品牌切割+落地页+商店合规 | **G11**：A 档＝干净机器装得上、开得了、数据不丢、卸得干净；C 档＝品牌清扫 0 命中 | `replica-brand`/`replica-launch`/`replica-deploy`(上游) |

### 2.1 顺序的硬约束（违反就返工）

- **S1 → S2 → S3 严格串行**。蓝图不能和取证并行，否则蓝图里全是猜测。
- **S6 与 S7 可交错**，但 S6 的「数据接口」必须先是**以假实现落定的稳定签名**（换真实现不改界面代码）。
- **S8 的用例从 S2 就开始写**（契约第 16 节），S8 只是补齐与执行。
- **S10 可以提前单跑**：只想判断「值不值得做」时，S0 + 粗 S1 + S10 就够。
- **只有明确标注的一次性验证原型**可以先于蓝图冻结；**原型不许当实现**。

### 2.2 三条铁律（违反后面全白做）

1. **细节不透不进开发。** 讲不清「谁看得到、为什么能点、点了改哪张表、别的页面怎么跟着变」，就不许写代码。
2. **页面做出来 ≠ 功能做出来。** 每个功能必须过**六面联动**（主列表 / 角标计数 / 详情 / 日历时间 / 搜索 / 提醒通知），受影响的每面都要有刷新时点与测试证据。
3. **AI 举证，产品官拍板。** 未确认的蓝图不得批量开发；确认后冻结，改先算影响面。

## 3. 怎么跑这套流程（命令级）

```bash
# 一次性的项目骨架
./scripts/new-project.sh <目录> --target "原应用名 版本"

# 每阶段先读阶段卡，再造产物
读 stages/ 下对应阶段卡（00 §2 的 S0…S11）

# 每阶段出口跑门（不通过不许进下一阶段）
python3 gates/run.py --stage G2 --project .
python3 gates/run.py --stage all --project . --json

# 蓝图期高频用的四个诊断工具（产品官审查前必跑全套）
python3 tools/blueprint_lint.py  --project . --fix-hints
python3 tools/menu_walk.py      --project . --check
python3 tools/linkage_matrix.py --project . --md-out REPORT/linkage.md
python3 tools/parity_score.py   --project . --markdown --md-out REPORT/parity.md
```

**退出码语义**：`0` 干净／`1` 已完成检查但有问题／`2` 用法或输入错误（**没做检查**）。
把 `2` 当 `1` 处理是最常见的假绿：它意味着检查根本没跑。

### 3.1 三个阶段各调什么（速查）

| 阶段 | 必须先跑 | 判据 |
|---|---|---|
| S1 出口 | `tools/evidence_manifest.py --check` | 0 MISSING，新文件已登记 |
| S2 出口 | `tools/blueprint_lint.py` + `menu_walk --check` + `linkage_matrix` | lint 无 ERROR；菜单缺项 0；六面都有人管 |
| S3 冻结 | 重算全文件 SHA-256 写进 `BLUEPRINT-LOCK.md` | 冻结后任何改动 → G3 FAIL |
| S6 出口 | `linkage_matrix --strict` | 未 wire 的面 = 0 |
| S9 出口 | `parity_score --fail-under 80` | must 全绿 + 功能分达标 |

## 4. 与产品官（Wayen）的交接点

**他不是每步都在场，但这 6 个点必须他拍板**（其余时间：只看门是否通过，不必看过程）。

| 时点 | 要他做什么 | 为什么非他不可 | AI 提供什么 |
|---|---|---|---|
| **S0 立项** | 定档位、定不做清单 | 决定后面所有取舍 | 候选范围 + 每项的代价估算（人天/周） |
| **S1→S2 之间** | 确认「看的到的东西就是这些」 | 只有他知道自己真实用法 | 屏幕清单 + 未知台账 + 证据索引 |
| **S3 审查会** | **逐条校正行为理解与体验取舍**，然后冻结 | 手感与气质只有人判；他承担范围风险 | 「待你决定」清单（每条附证据 + 候选解释 + AI 建议） |
| **S6 核心闭环后** | 真机试一次，说「愿不愿意每天开」 | 只有他知道自己的使用频率与耐心 | 可运行构建 + 与原生对比截图 |
| **S9 评分** | 接受或反驳分数与缺失清单 | 定义「做到什么程度算够」 | 功能分/界面分/缺失清单（可反驳口径） |
| **S10→S11** | 拍板定价、分发、对外发布（不可逆） | 对外发布不可逆 | 痛点证据 + 定位方案 |

### 4.1 审查会怎么开（S3 的具体做法）

1. **提前 24 小时发材料**：`features.csv`（must 行）+ 全部 `contracts/` + `menus.csv` 三条件 + `unknowns.csv` + `blueprint_lint` 输出。
2. **「待你决定」清单**单独一页，格式固定：

   ```
   D-01 [S2/日期菜单] 清除日期是否同时清除提醒时间？
        证据：S-02 截图 3 张（只有第 1 张能看到提醒字段）
        候选：A 同时清（简单）／B 只清日期（更常见）
        AI 建议：B，因为原版 X 处行为如此（证据 U-001）
        影响面：C-F-DATE-EDIT §11 写入字段、LK-004 提醒调度、T-105
   ```

3. **逐条记录确认**：确认的写进 `DECISIONS.md`（`D-xx`），改了契约的同步改版本号。
4. **冻结**：算全文件哈希写 `BLUEPRINT-LOCK.md`，从此只读。

### 4.2 禁止事项（这几条比流程更重要）

- **不许自批验收**。实现者不得作为唯一验收人；A 档单人串行时必须标「自复验（独立性未满足）」。
- **不许暗改契约**。实现时发现契约有问题 → 停 → 提变更单 → 产品官决定。
- **不许伪造批准**。他没说过的确认，一个字都不许写进 `DECISIONS.md`。
- **不许把推测写成实测**。UI 观察 / 源码推断 / 数据库观察必须分等级标注。
- **不许用「按原版」「视情况」结案**。写不出来就进 `unknowns.csv` 并给补验动作。
- **不许跳过受影响的联动测试**（改一处必跑回归）。

## 5. 角色与派工

| 角色 | 是谁 | 职责 | 禁止 |
|---|---|---|---|
| **产品官** | Wayen | 校正行为理解、确认体验取舍、拍板范围、真机验收 | — |
| **Lead（总控）** | 主 Agent | 拆解、派工、跑门、关键路径攻坚、集成 | 不写主要业务代码（会失去把关独立性） |
| **蓝图工** | Agent | 取证、拆透、写契约、暴露未知 | 不得把推测写成实测 |
| **重建工** | Agent | 按契约实现、自测、同类扫描 | 不得自批验收 |
| **验证官** | Agent（独立上下文） | 独立复现、独立重写测试、真机走查 | 不改产品代码 |

**派工纪律**（写进每张任务卡）：写作用域隔离（一文件一 owner）／验收标准派工时写死（含量化指标）／
证据纪律（`文件:行`、命令、实测数字）／`blocked_by` 显式化／不做超范围优化／**并发期间禁止 `git add -A`**。

## 6. 汇报格式（缺项视为未完成）

```
【状态】完成 / 部分完成 / 阻塞
【产出】文件路径（可点击验证）
【证据】关键结论的出处：文件:行 / 命令 / 实测数字
【验证】我跑了什么命令，结果是什么（含退出码与次数）
【存疑】我不确定的地方 / 已知缺口
【影响】这次改动可能影响哪些既有功能
```

「已完成」「测试都过了」「应该没问题」**不是**汇报。
数字必须带**口径**（起点/终点/环境/样本量/commit），否则一天后就变成下一个「口径不一」。

## 7. 常见翻车（都来自实测，不是设想）

| # | 症状 | 真因 | 本体系怎么挡 |
|---|---|---|---|
| 1 | 功能清单齐、内部不联动 | 只列「有哪些功能」，没列「功能之间怎么互相影响」 | `linkage.csv` + G6 联动门（R18）+ `linkage_matrix.py` |
| 2 | 多层菜单选项不对、该灰的不灰 | 显示/可用/选中三种条件混成一句「看情况」 | `menus.csv` 三列强制分开 + `menu_walk --cards` |
| 3 | 边改边退，数据丢了 | fire-and-forget / 防抖 timer 不在写链 / 关窗不冲刷 | R1–R3：串行链 + 可 await 完成信号 + 结构化冲刷结果 |
| 4 | 测试全绿但用户一用就崩 | 用 `sleep` 猜完成；用内存库测持久化 | R1/R4/R5：真文件 + 完成信号 + 故障注入 + 连跑 ≥3 次 |
| 5 | 改了 A 结果 B 被改 | 异步执行时读「当前选中」而非入队时捕获的 ID | 命令携带不可变 `entityId/patch/revision` |
| 6 | 旧结果覆盖新选择 | 没有 generation/queryId 校验 | 读路径带 generation，过期结果丢弃 |
| 7 | 分析数据库把真实数据搞坏 | 直接对线上库操作 | **默认操作副本**（A 档硬性要求） |
| 8 | 反编译代码能编译但行为静默错 | 大量方法体是空壳 | R8/R9：只当规格书；关键路径自己写并测试 |
| 9 | 动了原程序之后 App 变空壳 | 签名与权限链绑定 Team ID，改动即失去数据访问 | **只读不改**（R9）：取证只走副本与规格层 |
| 10 | 逆向读出乱码或半个选择器 | arm64 chained fixup 掩码用了 51 位 | 掩码 `value & 0x0000FFFFFFFFFFFF`；Swift 类用 `otool -oV` |
| 11 | 静态找到方法就断定功能归属 | 方法存在 ≠ 有调用点；Swift 静态派发绕过 `objc_msgSend` | 补调用点证明（`__objc_selrefs`）；证据等级 A 才进契约 |
| 12 | 在原库上改动被覆盖 | 直接写别人的库：程序下次落盘覆盖、启动重置字段 | **只在副本上只读导出**（R4） |
| 13 | 上游英文技能与本地档位冲突 | 上游禁止看源码，A 档允许（仅本地自用） | 用 `skills/replica-local-source` 覆盖该条，其余照用（见 `COMPAT.md`） |
| 14 | 三份模板三套编号，AI 各说各话 | 没有单一事实来源 | 00 §4 ID 规范 + §9 R 编号唯一权威 |
| 15 | 文档说「已修复」，代码里没修 | 正文手写现状 | `STATE.md` 是唯一现状来源（七态） |
| 16 | 门禁脚本写死某个项目的路径和数字 | 门禁与项目耦合 | manifest 驱动，阈值写在 `.replica/gate.manifest.yml` |
| 17 | AI 说「完成了」，实际只有半个功能 | 汇报无证据 | §6 汇报格式 + 门禁强制证据路径 |
| 18 | 蓝图冻结了还在改 | 没有冻结记录与哈希 | `BLUEPRINT-LOCK.md` + G3 实算哈希比对 |
| 19 | 界面像了但用起来别扭 | 只对视觉，没对操作步数与焦点行为 | S9 行为 diff（点击数/焦点/错误态/记忆状态） |
| 20 | 采证采到一半范围失控 | 一开始没划「这一版做什么」 | S0 不做清单 ≥5 + S1 明确 skip 项及理由 |

数字会漂：**结论性数字必须同时记 commit 与时间，并附复算命令。**

## 8. 三种使用路径

| 路径 | 什么时候用 | 怎么走 |
|---|---|---|
| **A 完整重建**（默认） | 从零做一个自用替代品 | `S0→S1→S2→S3(冻结)→S4→S5→S6⇄S7→S8→S9→S11`（S10 可选） |
| **B 中途接入** | 已有半成品，想按体系收敛 | 先 `S1 补齐 + S2 反向契约`（对已实现的代码写契约，暴露「当初没想清楚的地方」）→ 跑 G6 找洞 → S8/S9 收敛。**最容易发现「页面有、内部没联动」** |
| **C 单点使用** | 不必走全程 | 值不值得做＝S0+S10+粗 S1；原版有哪些功能＝S1；某功能怎么运作＝S2 单功能契约；我差在哪＝S9；为什么用户骂它＝S10 |

## 9. 与其他技能的关系

| 技能 | 关系 |
|---|---|
| `replica-blueprint`（本体系自带） | S2 的执行手册。**进 S2 必须加载**，它写清了菜单穷举、三条件判定、16 节逐节写法 |
| `replica-local-source`（本体系自带） | A 档的取证手册（源码/二进制/数据库）。S1 里凡涉及「看进去」的动作都由它管 |
| `replica-skill/replica-*`（上游 11 个，MIT，vendored） | 各阶段的方法素材与 Python 工具来源。**规则以本地为准**，冲突见 `COMPAT.md` |
| `gates/` | 判决层。工具只诊断，门禁才放行 |
| `tools/` | 诊断层。六个工具 + `tools/README.md` |

上游技能与本地阶段的完整映射、哪些规则被覆盖、哪些继续生效，见同目录 **`COMPAT.md`**——那是必读，
因为它解释了为什么「上游说禁止看源码，这里却允许」。
