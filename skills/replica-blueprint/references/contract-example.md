# C-F-DATE-EDIT · 修改任务的日期与时间

> **这是示范样例，不是某个项目的验收记录。** 用途：告诉你"细节级"到底要多细。
> 照抄结构可以，照抄结论不行——每一项都必须有你自己的证据（`S-xx` / `M-xx` / 证据文件）。
>
> 场景设定：一个本地的任务管理应用（这一类），A 档本地自用。
> 关联：`F-DATE-EDIT` / 屏幕 `S-01` `S-02` / 流程 `FL-01` / 菜单 `M-DATE` `M-DATE-TODAY` `M-DATE-CLEAR` /
> 数据 `E01.dueDate` `E01.allDay` `E01.remindTime` `E01.repeat` / 联动 `LK-001…LK-006` / 测试 `T-101…T-105`

---

## 1 目标与入口

**用户意图**：把一条任务的截止时间从"今天"挪到"明天 / 下周三 / 某个具体日期"，或者把日期整个清掉。

**全部入口**（缺一个都不算写完）：

| 入口 | 形态 | 前置上下文 | 备注 |
|---|---|---|---|
| 详情面板日期行 | 点击 `日期` 行 → 展开菜单 `M-DATE` | 任务已选中 | 主入口 |
| 右键任务行 | 上下文菜单 →「日期…」 | 列表里有任务 | 与详情面板打开**同一个** `M-DATE`，不另做一套 |
| 快捷键 `⌘D` | 直接打开 `M-DATE` | 焦点在列表或详情 | 焦点在输入框内时不响应（避免与输入法冲突） |
| 快速添加语法 / 自然语言 | 输入 `明天 10:00 写周报` | 在快速添加框 | 走解析器，最终调用**同一个命令** `Cmd.SetDueDate` |
| 拖拽到日历格 | 把任务行拖到日历某天 | 日历视图打开 | 只改日期，**保留**原时分（详见 §3 与 §15） |
| 拖拽到「明天」智能清单 | 同上 | 侧栏可见 | 等价于选"明天" |

**替代路径**：没有日期时，详情面板显示「添加日期」，点它同样打开 `M-DATE`（只是 `M-DATE-CLEAR` 这一项不可用）。

**前置上下文**：
- 必须有且只有一条选中的任务。多选状态下本功能**不启用**（`enabled_cond` 写清，见 §5）。
- 任务处于"已完成"状态时，日期行**仍可点**（改完成任务的日期是合法操作），但菜单里不出现「重复」分支。
- 应用处于退出冲刷阶段（`flushing=true`）时整个菜单禁用（见 §5、§13）。

**证据**：`screens/S02-date-row.png`、`screens/S02-date-menu.png`（菜单展开态）、
`evidence/probe/date-entry-matrix.md`（六个入口逐一实测记录）。
证据等级：入口 1/2/3 为 **A 实测**；入口 4/5/6 为 **C 推断**（尚未逐一验证，已登记 `U-003`）。

## 2 界面与层级

**日期行的控件顺序**（从左到右，不可调换）：

```
[ 📅 图标 ] [ 「今天 18:00」 或 「无日期」 ] [ ▾ 小箭头 ]
```

- 有日期时显示 `相对日 时分`（今天 / 明天 / 周三 / 7月14日，超过 7 天显示绝对日期）。
- 无日期时显示「添加日期」，颜色为 `text-muted`。
- 箭头仅在 hover / 展开时可见（减少视觉噪音）。

**菜单层级**：

| 层级 | 内容 | 展开方式 | 关闭方式 |
|---|---|---|---|
| L1 `M-DATE` | 今天 / 明天 / 本周末 / 下周一 / 选择日期… / ── / 清除日期 | 点击日期行，**在行下方**展开（非模态） | 点外部 / `Esc` / 选中一项 |
| L2 「选择日期…」 | 月历浮层（可翻月）+ 时间输入 | 点「选择日期…」后**在同一浮层内替换**为月历（不新开一层） | `Esc` 回到 L1；再 `Esc` 关闭整个浮层 |
| L2 「重复」子层 | 不重复 / 每天 / 每周 / 每月 / 自定义… | 悬停或点右侧 `›`，**向右**展开第二列（flyout） | 鼠标移回 L1 时 L2 消失 |

**可滚动区**：`M-DATE` 本身不滚动（固定 7 项 + 1 分隔符）。月历浮层在高度不足时整月滚动，**不**拆成两屏。

**尺寸策略**：
- `M-DATE` 宽 220px，行高 32px，浮层最大高度 `min(内容高度, 60vh)`。
- 月历浮层宽 260px；窗口宽 < 480px 时改为全宽底部抽屉（移动端）。

**证据**：`screens/S02-date-menu.png`、`screens/S02-calendar-popover.png`。证据等级：A 实测。

## 3 每个菜单选项

`M-DATE` 的同级顺序与类型（`menus.csv` 的权威行，这里只做引用式复述）：

| order | 类型 | 标签 | 默认项 | 点击后 |
|---|---|---|---|---|
| 1 | action | 今天 | ✅ **是默认项**（打开时高亮） | 立即应用：`dueDate = 今天同日同时分`，关闭浮层 |
| 2 | action | 明天 | — | 立即应用：日期 +1 天，时分保留 |
| 3 | action | 本周末 | — | 立即应用：落到最近的周六（若今天已是周六则今天） |
| 4 | action | 下周一 | — | 立即应用 |
| 5 | separator | ── | — | 不可点，不可聚焦（键盘跳过） |
| 6 | action | 选择日期… | — | **不应用**，切换到月历浮层（L2） |
| 7 | action | 清除日期 | — | 立即应用：`dueDate = null`，**同时**清 `remindTime`（见 §11 与 `U-001`） |

**默认项 vs 当前项**：
- **默认项**＝打开时高亮哪一项（`default_item = M-DATE-TODAY`），只影响焦点落点。
- **当前项**＝哪个选项代表任务现在的日期（若等于今天则「今天」右侧显示 ✓）。
- 两者**可以不同**：任务日期是 7 月 20 日时，打开菜单高亮「今天」（默认项），但没有任何 ✓（因为当前值不匹配任何快捷项）。
- ⚠️ 这是两件事，做成一件就会出现「一打开就显示打钩」的错觉。

**打开 / 关闭行为**：
- 打开：浮层出现在日期行下方 4px，水平左对齐；焦点进入菜单第一项（= 默认项）。
- 关闭：`Esc` / 点外部 / 选中动作项 → 关闭并把焦点**还给日期行**（不是还给整个详情面板）。
- 从 L2（月历）按 `Esc` → 回到 L1 并把焦点还给「选择日期…」；再按 `Esc` 才关闭整个浮层。

**鼠标跨层**：`M-DATE` → 悬停「重复」右侧区域时，第二列从右侧 0px 处展开，两列重叠 8px 的"桥"，鼠标沿对角线移动不会误关（关闭延迟 120ms）。

**键盘行为**：
- `↑ / ↓`：层内移动，跳过 separator。
- `→`：进入子层（「重复」/「选择日期…」）；`←`：回到父层。
- `Enter` / `Space`：执行当前项。
- `Esc`：见上面的逐层关闭顺序。
- 输入法组合态（中文拼音未上屏）时，`Esc` 先被输入法消费，不关菜单。

**证据**：`screens/S02-date-menu.png`、`evidence/video/date-menu-keyboard.mov`。证据等级：A 实测（键盘逐项走过一遍）。

## 4 显示条件

| 元素 | 出现条件 | 不出现时 |
|---|---|---|
| 日期行 | 始终出现（无日期时显示「添加日期」） | — |
| `M-DATE` 整体 | 单条任务选中 且 详情面板已展开 | 多选时菜单不可打开（点击无反馈，行本身显示为禁用态） |
| `M-DATE-TODAY/TOMORROW/WEEKEND/MONDAY` | 始终出现在菜单里 | — |
| `M-DATE-CLEAR`（清除日期） | **始终可见** | — |
| 「重复」子层入口 | 任务**非**已完成态 | 已完成任务不出现该行；菜单高度减少 1 行，**不补空白** |
| 月历浮层 | 点「选择日期…」后出现，替换 L1 内容 | — |

**隐藏后的布局与焦点**：
- 隐藏某一行时，浮层高度按行高整数倍收缩（`n × 32px`），**不留空洞**。
- 若当前焦点所在行被隐藏（例如任务在菜单打开期间被标记完成），焦点自动跳到**下一个可用项**；若已是最后一项则跳到上一项。
- 隐藏不会导致浮层重新定位（仍锚在日期行下方）。

**证据**：`screens/S02-date-menu.png`（正常）、`screens/S02-date-menu-completed.png`（已完成态，少了重复行）。
证据等级：A 实测。

## 5 可用与选择条件

> ⚠️ 本节最容易写坏：**可见 ≠ 可用，可用 ≠ 已选中**。三段分开写。

### 5.1 可用条件（能不能点）

| 选项 | 可用条件 | 禁用时的表现 |
|---|---|---|
| 今天 / 明天 / 本周末 / 下周一 | 任务可写（未处于只读/归档视图） | 整行 40% 不透明度，**不加** tooltip（可见即解释） |
| 选择日期…（月历） | 同上 | 同上 |
| **清除日期** | `dueDate != null`（**已有日期才能清**） | **可见但禁用**：文字变 `text-muted`，鼠标 hover 无高亮，点击无任何反应 |
| 重复子层入口 | 任务非已完成 且 任务可写 | 整行降透明度 |
| 全部菜单项 | `flushing == false`（不在退出冲刷阶段） | 整个浮层禁用，点击外部可关闭但不执行任何项 |
| 全部菜单项 | 仅单选（`selection.count == 1`） | 多选时浮层不打开 |

**关键区分（本次实证的典型陷阱）**：
「清除日期」在**只有重复、没有具体日期**的情况下 **可见但不可用**。
→ 所以"有重复"不等于"有日期"，**不能**用 `repeat != null` 代替 `dueDate != null`。

**禁用反馈规则**：
- 禁用项**可以聚焦**（键盘能停在上面），`Enter` 无效果并发出系统提示音（macOS `NSBeep`）。
- 禁用项**不显示** tooltip 解释——因为解释会反复打扰；替代做法是在项文字后加极浅的说明（仅「清除日期」有：「已有日期时可用」这句**不显示**，靠变灰表达）。

### 5.2 选中条件（打不打钩）

| 视觉 | 判定依据 | 说明 |
|---|---|---|
| 「今天」右侧 ✓ | `dueDate` 的日期部分 == 今天（本地时区） | 只比日期，**不比时分** |
| 「明天」右侧 ✓ | `dueDate` 日期部分 == 今天 + 1 天 | 跨月/跨年自动进位 |
| 「本周末」右侧 ✓ | `dueDate` 日期部分 == 最近周六 | — |
| 「下周一」右侧 ✓ | `dueDate` 日期部分 == 下一个周一（若今天周一，则为 7 天后） | — |
| 「重复」行右侧 `›` + 当前规则文字 | `repeat != null` 时在行尾显示简短规则（`每周工作日`），`repeat == null` 时不显示 | 这是**回显**不是打钩 |
| 重复子层内的 radio | `repeat.rule == 'WEEKLY' && byday ⊇ {MO,TU,WE,TH,FR}` 等（逐项在 `M-REPEAT-*` 行定义） | 单选组，同组内互斥 |
| 「选择日期…」 | 永不打钩 | 它是动作不是状态 |

**选中条件 ≠ 点击历史**：打钩只看当前持久值，不看"用户上次点过哪个"。

### 5.3 互斥与组合

- 「今天/明天/本周末/下周一」是**同一组快捷日期**：选中其中一个时其余不显示 ✓。
- 无日期时：**所有**快捷日期都不打钩，且「清除日期」禁用。
- 有日期但不匹配任何快捷项（如 7 月 20 日）：全部不打钩，但「清除日期」**可用**。
- 重复规则与日期**独立**：可以"每天重复 + 无具体日期"（部分产品的用法）。此时「清除日期」禁用，但「重复」行显示当前规则。

## 6 筛选条件

本功能**不涉及**列表筛选，但涉及**筛选后的可见性后果**（用户在筛选视图里改日期，任务可能移出当前列表）：

| 场景 | 期望行为 | 依据 |
|---|---|---|
| 在「今天」智能清单里把任务改成明天 | 写入成功后该行**从当前列表移出**，焦点落到下一行（若无下一行则落到上一行，若列表空则焦点回到列表容器） | `LK-002` |
| 在「已完成」视图改日期 | 行**留在原列表**（已完成视图不看日期） | 实测 |
| 在搜索结果里改日期 | 该条按新日期**重新过滤**：不再命中则移出结果；命中则就地更新徽标 | `LK-005` |
| 排序按日期升序时改日期 | 该行**重排**到新位置（整表重排，不做动画位移） | 实测 |

**边界日期**：
- 跨月：`1月31日 + 1天 = 2月1日`（不做"月末对齐"）。
- 闰日：`2月28日 + 1天` 在闰年为 `2月29日`，平年为 `3月1日`。
- 时区：全部按**系统本地时区**计算"今天"。系统时区在应用运行期间变化 → 菜单的「今天」高亮**不实时重算**，直到下次打开菜单（登记为已接受风险 `U-004`）。
- 全天任务（`allDay = true`）：改日期时**不动** `allDay`，时分字段保持原值但仍不显示。

**角标统计口径**：改日期会改变「今天」「最近 7 天」角标。口径＝该视图中未完成任务的条数，见 `LK-002`。

## 7 业务实现逻辑

**规则求值顺序**（严格按此顺序，顺序错了会出现中间态闪烁）：

```
1. 校验：selection.count == 1 且 flushing == false 且视图可写
2. 解析：把"今天/明天/本周末/下周一"解析为目标 LocalDate（本地时区）
3. 组合：newDue = 目标日期 + 原 dueDate 的时分（原 dueDate 为 null 时用 用户默认时间 09:00）
4. 全天修正：allDay == true → newDue 的时间部分置 00:00，并保留 allDay
5. 校验：newDue 不得早于任务的 createdAt 的日期（允许等于）→ 否则拒绝并提示"不能早于创建日"
6. 提交：调用 Cmd.SetDueDate{entityId, newDue, revision}（见 §11）
7. 成功后：广播 DueDateChanged{entityId, oldDue, newDue}（见 §12）
```

**默认规则**：
- 无原日期 → 时分取用户偏好 `defaultTaskTime`（默认 `09:00`）。
- 「本周末」定义 = 最近一个周六（若今天就是周六，取今天；若今天是周日，取"昨天"违反直觉 → 实际取**下周六**，见 `unknowns.csv U-005`）。

**参数与校验**：

| 参数 | 类型 | 约束 | 违反时 |
|---|---|---|---|
| 目标日期 | LocalDate | 不早于 createdAt 的日期；不晚于 `createdAt + 100 年` | 内联红字提示，浮层不关闭 |
| 时分 | LocalTime | 00:00–23:59 | 由月历的时间输入框校验（`§3 L2`） |
| revision | int | 必须等于读取时的 revision | 见 §13 冲突处理 |

**算法边界（必须写明，不许写"调用某服务"）**：
- 日期加减用**本地日历**（非 UTC），避免 DST 边界偏移。
- 每年 3 月/11 月的 DST 切换日：`02:30` 这类不存在的时刻，回退到 `03:00` 并在日志留一条 `DSTAdjust`。
- 「+1 天」在 DST 春季前进日意味着"实际经过 23 小时"，这是**预期行为**，不做补偿。

## 8 具体效果

**能被具体输入复算**（这是这一节的最低要求）：

| 输入（改前） | 操作 | 输出（改后） | 界面同时发生什么 |
|---|---|---|---|
| `dueDate = 2026-07-13 18:00`（周一） | 点「明天」 | `2026-07-14 18:00` | 日期行变「明天 18:00」；菜单关闭；焦点回日期行 |
| `dueDate = null` | 点「今天」 | `2026-07-13 09:00`（取 `defaultTaskTime`） | 日期行从「添加日期」变「今天 09:00」 |
| `dueDate = 2026-01-31 23:30` | 点「明天」 | `2026-02-01 23:30` | 跨月进位 |
| `dueDate = 2026-07-14 18:00, allDay=true` | 点「明天」 | `2026-07-15 00:00, allDay=true` | 日期行显示「明天」不带时间 |
| `dueDate = 2026-07-14 18:00` | 点「清除日期」 | `dueDate = null`，`remindTime = null` | 日期行变「添加日期」；**提醒行同时变空** |
| `dueDate = null, repeat = WEEKLY` | 点「清除日期」 | 无变化（该项禁用） | 点击无反应，播放提示音 |
| `createdAt = 2026-07-14`, `dueDate = 2026-07-20` | 手动选 `2026-07-13` | 拒绝 | 浮层不关，日期格下方红字「不能早于创建日 (7月14日)」 |

**反馈粒度**：
- 成功：无 toast（就地更新本身就够，加 toast 反而吵）。
- 失败（写入失败）：详情面板顶部红条「保存失败，已保留你的更改」+「重试」按钮，**不关闭**菜单。
- 校验失败：内联红字，**不关闭**菜单。

## 9 状态变化

**主状态机**（`SM-01 DueDateField`，详见 `state-machines.md`）：

| 原状态 | 事件 | 条件 | 目标状态 | 副作用 |
|---|---|---|---|---|
| Idle | 打开菜单 | 单选 & 可写 | MenuOpen | 记录 `revision` 快照 |
| MenuOpen | 选快捷日期 | 校验通过 | Saving | 乐观更新 UI；`pendingSave` 入队 |
| Saving | 写入成功 | revision 未变 | Idle | 广播 `DueDateChanged`；刷新六面 |
| Saving | 写入失败 | 网络/IO 错误 | SaveFailed | UI 回滚到快照；显示红条；保留菜单 |
| SaveFailed | 点重试 | 仍可写 | Saving | 重发同一命令（同一 `revision`） |
| Saving | 应用退出 | — | Flushing | 见 §13：必须等写入完成或明确失败 |
| MenuOpen | `Esc` / 点外部 | — | Idle | 焦点回日期行；**不写库** |

**不进入 Saving 的情况**：点禁用项、点 separator、在只读视图点任何项。

**冲突（revision 变化）**：写入前检查 `revision`；不一致 → 不覆盖，弹出「这条任务在别处被修改了。刷新后重试 / 保留我的更改」两个按钮。选"保留"则重新读最新值、用新 revision 重发。

## 10 数据读取

| 需求 | 来源 | 查询条件 | 新鲜度 |
|---|---|---|---|
| 当前日期值 | `E01 TaskModel.dueDate` | `WHERE id = :entityId` | 打开菜单时读一次，快照保存 |
| 当前 revision | `E01.revision` | 同上 | 同上（**写入时必须带回**） |
| 是否全天 | `E01.allDay` | 同上 | 同上 |
| 用户默认时间 | `E09 UserPrefs.defaultTaskTime` | 单行 | 应用启动时读一次并缓存 |
| 是否已完成 | `E01.completedAt IS NOT NULL` | 同上 | 同上 |
| 当前选中数量 | 视图层内存态 | — | 实时 |

**派生值**：
- 「今天/明天/本周末/下周一」的日期：每次打开菜单时按当前本地时区重算。
- 日期行的显示文案：`相对日(7天内) / 绝对日期(>7天) + 时分(非全天)`。

**空库与异常库行为**：
- `dueDate = null`：显示「添加日期」，「清除日期」禁用，其他项正常。
- `dueDate` 是非法值（例如 `0` 或超出范围）：按 `null` 处理，并在日志留 `CorruptDueDate{id, raw}`；**不**静默修正数据库。
- 读不到任务（已被删除）：关闭浮层，显示「这条任务已不存在」，焦点回到列表。

## 11 数据写入

**命令**：`Cmd.SetDueDate{ entityId: string, newDue: ISO8601|null, revision: int }`
**清除日期走同一命令**（`newDue = null`），**不**另开一个 `Cmd.ClearDate` —— 一条写路径，避免两处逻辑漂移。

| 项 | 值 |
|---|---|
| 精确字段 | `dueDate`（写）；`allDay`（**仅当**原值为 true 时把时间部分归零，值不变）；`updatedAt`（写当前时刻）；`revision`（+1）；**`remindTime`（仅当 `newDue = null` 时置 null）** |
| 必须**不变**的字段 | `id` / `createdAt` / `title` / `notes` / `listId` / `priority` / `tags` / `repeat` / `completedAt` |
| 事务范围 | 单表单行更新 + revision 递增，同一事务 |
| 约束 | `dueDate IS NULL OR dueDate >= createdAt 的日期 00:00`；`revision = :expectedRevision` |
| 写入时点 | 点击动作项后**立即**（不做防抖——日期是确定性单值，不需要防抖） |
| 完成信号 | 命令返回 `{ok: true, revision: n+1}` 的 Promise；**界面必须 await 它**再宣告成功 |
| 失败处理 | 抛错 → UI 回滚到快照 → 保留菜单 → 显示重试 |
| 幂等 | 相同 `entityId + newDue + revision` 重放：第二次会因 revision 不匹配而拒绝（安全） |

**为什么 `remindTime` 要跟着清**：见 `U-001`。当前采信"清除日期同时清除提醒"，因为"没有日期却有提醒"在语义上自相矛盾。
此结论已进 `DECISIONS.md D-02`（产品官确认）。若未来改为保留提醒，需走变更单并同步 §8、§12、`LK-004`。

## 12 跨页面联动

六面逐面写，每面给刷新时点与 `LK` 编号：

| 面 | 影响 | 刷新时点 | LK |
|---|---|---|---|
| **主列表** | 该行日期徽标就地更新；若排序按日期则整表重排 | 写入事务提交成功 → 同一个帧内同步刷新 | `LK-001` |
| **角标计数** | 「今天」「最近7天」「清单」角标重算 | `DueDateChanged` 广播 → 下一帧重算（合并同帧内多次变更） | `LK-002` |
| **详情面板** | 日期行显示新值；焦点**保留**在日期行 | 写入成功回调 → 立即 | `LK-003` |
| **日历时间** | 任务落到新日期格；跨周时从原周移除、插入新周 | 写入成功后 → 日历订阅 `DueDateChanged` | `LK-004` |
| **搜索** | 该条按新日期重新过滤；不再命中则移出结果 | 下次查询时（结果集带 `generation`，过期结果丢弃） | `LK-005` |
| **提醒通知** | 重算下次触发时刻；撤销旧通知请求、登记新请求 | 写入成功后 → 调度器重排 | `LK-006` |

**一致性要求**：
- 六面之间的刷新**不要求同一帧完成**，但**必须最终一致**，且用户可见的中间态不得出现"列表已变、角标没变"超过 1 帧。
- 若某面刷新失败（例如日历组件未就绪），**不影响写入本身**，但要在日志留 `LinkageRefreshFailed{face, id}` 并在下次进入该面时补偿。

**不适用的面**：本功能六面**全部适用**，无 `na`。

## 13 并发与生命周期

| 场景 | 期望行为 |
|---|---|
| **快速连点「明天」两次** | 第一次后菜单立即关闭 → 第二次点击落在列表上（不会变成"加两天"）。若菜单未关（极端慢机），第二次点击被 `saving` 状态吞掉 |
| **重复提交** | 同一 `revision` 的第二次写入被约束拒绝，UI 显示"已在保存中"，不重复发命令 |
| **A 改完立刻切到 B 再改 B** | 命令携带 `entityId`（入队时捕获），**绝不**在延迟执行时读"当前选中"。这是 R5/§10-05 的直接来源 |
| **迟到结果** | 每次读路径带 `generation`；返回时 `generation` 不匹配 → 丢弃结果，不覆盖新选择 |
| **防抖** | 本功能**不防抖**（单值确定性操作）。防抖只用于标题/备注这类连续输入 |
| **关窗（`⌘W`）** | `Closing` 拦截 → `e.Cancel = true` → 等待 `pendingSave` 完成 → 再真正关窗。冲刷失败 → 弹「还有更改未保存」并提供"重试/放弃" |
| **`⌘Q` 退出** | 同关窗，且冲刷有 3 秒上限；超时则提示并不退出（**不静默丢弃**） |
| **重启** | 已提交的写入必须还在（真文件持久化，见 R4） |
| **睡眠唤醒** | 唤醒后重算"今天"；若应用跨越了午夜，菜单打开时以新的"今天"为准（不主动刷新已打开的菜单） |
| **系统时区变更** | 不实时重算（见 `U-004`，已接受风险） |

## 14 撤销与恢复

| 项 | 规定 |
|---|---|
| 可撤销 | ✅ `⌘Z` 撤销最近一次日期修改（单步，窗口 30 秒） |
| 恢复哪些值 | `dueDate` + `allDay` + `remindTime`（若清除时连带清了提醒，撤销要**一起恢复**） |
| 窗口期 | 30 秒内或直到下一次修改；以先到者为准 |
| 连续编辑 | 连续改 3 次 → 视为 3 个独立撤销步（不做合并），避免"撤销一次跳回很早的状态" |
| 保存失败后重试 | 保留用户输入；重试用同一 `revision`；若期间 revision 变了 → 走 §9 冲突流程 |
| 误操作保护 | 无二次确认（改日期是低频可逆操作，加确认更烦）。但"清除日期"若**同时清除了提醒**，撤销提示文案要写明：「已撤销：日期与提醒都已恢复」 |
| 不可恢复场景 | 应用崩溃后重启 → 撤销栈清空（明确告知，不假装能撤销） |

## 15 体验标准

**R11：不能写成数值或步骤的体验要求 = 无效要求。** 所以本节全部可测：

| 项 | 可测标准 |
|---|---|
| 输入法组合 | 中文拼音输入中（未上屏）按 `Esc`：只清输入法，不关菜单。拼音上屏后再 `Esc` 才关 |
| 焦点返回 | 菜单关闭后焦点**必须**回到日期行（`document.activeElement` 断言）；从 L2 关闭则回到「选择日期…」 |
| `Esc` / `Enter` | `Esc` 逐层关（L2→L1→关）；`Enter` 执行当前聚焦项 |
| 可访问性 | 菜单 `role="menu"`，项 `role="menuitem"`；禁用项 `aria-disabled="true"` 且**可聚焦**；快捷键用 `aria-keyshortcuts` 标注 |
| 布局稳定 | 打开菜单**不改变**详情面板布局（浮层用 absolute 定位）；菜单内隐藏一行不引起浮层重新定位 |
| 滚动与动效 | 展开 120ms ease-out，收起 90ms；`prefers-reduced-motion: reduce` 时全部 0ms |
| 性能（含口径） | **起点**：点击动作项 → **终点**：列表行徽标文本更新。**环境**：M1 / 8GB / 1000 条任务。**p50 ≤ 16ms，p95 ≤ 50ms**（不含磁盘 fsync）；fsync 单独测，p95 ≤ 80ms |
| 长内容 | 任务标题 60 字符时，日期行不换行、不撑破面板（`text-overflow: ellipsis`） |
| 宽窄 | 320px 与 1440px 两种宽度下菜单不溢出屏幕边缘 |
