# replica-blueprint · 行为蓝图（S2 执行手册）

> 一句话：**蓝图的产出不是「一份文档」，是一组互相引用、每条都能被机器检查的规格。**
> 判断标准只有一条：**把这份蓝图交给一个没看过原版应用的人，他能不能做出行为一致的东西，
> 且做的时候不需要问你任何问题。**

S2 是整个体系里**最耗时、最值钱**的阶段。跳过它的代价不是"文档没写"，是 S6 建到一半发现
「点了没反应」「该灰的能点」「改完别的地方没更新」，然后返工。

## 0. 进入 S2 的前置（缺一条就别开始）

```
[ ] S1 已过 G1：recon.md 10 段齐、screens.csv 四态齐、unknowns.csv 已建
[ ] 手上有可操作的原版（自己的账号、能点、能改、能重启）
[ ] 有稳定的截图能力（每层菜单都要留图）
[ ] 已读 templates/blueprint/SCHEMAS.md（列名与 16 节标题的唯一来源）
[ ] 已知这一版的 must 功能清单（features.csv 里 priority=must & scope=in）
```

**顺序硬约束**：S1 没完不许开始 S2。蓝图建在猜测上，后面全部返工。

## 1. 九步操作序列（照做，别跳）

| 步 | 动作 | 产出 | 做完的判据 |
|---|---|---|---|
| **1** | **穷举菜单层**：每个菜单从顶层往下一层层展开、每层截图 | `screens/` 截图 + `menus.csv` 骨架 | 每个叶子都有路径、顺序、类型 |
| **2** | **拆三条件**：逐个叶子问「什么时候出现 / 什么时候能点 / 什么时候打钩」 | `menus.csv` 三列填满 | 没有一个叶子写「视情况」「按原版」 |
| **3** | **写流程**：把核心闭环按屏幕顺序串起来，数点击数 | `flows.md` 每流程 4 个子节 | 每条路径上的 `S-xx` 都在 `screens.csv` 里 |
| **4** | **建状态机**：哪些对象有状态、怎么转换、哪些转换必须被拒绝 | `state-machines.md` | 每个状态有「是否持久化」，每条非法转换有「期望拒绝方式」 |
| **5** | **定数据字典**：实体、字段、类型、默认、空值、约束、来源 | `data-dictionary.md` | 每个字段标「原版观察 / 推断」 |
| **6** | **写 16 节契约**：一功能一文件，逐节按 SCHEMAS §8 的最小内容写 | `contracts/C-F-xxx.md` | 16 节齐、无占位、无「按原版」 |
| **7** | **查六面联动**：每个写操作问六面「变不变」 | `linkage.csv` | must 功能六面都有条目或明确理由 |
| **8** | **登记未知**：凡是没验证的一律进台账 | `unknowns.csv` | 每条有可执行的补验动作；阻断级为 0 才能冻结 |
| **9** | **跑自检**：三个工具 + 人工通读 | 干净输出 | 见 §8 |

**估算**：一个「中等复杂功能」（如修改日期 + 重复）的完整契约约 **2–4 小时**；
一个 must 菜单叶子约 **15–30 分钟**。想快只能靠模板和工具，不能靠少写。

## 2. 菜单穷举操作法（这一步做不好，后面全歪）

### 2.1 每层截图法

```bash
# macOS 单窗口截图（最可靠，不会把别的 app 拍进来）
screencapture -x -l <windowID> screens/02-date-menu.png
# 找 windowID
osascript -e 'tell app "你的应用" to id of window 1'
```

**截图纪律**：
1. **一张图只拍一层**。不要把「日期菜单 + 重复子菜单 + 自定义」挤在一张图里——后面写三条件会错位。
2. **文件名带层号与用途**：`02-date-menu.png`、`04-repeat-weekly.png`。
3. **同一层要拍两张**：正常态 + 「该灰的时候」的那张。**灰的样子只有截图能证明。**
4. 截图立刻进 `screens/`，用 `python3 tools/evidence_manifest.py --project .` 登记。

### 2.2 逐层记录表（对着填，别凭记忆）

| 层 | 操作 | 截图 | 记录什么 |
|---|---|---|---|
| L0 | 主界面 | 01 | 整体布局、侧栏、主区、状态栏 |
| L1 | 点「日期」按钮 | 02 | 浮层位置/尺寸、**所有**选项、哪些灰、哪个打钩、分隔符在哪 |
| L2 | 浮层里点「重复」 | 03 | 二级浮层往哪展开（右侧/下方）、父层是否还在 |
| L3 | 二级里点「每周」 | 04 | 三级：选周几的按钮组、能否多选 |
| L4 | 三级里点「自定义」 | 05 | 四级：间隔/结束条件、数字输入框范围 |

**每一层必须回答的五个问题**（答不出就是没采到位）：
1. 这一层的**完整路径**是什么（`日期 › 重复 › 每周`）？
2. 每个选项的**同级顺序**（第几个）与**类型**（子菜单/动作/单选/多选/分隔符/纯文字）？
3. **什么时候出现**（显示条件）？隐藏后布局怎么变、焦点去哪？
4. **什么时候能点**（可用条件）？禁用时给什么提示？灰但可见的有哪些？
5. **什么时候打钩**（选中条件）？打钩依据是持久值还是草稿值？

### 2.3 条件反推法（最容易出错的地方）

**不要问「这个选项是干嘛的」，要问「什么情况下它会变」**。三种反推路径：

| 反推路径 | 怎么做 | 反问自己 |
|---|---|---|
| **数据反推** | 改变数据状态，看选项怎么变：没有日期时「清除日期」还在吗？只有重复没有日期时呢？ | 这个选项依赖哪个字段？ |
| **模式反推** | 切换模式：任务完成态 / 只读态 / 退出冲刷中 / 多选状态 | 换了模式它还一样吗？ |
| **时序反推** | 在写入中途、广播未到时点它，看是禁用还是排队 | 写入中能再点吗？点了会怎样？ |

**已验证的实例（目标应用日期菜单，来自 case 实录）**：
- `清除日期` 在「已有日期」时**可用**；在「只有重复、没有具体日期」时**可见但禁用**。
  这两句话必须分开写进两列，否则实现时一定做错（做出来就是"点了没反应"）。
- 「每周工作日」的**打钩依据是 `repeat.byday` 是否覆盖周一至周五**，不是「用户上次点过它」。
  这就是「选中条件 ≠ 点击历史」。

### 2.4 键盘与鼠标跨层（90% 的人漏掉这一块）

必测清单（每个菜单都走一遍）：
- `↑ ↓` 在层内移动；`→` 进子层；`←` 回父层；`Esc` 关到**哪一层**（全部关？只关一层？）
- **鼠标从父层移到子层的过程中，父层是否消失**（"斜着移过去"会不会关掉菜单）
- 打开时**默认焦点**在哪个选项；关闭后**焦点回到哪里**（原按钮？行？）
- 有快捷键的选项：快捷键在菜单关闭时也生效吗？冲突了怎么办？

## 3. 三条件分离判定（本技能最核心的一节）

**三种条件回答三个完全不同的问题，混在一起写就是给自己挖坑。**

| 条件 | 回答什么 | 错了的后果 | 在 `menus.csv` 的列 |
|---|---|---|---|
| **显示条件** | 节点**在不在** | 显示了不支持的选项 → 用户以为支持 | `visibility_cond` |
| **可用条件** | 能不能**点** | 该灰的可点 → 点了报错或静默无效 | `enabled_cond` |
| **选中条件** | **打不打钩** | 打钩错位 → 用户以为设置成功，实际没改 | `checked_cond` |

### 3.1 直接照抄的判定问句

写每个叶子时，**逐句自问**，把答案贴着数据/模式/时序写：

```
【显示】
Q1 这个选项在什么上下文才出现？（哪个屏幕、哪个面板、哪种对象类型）
Q2 依赖哪些数据状态？（有日期 / 有重复 / 已完成 / 多选…）
Q3 不出现的时候，布局怎么补？焦点落到哪？
Q4 是"永久不出现"还是"这次不出现"？（前者应该在别处说明，不要留行）

【可用】
Q5 可见但禁用的情况有哪些？（逐条列，不要合并成"条件不满足时禁用"）
Q6 禁用时给什么反馈？（灰掉 / tooltip / 点击后提示语；必须能具体到文案）
Q7 全局性禁用：退出冲刷中 / 写入中 / 无权限 / 离线，分别是全菜单禁用还是部分？
Q8 互斥与组合：选了 A 还能选 B 吗？最多选几个？怎么取消选择？

【选中】
Q9 打钩由哪个**持久值**决定？（字段名 + 值）
Q10 还是由**草稿值**决定？（还没提交的编辑）
Q11 有没有"部分选中"（多选组里选了 3 个中的 2 个）？怎么表现？
Q12 打钩和点击历史无关吗？（如果有关，说明这是"最近使用"而不是"选中"）
```

### 3.2 合格 / 不合格对照

| | 不合格（会被 lint 判禁用词或 REF-LINK-VAGUE） | 合格 |
|---|---|---|
| 显示 | `视情况显示` | `当任务详情面板打开 且 任务未永久删除 时出现；不出现时浮层高度减少 1 行，焦点保持在日期按钮` |
| 可用 | `需要权限` | `需有可写权限；退出冲刷阶段（flushing=true）全菜单禁用；禁用时整行降为 40% 不透明度，不加 tooltip` |
| 选中 | `点了就选中` | `repeat.rule == 'WEEKLY' && repeat.byday ⊇ {MO,TU,WE,TH,FR}` |
| 混合 | `看情况，一般能点` | 拆成上面三行 |

### 3.3 用工具逼自己

```bash
python3 tools/menu_walk.py --project . --cards    # 每个叶子一张三条件卡，缺哪条一目了然
python3 tools/menu_walk.py --project . --gaps     # 只列缺项
python3 tools/menu_walk.py --project . --check    # 门禁用：缺一个就退出码 1
```

`--cards` 的输出长这样（缺的会打 ✗ 并告诉你该写什么）：

```
菜单叶子卡  今天  M-DATE-TODAY
  路径        日期 › 今天
  类型        action（动作）    同级 order：1
  ── 三条件（必须分开写，不许写"看情况"）──
  ✓ 显示条件    任务详情打开且未完成
  ✓ 可用条件    任务存在且可写
  ✓ 选中条件    dueDate == 今天
  ── 触发 ──
  ✓ 命令      Cmd.SetDateToday
  ✓ 契约      contracts/C-F-DATE-EDIT.md
```

## 4. 16 节契约：逐节写法与反例

**格式唯一来源**：`templates/blueprint/SCHEMAS.md` §8。标题必须**逐字一致**（脚本按标题匹配）。
生成骨架：

```bash
python3 tools/contract_scaffold.py --feature F-DATE-EDIT --name "修改日期" --out BLUEPRINT/contracts/
python3 tools/contract_scaffold.py --all --project . --only-must    # 批量
```

每节生成时会带 `<!-- 必须写什么：… -->` 与 `<!-- 反例：… -->` 注释。
**注释是提示，填完要删**（留着会被 lint 判 `CONTRACT-HINT-LEFT`）。

### 4.1 逐节最小内容 + 反例（完整版见 `references/contract-example.md`）

| 节 | 必须写到什么程度 | 反例（都不合格） |
|---|---|---|
| **1 目标与入口** | 用户意图一句话 + **全部**入口：按钮、快捷键、右键菜单、拖拽、深链、命令行 + 前置上下文 + 替代路径 | ✗「用户点日期按钮改日期」——漏了快捷键、右键菜单、拖拽 |
| **2 界面与层级** | 控件从上到下顺序、浮层/子菜单关系、可滚动区、宽度/高度策略、尺寸变化时谁先收缩 | ✗「一个弹层选择日期」 |
| **3 每个菜单选项** | 逐项：完整路径、同级顺序、类型、默认项、当前项来源、打开/关闭行为、鼠标跨层、键盘行为 | ✗「日期菜单有今天/明天/自定义」 |
| **4 显示条件** | 可判定的表达式或明确数据状态 + 隐藏后布局与焦点处理 | ✗「按原版显示」 |
| **5 可用与选择条件** | **可用 ≠ 已选中**，分两段；禁用解释、互斥、组合、最大选择数、取消选择；选中态由哪个值决定 | ✗「可点，选中时高亮」 |
| **6 筛选条件** | AND/OR 与嵌套优先级、包含/排除、空值、边界日期与时区、排序、分组、分页、**角标统计口径** | ✗「按时间过滤」 |
| **7 业务实现逻辑** | 规则求值顺序、默认规则、参数、校验、算法边界 | ✗「调用日期服务」 |
| **8 具体效果** | 每步后的文案、数值、位置、列表成员、计数、反馈，能被具体输入复算 | ✗「界面刷新」——要写「主列表行日期徽标同步更新，角标重算为 3」 |
| **9 状态变化** | 原状态→事件→条件→目标状态→副作用；加载/保存中/失败/冲突/重试/取消/撤销 | ✗「保存后状态更新」 |
| **10 数据读取** | 实体.字段来源、查询条件、派生值、数据新鲜度、空库与异常库行为 | ✗「从数据库读」 |
| **11 数据写入** | 命令与参数、精确字段、事务范围、约束、写入时点、完成信号、失败保留、**必须不变的字段** | ✗「写入任务表」 |
| **12 跨页面联动** | 六面逐面写影响 + 刷新时点 + 对应 `LK-xxx` | ✗「相关页面刷新」 |
| **13 并发与生命周期** | 快速连点、重复提交、A→B 切换、迟到结果、防抖、关窗、Cmd+Q、重启、睡眠唤醒 | ✗「正常使用没问题」 |
| **14 撤销与恢复** | 恢复哪些值、窗口期、连续编辑、保存失败重试、误操作保护 | ✗「支持撤销」 |
| **15 体验标准** | 输入法组合、焦点返回、Esc/Enter、可访问性、布局稳定、动效、**性能起止点** | ✗「体验流畅」——R11：不能写成数值或步骤的要求 = 无效要求 |
| **16 测试与证据** | 正常/负向/边缘/跨页面/立即退出重启 的用例号 + **断言的具体值** | ✗「测试通过」；截图不能代替落库证明 |

### 4.2 写契约的四个手感

1. **每写一句「会变」，就顺手写「变成什么」**。`§8 具体效果` 不是修辞，是可复算的输入输出。
2. **顺手写六个面**。写到 `§11 数据写入` 时，立刻问「这六个面各自怎么变」——这是 `§12` 的来源，
   也是 `linkage.csv` 行的来源（同一条事实写在一处，另一处引用 `LK-xxx`）。
3. **`N/A：理由` 只用于真的不适用**。比如纯读的功能「§11 数据写入：N/A：本功能不写库」。
   不接受「暂时不适用」。
4. **写完自己念一遍**：一个没看过原版的人照着做，会不会有无法回答的问题？有就补，别留。

## 5. 六面联动清单（防「页面有、内部没联动」）

**任何会改变数据或视图状态的操作，都必须过这六面。** 不适用的面也要写理由，不许省略。

| 面 | 要问的问题 | 合格写法示例 |
|---|---|---|
| **主列表** | 这一行变什么？位置变吗（排序/筛选）？整表重排还是就地更新？ | `该行日期徽标就地更新，不重排整表` |
| **角标计数** | 哪些数字要重算（今天/本周/清单/标签）？统计口径是什么？ | `侧栏「今天」「本周」角标重算；口径=未完成且 dueDate 落在区间` |
| **详情面板** | 显示哪个字段？保留焦点吗？正在编辑冲突怎么办？ | `日期字段显示新值，焦点保留在日期按钮` |
| **日历时间** | 落到哪个日期格？跨周/跨月要重排吗？ | `落到新日期格；跨周时该条从原周移除并插入新周` |
| **搜索结果** | 这条还在结果里吗？排序位置变吗？索引要更新吗？ | `按新日期重新过滤该条；若不再命中则从结果移除` |
| **提醒通知** | 下次触发时刻要重算吗？已排队的通知要撤吗？ | `调度器重算下次触发；撤销旧的通知请求并登记新请求` |

**联动行怎么写**（`linkage.csv` 一行）：

```
LK-001 | F-DATE-EDIT | TaskDateChanged{taskId} | S-01 | 主列表行日期徽标 |
TaskModel.dueDate | 写入事务提交成功 → 同步刷新 | 保留选中；若因筛选移出则焦点落到下一行 | T-103 | wired
```

六列必须都有：**源 → 事件 → 受影响控件 → 数据 → 刷新时点 → 状态处理 → 测试号 → 状态**。
`affected_control` 不许写「界面刷新」这种笼统话（lint 会判 `REF-LINK-VAGUE`）。

**自查命令**：

```bash
python3 tools/linkage_matrix.py --project .                 # 六面矩阵
python3 tools/linkage_matrix.py --project . --strict        # 有未 wire 的面即失败
python3 tools/linkage_matrix.py --project . --md-out REPORT/linkage.md
```

输出会直接点名两类问题：
- **一面都没有** 的 must 功能（做了也只是个壳）
- **只有 1 面** 的可疑功能（多半没想透）

## 6. 未知怎么处理（不猜，但要推进）

**规则：不确定的绝不写进契约。写进 `unknowns.csv`，并且必须给可执行的补验动作。**

| 字段 | 要求 | 不合格 |
|---|---|---|
| `description` | 具体到行为，不写「细节待定」 | ✗「日期行为待定」 ✓「清除日期是否同时清除提醒时间」 |
| `verification_action` | **能执行的动作** | ✗「再研究一下」 ✓「在 S-02 执行清除日期，立即看提醒字段并截图」 |
| `blocking` | 阻断开发＝yes | 冻结前必须 0 条 |
| `status` | `open / resolved / accepted-risk / out-of-scope` | `accepted-risk` 与 `out-of-scope` 必须产品官批准 |

**补验优先级**：影响 must 功能的 > 影响数据写入的 > 影响联动的 > 影响文案的。
补验完立刻回填契约，并在 `DECISIONS.md` 留一行（如果是产品取舍）。

## 8. 自检清单（S2 出口，全部打勾才能进 S3）

### 8.1 机器自检（三条必须干净）

```bash
python3 tools/blueprint_lint.py  --project . --fix-hints   # 退出码 0，无 ERROR
python3 tools/menu_walk.py       --project . --check       # 退出码 0，gap_count=0
python3 tools/linkage_matrix.py  --project .               # 看「待补清单」是否已全部有理由
```

| 检查 | 通过标准 |
|---|---|
| `blueprint_lint` | ERROR 0；must 契约覆盖率 100% |
| `menu_walk --check` | 缺项 0；无环、无孤立节点、同级 order 不冲突 |
| `linkage_matrix` | 没有「一面都没有」的 must 功能；每个 only-1-面 的功能都有理由 |
| 禁用词 | `按原版 / TBD / 待定 / 视情况 / 同前` 0 命中 |

### 8.2 人工通读（机器查不出来的）

```
[ ] 契约里每个「会变」都写了「变成什么」——不是"刷新"而是"从 A 到 B"
[ ] 每个叶子都能回答「什么时候出现/能点/打钩」，且三条互不重复
[ ] 六面里不适用的面，写的是理由而不是省略
[ ] 每个 must 功能都有自己的契约文件，而不是塞进别人的契约里
[ ] 数据字典里每个字段都标了「原版观察」还是「推断」
[ ] 未知台账里 blocking=yes 的条数是 0
[ ] 随便挑一节读，一个没看过原版的人能照着做出来（不能 → 补）
[ ] 没有任何一条结论是我"觉得应该是这样"而没有证据的
```

### 8.3 交付前最后一问

> **如果 S6 的 Agent 只有这份蓝图、没有原版应用，他能做出行为一致的东西吗？**
> 不能 → 说明还有没写下的隐含知识 → 现在是补它的最后时机（S3 冻结后就贵了）。

## 9. 常见翻车（S2 专属）

| 症状 | 真因 | 修法 |
|---|---|---|
| 菜单层级对了，选项不对 | 只拍了展开的样子，没拍「该灰的时候」 | 每层拍两张：正常态 + 禁用态 |
| 三条件写成了同一句话 | 没有逐句自问（§3.1 的 12 个问题） | 用 `menu_walk --cards` 逐叶子过一遍 |
| 契约写得很长但没法实现 | 只写"是什么"，没写"谁在什么时候改哪个字段" | 补 §10 数据读取 + §11 数据写入 + §12 联动 |
| 写完发现两个契约互相矛盾 | 同一事实写了两处 | 一处权威（通常菜单在 `menus.csv`、行为在契约 §4/§5），另一处**引用 ID** |
| 联动了但没测 | 只写了 `LK` 行没写测试号 | `test_ref` 必填（lint 会判 `REF-LINK-NO-TEST`） |
| 冻结前一天还在改 | 没有「未决项=0」的闸 | 冻结前跑 `blueprint_lint` + 人工清单，未过不许发材料开会 |
| 把推断当实测 | 写的时候没标来源 | 每条断言带 `S-xx` / `M-xx` / 证据路径（SCHEMAS §0.9） |

## 11. 一个 30 秒判断「这份蓝图够不够细」的方法

随便抽一个功能，问这四句：
1. **谁看得到它？**（显示条件）
2. **为什么能点？**（可用条件）
3. **点了改哪张表哪个字段？**（§11 数据写入）
4. **别的页面怎么跟着变？**（§12 + 六面联动）

四句答不上任何一句 → 这个功能还没到能开发的程度。
这正是 00 §0.2 铁律 1 的原话：**细节不透不进开发。**
