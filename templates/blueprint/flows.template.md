## FL-01 修改任务日期

- 目标：把已有任务从 10 月 23 日（周五）改到 10 月 26 日（下周一），且不改变任务其他属性。
- 起点：S-01 主窗口，列表中已有任务「给张经理回电话」，当前 `dueDate = 2026-10-23 15:30`，`isAllDay = false`，无重复、无提醒。
- 路径：S-01 双击行 → S-02 详情 → 点"日期"行 → S-03 日期浮层 → 选"下周" → 点浮层外关闭 → 回到 S-02。
- 点击数：4。

### 正常路径

1. **双击列表行** → S-02 详情面板从右侧展开（宽度 380pt，带 120ms 横向滑入），列表行保持选中高亮；详情标题框自动获得键盘焦点但**不进入编辑态**（光标不插入，避免误改标题）。
2. **点击详情"日期"行** → S-03 日期浮层在日期行下方 4pt 处展开（宽 260pt），浮层内"今天"高亮（因为 `dueDate` 今天是 10-23），月历显示 2026 年 10 月，"26"未被选中。
3. **点击"下周"** → 浮层立即关闭（不等回执）；详情日期行文案从 `10月23日 周五 15:30` 变为 `10月26日 周一 15:30`，**时分保持 15:30 不变**；同一帧内列表行日期徽标同步更新，该行在同组内按新日期重新排序并移动位置。
4. **写入提交成功后**（约 40ms 后）→ 侧栏「今天」角标从 7 减为 6，侧栏「最近7天」角标不变；日历视图（若已打开在该周）中该条从 10-23 格移到 10-26 格；搜索"张经理"结果行的日期徽标变为 10月26日；提醒调度队列里该任务的下次提醒时刻被重算为 10-26 14:30（提前 1 小时）。
5. **点浮层外（或按 Esc）** → 焦点回到详情"日期"行；列表滚动位置保持不跳；再按 Esc 关闭详情，焦点回到第 1 步那一行（即使该行已因排序移动位置，焦点跟随行本身而不是跟随屏幕坐标）。

> 关键：第 3 步的 UI 变化（乐观更新）与第 4 步的联动刷新是两个不同时点。
> 详情与列表行是"写入发起即更新"，其余四面是"事务提交成功后刷新"。混成一个时点会导致写入失败时界面已显示新日期。

### 失败与取消

| 情形 | 用户看到 | 系统状态 | 可恢复动作 |
|---|---|---|---|
| 磁盘只读 / 写库失败 | 日期行文案**回滚**为 `10月23日 周五 15:30`，行尾出现红色感叹号，点击展开"保存失败：磁盘空间不足"，底部"重试"按钮 | 库内仍为 10-23；草稿保留在内存（值 = 2026-10-26 15:30） | 修复磁盘空间后点"重试"，用同一草稿提交；或点"放弃修改"显式丢弃 |
| 提交超时（结果未知） | 日期行显示新值但带灰色转圈，tooltip"正在确认保存结果" | 不确定是否已落库；禁止再次提交同一命令 | 轮询实体 revision 确认；确认已提交则转成功态，未提交则转失败态，不盲目重试 |
| 浮层展开时按 Esc | 只关闭 S-03，详情仍打开，日期未变 | 无写入（尚未选择任何项） | 重新点日期行 |
| 选了"下周"后立即按 Esc 关闭详情 | 详情关闭，列表行已是新日期（乐观更新），写入在后台继续 | 写入队列继续执行，不因 UI 关闭而取消 | 无（正常情况）；若写入失败，侧栏出现一条全局错误提示，点开可定位该任务 |
| 任务已被另一处删除（并发） | 详情自动关闭，列表行以 200ms 淡出移除，顶部提示"该任务已被删除" | 写入被拒，`NOT_FOUND_OR_DELETED` | 无（任务已不存在）；提供"撤销删除"入口若该删除仅是在本应用内发生 |
| 用户重复点击"下周" | 第二次点击不产生第二条命令（幂等：目标日期相同直接忽略） | 仅一次写入 | 无 |

### 边界

| 边界 | 期望行为 | 依据 |
|---|---|---|
| 跨月（10-31 → 11-01） | 按日历推进，不是 +24 小时；月历翻页显示 11 月，日期徽标显示 `11月1日 周日` | U-006 待验证，先按日历推进记录 |
| 跨年（12-31 → 01-01） | 同上，年份参与显示格式化 `2027年1月1日` | 同上 |
| 闰日（2028-02-29 设为"每年重复"） | 允许设置；非闰年该实例落在 02-28 并在行内标注"闰日顺延" | screens/S03-leapday-01.png |
| 时区变更（出差改系统时区 +8 → +1） | 定时任务按 `isFloating == false` 时保持绝对时刻（15:30+08:00 显示为 08:30+01:00）；`isFloating == true` 时保持墙钟时间 | U-015 待验证 |
| DST 切换（目标时刻落在不存在的 02:30） | 顺延到 03:30，并在详情显示一行小字说明 | 需补验（U-016） |
| 全天任务改日期 | 时间恒为 00:00，不显示时分；若原为定时 15:30，切全天时把 15:30 保留在草稿里，取消全天后可还原 | 契约 §5 互斥规则 |
| 目标日期等于当天已有任务 | 允许重复，不合并、不提示 | - |
| 该行处于当前筛选（如"今天"清单）之外的新日期 | 提交成功后该行从当前列表移出，移出动画 200ms，焦点落到下一行；若移出后列表为空则显示该清单空态 | U-002 待验证，`linkage.csv` LK-002 有对应用例 |
| 任务已完成（status != 0）时改日期 | 允许，但改完后任务仍为完成态，不自动复活 | - |
| 任务在回收站（deleted = 1） | 不显示日期入口（`visibility_cond` 为假） | menus.csv M-DATE |

### 恢复

| 场景 | 恢复路径 | 恢复什么 / 不恢复什么 |
|---|---|---|
| 误操作改错日期 | 改后 5 秒内在详情底部出现"已改为 10月26日 · 撤销"，点撤销回到 10-23 15:30，六面同步回退 | 恢复 `dueDate` 与 `isAllDay`；不恢复由此产生的提醒改期（提醒按新日期重算后再撤销会回到原时刻，此点由 LK-008 覆盖） |
| 保存失败 | 草稿保留，重试按钮可用；关闭详情再打开，详情显示的是**库里的旧值**，草稿作为"未保存的修改"提示条浮在详情形顶端 | 草稿只保留最近一次；连续多次编辑只保留最后一版 |
| 修改后立即 ⌘Q 退出 | 退出前冲刷：捕获该任务命令并入队，等待屏障确认；成功则退出，失败则弹"有 1 项修改未保存，重试/放弃并退出/取消退出" | 已提交的事务保证在重启后仍在；未提交的草稿不承诺恢复（不假装强杀恢复） |
| 修改后应用崩溃 | 重启后读库：若事务已提交则显示新日期，否则显示旧日期；两种情况都不出现"半写"状态（`dueDate` 与 `remindTime` 同事务） | - |
| 改日期同时把任务移到另一清单（两处并发） | 两个命令串行执行，各自带 `entityId` 与 `expectedRevision`；后执行者遇到版本冲突则提示"该任务已被修改，是否覆盖" | 不允许静默覆盖 |

## FL-03 设置每周工作日重复

- 目标：把「周一晨会纪要」设为每周一至周五重复，永不结束。
- 起点：S-02 详情，任务已有 `dueDate = 2026-10-26 09:00`。
- 路径：S-02 → 点日期行 → S-03 → 点"重复" → S-04 → 点"每周工作日" → 关闭。
- 点击数：7（双击行、点日期行、点重复行、点每周工作日、点结束条件、选"永不"、点浮层外）。

### 正常路径

1. 点"重复"行 → S-04 在 S-03 右侧展开（二级浮层），"每天"默认高亮。此时 S-03 **保持打开**不关闭。
2. 点"每周工作日" → 该行显示选中圆点，"每周"行**不显示选中**（互斥呈现）；下方"选择周几"摘要显示 `周一、周二、周三、周四、周五`。
3. S-04 底部出现"结束条件"行，回显"永不"。
4. 关闭浮层（Esc 两次：先关 S-04 回到 S-03，再关 S-03 回到 S-02）→ 详情"重复"行文案变为 `每个工作日`，日期行右侧出现重复图标 ↻。
5. 提交成功后 → 列表行出现 ↻ 图标；侧栏「今天」角标不变（本周剩余实例在未来的日期）；日历视图中未来 5 个工作日各出现一条；提醒调度按每个实例的 09:00 - 提前 1 小时 = 08:00 各注册一条；搜索该关键词返回 1 条（母任务，不展开实例）。
6. 库内 `repeatFlag = "RRULE:FREQ=WEEKLY;INTERVAL=1;BYDAY=MO,TU,WE,TH,FR"`，`repeatFirstDate = 2026-10-26`。

### 失败与取消

| 情形 | 用户看到 | 系统状态 | 可恢复动作 |
|---|---|---|---|
| 在"选择周几"里取消最后一天 | 该天勾选回弹为选中，行内提示"每周重复至少要选择一天" | 命令层拒绝写入，无库变更 | 改选其他组合 |
| 规则串生成失败（引擎异常） | S-04 关闭，重复行保持原值并短暂闪红；顶部提示"重复规则保存失败" | `repeatFlag` 未变 | 重试 |
| 选择"每周工作日"后又改回"每天" | 第二次选择覆盖第一次，`repeatFlag` 被完整替换（不是叠加） | 仅最后一次生效 | - |
| 退出冲刷阶段点击规则项 | 整层置灰不可点，tooltip"正在保存，稍候再试" | 无变更 | 保存完成后重试 |

### 边界

| 边界 | 期望行为 | 依据 |
|---|---|---|
| 基准日落在周六 | 允许设置；首个实例顺延到下周一（10-31 周六 → 11-02 周一） | 需补验 U-007 |
| 法定节假日 | "每周工作日"默认**不**跳过节假日；若用户要跳节假日，选"法定工作日"变体（`TT_SKIP=HOLIDAY,WEEKEND`） | 证据表明原版存在两个不同规则，区别待 U-004 |
| 结束条件"按次数"= 1 | 允许，等价于不重复；UI 提示"仅执行 1 次，建议关闭重复" | - |
| 结束条件"按日期"早于首个实例 | 拒绝写入，提示"结束日期不能早于开始日期" | - |
| 已完成实例被删除 | 不退还次数 | - |

### 恢复

- 改错规则：5 秒内"撤销"回到原 `repeatFlag`（无重复则回到空）。
- 规则改后已生成的未来实例：随规则变更重新展开，旧的未来实例被删除（已完成实例保留）。
- 退出后重启：`repeatFlag` 与 `repeatFirstDate` 同事务落库，两者必须同时存在，缺失一个视为数据损坏并在启动自检中报警（R14）。
