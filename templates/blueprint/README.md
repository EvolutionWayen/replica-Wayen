## 0. 这个目录装的是什么

S1（取证）到 S3（冻结）三个阶段要产出的全部文件模板。**它们共同回答一个问题：这个功能到底怎么运作。**

| 文件 | 阶段 | 对应真实路径 | 回答什么 | 行数级别 |
|---|---|---|---|---|
| `recon.template.md` | S1 | `BLUEPRINT/recon.md` | 这个应用是什么形状（屏幕/入口/流程/模块/未知） | 10 段，≥120 行 |
| `features.template.csv` | S1 | `BLUEPRINT/features.csv` | 用户能做哪些事，哪些在本版范围 | 11 列，每功能一行 |
| `screens.template.csv` | S1 | `BLUEPRINT/screens.csv` | 有哪些屏，怎么进出，五态齐不齐 | 14 列，每屏一行 |
| `menus.template.csv` | S2 | `BLUEPRINT/menus.csv` | 菜单树长什么样，每个选项何时可见/可用/选中 | 15 列，每节点一行 |
| `flows.template.md` | S2 | `BLUEPRINT/flows.md` | 用户跨屏走一条路时发生了什么 | 每流程 4 子节 |
| `contract.template.md` | S2 | `BLUEPRINT/contracts/C-F-xxx.md` | 单个功能的完整行为契约 | 16 节，一功能一文件 |
| `linkage.template.csv` | S2 | `BLUEPRINT/linkage.csv` | 改了 A 之后，另外五个地方怎么跟着变 | 10 列，每条联动一行 |
| `state-machines.template.md` | S2 | `BLUEPRINT/state-machines.md` | 哪些对象会"卡住"，状态怎么合法转换 | 每机 3 表 |
| `data-dictionary.template.md` | S1 起草 / S4 定型 | `BLUEPRINT/data-dictionary.md` | 字段的语义、默认、空值与时区口径 | 每实体 1 表，9 列 |
| `unknowns.template.csv` | S1/S2 | `BLUEPRINT/unknowns.csv` | 还不知道什么、怎么补验、是否阻断 | 9 列，每条未知一行 |
| `BLUEPRINT-LOCK.template.md` | S3 | `BLUEPRINT/BLUEPRINT-LOCK.md` | 谁在什么时候确认了哪一版，哈希可复算 | 4 节 |
| `SCHEMAS.md` | — | （只读，不进项目） | **机器契约**：列名/节名/枚举的唯一定义 | 改动须走变更单 |

> `SCHEMAS.md` 是唯一格式权威。模板照它写，门禁照它校验，工具照它计算。
> 模板与 SCHEMAS 冲突时，以 SCHEMAS 为准，并且要报一个 bug（说明模板写错了）。

## 1. 填写顺序（照这个顺序填，别跳）

<!-- 指引：顺序不是排版偏好，是依赖关系。前一步的输出是后一步的输入，跳步会导致返工。 -->

| 步 | 填什么 | 为什么必须在这一步 | 完成后能回答 |
|---|---|---|---|
| 1 | `features.csv` | 先把"要做哪些事"钉死，后面所有文件都挂在这张表上 | 本版做 N 件事，must 是哪些 |
| 2 | `screens.csv` | 每件事发生在哪一屏；五态是否都见过 | 有几屏，哪屏的空态还没录 |
| 3 | `menus.csv` | 屏幕里最复杂的部分：多层菜单与三条件 | 每个叶子可见/可用/选中各是什么 |
| 4 | `contracts/C-F-xxx.md` × N | 一功能一契约，把行为写到可实现的粒度 | 这个功能点了之后到底发生什么 |
| 5 | `flows.md` | 把多个契约串成用户的真实路径 | 用户从哪到哪，点几下，失败怎么办 |
| 6 | `linkage.csv` | 跨页面影响矩阵，六面逐个填 | 改了 A，B/C/D/E/F 各自何时变 |
| 7 | `state-machines.md` | 把"会卡住的对象"的状态抽出来 | 保存中能不能点第二次，失败怎么恢复 |
| 8 | `data-dictionary.md` | 字段级口径（日期/时区/空值） | 落库存什么，跨时区怎么算 |
| 9 | `unknowns.csv` | 把前面每一步里"我还不确定"的收拢成台账 | 还剩几个阻断项，谁去补 |
| 10 | `BLUEPRINT-LOCK.md` | 跑完 G1/G2 → 算哈希 → 签确认 | 这一版被谁在何时确认 |

**并行与串行的硬约束**：

- 1→2→3 必须串行（屏幕来自功能，菜单来自屏幕）。
- 4 可以在 3 完成后**并行**写多个契约（不同功能互不依赖）。
- 5/6 必须在相关契约写完之后（否则流程和联动都是猜的）。
- 7/8 贯穿全程：写契约时发现状态或字段不清，立刻回补 7/8，不要堆到最后。
- 9 每填完一个文件就更新一次，不要最后一天集中补。
- 10 只能在 G1 G2 都 PASS 之后。

## 2. 每一步的质检要点

<!-- 指引：每步给"最容易漏的 3 件事"+"一条自检命令"。自检命令跑不出结果就是没做。 -->

### 步 1 · features.csv

| 质检点 | 判定标准 |
|---|---|
| 每个功能是"动词开头的一件事" | 出现"管理""优化""支持"这类词 → 不合格，拆开 |
| `priority` 有 must 但 `contract_ref` 为空 | 不合格，must 功能必须有契约文件 |
| `scope=out` 或 `progress=skip` 没写理由 | 不合格，`notes` 必须写理由 |
| `original=no` 的行 | 那是你自己加的功能，必须在 DECISIONS 有记录 |

自检：`python3 tools/blueprint_lint.py --only features`

### 步 2 · screens.csv

| 质检点 | 判定标准 |
|---|---|
| 五态列 | `state_filled/empty/loading/error` 必须是 `yes`；`state_permission` 可为 `-` 但要在 notes 说明 |
| `entry` / `exits` | 必须能指到具体控件（"双击列表行"而非"点进去"） |
| `focus_restore` | 必须写"返回到哪一行"而不是"恢复焦点" |
| `flows` 列 | 经过该屏的 FL-id 要齐，flows.md 里引用的屏幕也要在这里存在（双向闭合） |

自检：`python3 tools/blueprint_lint.py --only screens`

### 步 3 · menus.csv

| 质检点 | 判定标准 |
|---|---|
| 三列内容是否真的不同 | 抽 3 个节点对比：`visibility_cond` 恒真的、`enabled_cond` 依赖数据的、`checked_cond` 依赖持久值的，三者必须明显不同 |
| 禁用词 | 出现「视情况」「按原版」「同前」「-」→ FAIL（`-` 只允许在 `shortcut`/`notes` 之外的列用于 label/separator 类型） |
| 父子闭合 | 每个 `parent_id` 除 `ROOT` 外都必须是已存在的 `node_id` |
| 叶子完整 | `type != separator|label` 的节点必须有 `command` 与 `contract_ref` |
| 隐藏后焦点 | 至少有一个节点明确写了"隐藏后焦点落到哪" |
| 破坏性动作 | 「清除日期」「永久删除」这类必须有 notes 说明确认与撤销 |

自检：`python3 tools/menu_walk.py --check`

### 步 4 · contract（一功能一文件）

| 质检点 | 判定标准 |
|---|---|
| 16 节标题 | 与 SCHEMAS §8 逐字一致（含序号与空格），脚本核不要眼看 |
| 每节非空 | 空节必须 `N/A：` + 理由 |
| 禁用词 | TODO / 待定 / 按原版 / 视情况 / 详见代码 → FAIL |
| §5 三条件 | 必须出现"可见但禁用"与"可用但未选中"两个具体例子 |
| §8 | 必须有具体数字与文案原文，能被第三方复算 |
| §12 | 六面齐全，每面有 LK-id 与 T-id |
| §16 | 五类用例齐全，断言是具体值，T-id 与 linkage 对得上 |

自检：`python3 tools/blueprint_lint.py --only contracts`

### 步 5 · flows.md

| 质检点 | 判定标准 |
|---|---|
| 四子节 | `### 正常路径` `### 失败与取消` `### 边界` `### 恢复` 缺一不可 |
| 每步有可见结果 | 写"系统处理"→ 不合格；要写"屏幕哪里出现了什么文字" |
| 点击数 | 是数出来的，不是估的 |
| 失败表 | 至少有 3 行，必须含"保存失败"与"任务已被删除"这类真实场景 |
| 边界表 | 至少含跨月/闰日/时区/全天切换四个中的三个 |

### 步 6 · linkage.csv

| 质检点 | 判定标准 |
|---|---|
| 六面覆盖 | 每面至少一条；不适用的面要写一行说明"为何不适用"，不许省略 |
| `affected_control` | 必须具体到控件与文字，出现"界面刷新""同步更新"→ FAIL |
| `refresh_timing` | 必须落在四类里：写入发起即 / 事务提交后 / 下次进入时 / 定时 |
| `state_handling` | 必须写"保留什么 / 清空什么 / 焦点去哪" |
| `test_ref` | 每个 LK 都有 T-id，且该 T 在 test-plan 里存在 |

自检：`python3 tools/linkage_matrix.py --check`

### 步 7 · state-machines.md

| 质检点 | 判定标准 |
|---|---|
| 三表齐全 | 状态 / 转换 / 非法转换，缺一不可 |
| 非法转换表 | 至少 3 行，否则说明你只想了正常路径 |
| 状态判据 | 指向真实字段（`E01.status == 0`）而不是"界面看起来" |
| 无重复定义 | 两个状态机不许描述同一件事 |

### 步 8 · data-dictionary.md

| 质检点 | 判定标准 |
|---|---|
| 来源分级 | 每字段标 `原版观察`/`推断`/`猜测`；`猜测` 的必须同时出现在 unknowns.csv |
| 日期三问 | 每个日期/时刻字段都要回答：本地日期还是 UTC 时刻、有无时区字段、全天怎么表达 |
| 空值语义 | `null`（没设）与 `0`（设成零值）必须区分 |
| 默认值来源 | 谁写的默认（UI 层/库层），不许空 |

### 步 9 · unknowns.csv

| 质检点 | 判定标准 |
|---|---|
| `verification_action` | 必须是可执行动作（"用 sqlite3 导出 X 字段，重复 3 次"），不是"再研究一下" |
| `blocking` | `yes` 的必须在 G3 前清零（resolved 或经批准 out-of-scope） |
| 与 recon §8 对应 | 编号一一对应，不许只在一边出现 |

### 步 10 · BLUEPRINT-LOCK.md

| 质检点 | 判定标准 |
|---|---|
| 前置 | G1 与 G2 都是 PASS（BLOCKED 不算） |
| 哈希 | 逐文件实算，且记录"实算与填写一致" |
| 覆盖率 | 契约文件数 == features.csv 中 must 功能数 |
| 确认要点 | 每一条都写出具体 ID，不许只打勾 |
| 阻断未知 | 必须为 0 |

自检：`python3 tools/blueprint_lint.py --all && python3 gates/run.py --stage G3 --project .`

## 3. 十条最常见的糊弄写法（出现即打回）

<!-- 指引：这一节是本目录最该被反复读的部分。
     每条给：糊弄原文 → 为什么它是糊弄 → 合格写法长什么样。
     审查时拿着这张表逐条比对，比通读十份文档更快。 -->

### 01 「界面刷新」「同步更新」

- **糊弄原文**：`具体效果：选择新日期后，界面刷新，日期显示更新，角标同步变化。`
- **为什么是糊弄**：用户看不见"刷新"这个动作，只看得到"哪一行文字的哪几个字变成了什么"。这句话无法验收，也无法写测试断言。
- **合格写法**：`主列表行日期徽标由 '10月23日' 变 '10月26日'；侧栏'今天'角标 7 → 6（提交成功后 40ms）；该行从第 3 位移到第 6 位，位移 180ms ease-out。`

### 02 「按原版」「和原版一样」

- **糊弄原文**：`显示条件：按原版逻辑。`
- **为什么是糊弄**：把理解工作退回给读者。原版是什么逻辑？三个月后你自己也不记得。而且这条会被 G2 的禁用词检查直接打回。
- **合格写法**：`仅当 dueDate != null 时可见；无日期时整行隐藏不占位，下方'重复/提醒/清除日期'上移，行间距仍 6pt。证据：screens/S03-date-menu-01.png。`

### 03 三条件混成一句「视情况」

- **糊弄原文**：`可用与选择条件：菜单项根据当前状态决定是否可用或选中。`
- **为什么是糊弄**：这是失效模式 #02 的原形。三条件糊在一起，实现时必然一个 `if` 炖完，上线后就是"该灰的不灰、该选的没选"。
- **合格写法**：`可见：恒真；可用：dueDate != null && writePhase == IDLE（无日期时禁用但占位，tooltip '请先设置日期'）；选中：remindTime != null && EXISTS(task_reminder)。禁用时仍保留圆点，只变背景色。`

### 04 断言写「保存成功」「数据正确」

- **糊弄原文**：`T-101：修改日期后检查数据已保存，界面显示正确。`
- **为什么是糊弄**：任何人都能声称它通过。没有具体值就没有失败的可能，测试等于没写。
- **合格写法**：`T-101：due_at == '2026-10-26T07:30:00Z'；is_all_day == 0；revision == 原值+1；列表第 6 行徽标文本 == '10月26日'；证据 = 落库快照 + 截图（截图只证明徽标）。`

### 05 「调用重复引擎生成实例」

- **糊弄原文**：`业务逻辑：若设置了重复则调用重复引擎生成实例并更新提醒。`
- **为什么是糊弄**："调用某服务"不是规格。输入是什么、输出是什么、边界在哪、失败返回什么，全缺，实现者只能自由发挥。
- **合格写法**：`输入 (repeatFlag, repeatFirstDate, 窗口 60 天) → 输出有序日期集；展开顺序：解析 RRULE → 应用 TT_SKIP → 应用 exDates 排除 → 截断到窗口；BYDAY 比较前先排序去重（原版顺序为 WE,MO,TU,TH,FR，顺序无语义）；无值返回 [repeatFirstDate]；非法 RRULE 返回 [] 并记脱敏日志。`

### 06 「已处理并发」「保证不丢」

- **糊弄原文**：`并发与生命周期：已处理快速点击和退出场景，保证数据不丢。`
- **为什么是糊弄**："已处理"不是规格，"保证不丢"无法测。这类句子在评审会上唯一的作用是让人以为想过了。
- **合格写法**：`100ms 内连点 5 次不同日期 → 5 条命令串行入队，每次用最新已提交 revision；最终值为第 5 次；撤销栈只留 1 个点（T-201）。关窗有 DIRTY → 冻结输入 → 建屏障 N → await committedSeq >= N → 成功才关；失败弹三选（T-205）。`

### 07 「交互流畅、响应迅速、符合设计规范」

- **糊弄原文**：`体验标准：操作流畅，界面美观，响应速度快。`
- **为什么是糊弄**：四个形容词，一条都测不了，直接命中 R11「不能写成数值或步骤的体验要求 = 无效要求」。
- **合格写法**：`性能口径：起点 = Cmd.SetDueDate 点击事件进入；终点 = 列表徽标新文案完成布局（rAF 后一帧）；环境 = M1 MBA / macOS 15 / 生产构建 / 冷缓存；目标 p50 ≤ 50ms、p95 ≤ 120ms。`

### 08 「细节待定」「后续补充」「TODO」

- **糊弄原文**：`数据写入：具体字段待定，后续补充。`
- **为什么是糊弄**：冻结蓝图里不许有占位（体系总纲 附录 A 第 7 条）。未定的事项必须进 unknowns.csv 并标 `blocking=yes`，让它变成有人负责的待办，而不是一句免责声明。
- **合格写法**：`见 U-001（清除日期是否连带清空 remindTime/repeatFlag）。本条在 U-001 resolved 前不得开工；补验动作：在副本库执行清除后导出 four 字段 + task_reminder 行数。`

### 09 只列六面中的三面

- **糊弄原文**：`跨页面联动：修改日期后，主列表、日历、提醒等相关界面会同步更新。`
- **为什么是糊弄**：这正是失效模式 #01「功能清单齐、做出来内部不联动」。六面只提 3 面，漏掉的角标、详情、搜索就是上线后要返工的地方（R18）。
- **合格写法**：六面逐个列表格，每面写：受影响控件（具体到文字）| 数据 | 刷新时点（四选一）| 状态保留/清空 | LK-id | T-id。不适用的面也要写一行说明理由。

### 10 「证据见截图文件夹」

- **糊弄原文**：`证据：截图在 screens/ 目录下。`
- **为什么是糊弄**：没有文件名、没有采集方式、没有时间，无法核对、无法判断对应哪个版本，也无法被别人重做一遍。
- **合格写法**：`screens/S03-date-menu-01.png | 截图 | screencapture -x -l <windowID> 抓主窗口详情日期行展开态 | 2026-10-23T09:12+08:00 | 对应 §2 §3。`

## 4. 自检脚本（提交评审前跑这一组）

```bash
cd <项目根>

# 1. 蓝图结构自检（列名/ID/跨文件引用/菜单树闭合/16 节）
python3 tools/blueprint_lint.py --all

# 2. 菜单三条件与叶子完整性
python3 tools/menu_walk.py --check

# 3. 联动矩阵（找没 wire 的面）
python3 tools/linkage_matrix.py --check

# 4. 取证的不可变性（证据只加不改）
python3 tools/evidence_manifest.py --verify

# 5. 门禁 G1 / G2
python3 gates/run.py --stage G1 --project .
python3 gates/run.py --stage G2 --project .

# 6. 冻结前最后一步：G3
python3 gates/run.py --stage G3 --project .
```

全部 `PASS` 且退出码 `0` 才允许签 `BLUEPRINT-LOCK.md`。
出现 `BLOCKED` 不算通过（缺依赖就解决依赖，不许写"应该没问题"）。

## 6. 本目录的维护约定

- `SCHEMAS.md` 是机器契约，**改它等于改门禁**，必须走变更单并通知所有人。
- 模板里的示例是**示例**，不是规范。示例用的 目标应用字段名（`dueDate` / `repeatFlag`）换成你的目标应用时要整体替换，但**结构不许动**。
- 发现模板与 SCHEMAS 冲突 → 报 bug，以 SCHEMAS 为准。
- 每个模板的第 3 行固定为 `> 复制为 <目标路径>。填不出来就说明还没想清楚。`，不许删改——这是给使用者的一句话提醒。
