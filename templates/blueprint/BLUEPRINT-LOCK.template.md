<!-- 指引：本文件不是仪式，是**证据**。它的唯一作用：证明"某人在某个时刻，确认了某一批具体内容"，
     并且事后任何人都能实算哈希验证"蓝图有没有被偷偷改过"。
     
     填法与顺序：
     1. 先跑 G1、G2 拿到 PASS（不许先冻结再跑门）
     2. 用 `shasum -a 256 <文件>` 逐文件算哈希填进第二节（必须先跑一次 tools/blueprint_lint.py）
     3. 逐条勾"确认要点"——每一条都要写出**你确认了哪些 ID**，不许只打勾
     4. 签上确认人与时间（ISO 8601 带时区）
     5. 冻结后再改任何蓝图文件 → G3 会 FAIL。改动走 CHANGES/C-xxx.md 变更单
     
     三个最容易造假的点（门禁会打回）：
     ① 哈希手填而不是实算 → G3 比对失败

     ③ blocking=yes 的 unknown 还开着就冻结 → 直接 FAIL
     
     不合格的写法：「已确认，可以开工。」「核心功能已审阅通过。」——这类句子既无 ID 也无时间，等于没签。 -->

## 确认要点

<!-- 指引：每一条都要写"我确认了哪些具体 ID"，因为"确认过了"这句话三个月后无法复核。
     下面每条的括号里写的是**必须填什么**，不是可选项。 -->

- [ ] **核心行为理解无误**（列出你逐条确认的 must 功能 ID，至少覆盖核心闭环：
      改日期 F-xxx、重复 F-xxx、快速捕获 F-xxx、搜索 F-xxx、提醒 F-xxx）
- [ ] **三条件已分离**（列出你亲自核对过三条件互不相同的菜单节点，至少 3 个，且必须包含
      一个"可见但禁用"、一个"可用但未选中"、一个"隐藏后焦点回退"的节点 ID）
- [ ] **六面联动已覆盖**（列出你确认过的联动条目 ID，六面每面至少一条：
      主列表 LK-xxx / 角标 LK-xxx / 详情 LK-xxx / 日历 LK-xxx / 搜索 LK-xxx / 提醒 LK-xxx）
- [ ] **数据字段口径已明确**（列出你确认过的、有争议的字段：
      `E01.dueDate` 的本地日期 vs UTC 时刻、`E01.isAllDay` 的三态、`E01.isFloating` 与 `E01.timeZone` 的组合，
      以及你确认的结论各一句）
- [ ] **保留/改进项已记录**（列出 DECISIONS.md 中的 D-xxx，说明哪些行为是"照原版"、哪些是"我有意改"）
- [ ] **阻断级未知为 0**（列出 unknowns.csv 里原先是 blocking=yes 但现已 resolved 的 U-xxx 及补验证据路径）
- [ ] **体验取舍已拍板**（列出 §15 里你亲自改过的数值：步数上限、性能目标、动效时长等）
- [ ] **范围外项已明确**（列出 features.csv 中 scope=out / progress=skip 的 ID 及理由所在行）

## 冻结后的变更规则

<!-- 指引：把规则抄在这里，是为了让下一个 Agent 不用去翻总纲。
     这段不需要你改写，但要确认它与你项目的实际做法一致。 -->

| 情形 | 允许的动作 | 禁止的动作 |
|---|---|---|
| 发现新细节 | 写 `BLUEPRINT/CHANGES/C-xxx.md`（改什么/为什么/证据），定位影响面，产品官确认，版本 +1，更新本文件哈希 | 直接改蓝图文件 |
| 实现时发现契约有问题 | 停下 → 提变更单 → 等产品官决定 | 边写代码边改契约 |
| 门禁因蓝图问题 FAIL | 修蓝图 → 重跑门 → 更新哈希 → 版本 +1 | 改门禁规则让它变绿 |
| 测试断言过不了 | 判断是契约错还是实现错；契约错走变更单 | 改测试断言让它通过 |
