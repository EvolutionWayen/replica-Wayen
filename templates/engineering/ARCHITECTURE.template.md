## 4. 数据流

### 4.1 写路径（从点击到落盘）

```
用户动作
  → 校验/权限/输入法状态
  → 不可变命令 {operationId, entityId, patch, baseRevision}
  → UI 显示未保存草稿（不得声称已保存）
  → 应用用例 / 串行写链（按明确的一致性域）
  → 事务校验 + 定向更新 + revision 递增
  → 持久化成功 / 结构化失败结果
  → UI 线程提交结果 + 受影响面刷新
```

必须写清的东西：命令里**捕获哪个 ID**（不许读「当前选中」）、**事务边界多大**、**完成信号是什么**、**失败返回有哪几种类型**。

### 4.2 读路径（防旧结果覆盖新选择）

```
导航/筛选/搜索 → queryId + generation
  → 权限与一致性范围
  → 查询下推存储（筛选/排序/分页）
  → 结果带版本 → UI 核对仍是当前 generation
  → 增量渲染，保留焦点/选中/滚动
```

必须写清：**过期结果怎么丢弃**（generation 比对）、**计数口径**（全量 COUNT 还是已加载页数）、**分页策略**（游标还是 offset）。

### 4.3 生命周期（退出不是唯一兜底）

```
请求退出 → 停止新编辑、捕获当前草稿
  → 冲刷防抖（捕获目标与值）→ 入队屏障
  → 等待 ≤屏障 的操作有明确结果
  → 成功：释放资源后退出
  → 失败/超时：保留或导出草稿，提供重试/取消
  → 只有明确接受放弃变更才允许未保存退出
```

必须写清：**冲刷返回的结构化结果长什么样**（`{status, pending, failed, errors}`）、**强杀时能保证什么**（已提交的写在 WAL 下仍在）、**不能保证什么**（正在进行的写）。
