## 五类类型的最低覆盖（每流程）

| 类型 | 最低条数 | 内容要求 |
|---|---|---|
| 正常 | ≥1 | happy path，断言最终状态的具体值 |
| 负向 | ≥1 | 非法输入 / 无权限 / 失败；断言不崩溃且有可读提示 |
| 边缘 | ≥1 | 跨月 / 闰日 / 时区变更 / 空值 / 极长文本 / 0 条与 1 万条 |
| 跨页面 | ≥1 | 六面联动（来自 `linkage.csv` 的 `test_ref`） |
| 生命周期 | ≥1 | 写 → 立即退出 → 重启 → 断言值还在 |

## 三类必测硬用例（先写这三个）

### 1 无等待即时关闭（R1/R3）

```text
改一个字段 → 不 sleep、不等 → 立即关闭/强杀 → 重开 → 断言具体值
```

反例：`save(); await sleep(200); assert(saved)` —— 恰好等到写入成功，把竞态伪装成绿灯。

### 2 改 A 不动 B（失效模式 05 / 单列更新）

```text
设 title/notes/priority/dueDate → 只改 title → 断言 notes/priority/dueDate 全未变
```

### 3 零调用点（失效模式 08 变体）

```text
设 1 分钟后提醒 → 等真实时间 → 断言弹窗真的出现（不许直接调内部 tick）
```

## 故障注入用例（至少四类）

| 故障 | 怎么造 | 期望 | 断言 |
|---|---|---|---|
| 磁盘只读 | `chmod -w <数据目录>` | 显示结构化失败；草稿保留 | 输入框内容未变；文案含「保存失败」 |
| 磁盘满 | 小容量 tmpfs / 占满 | 同上且不崩溃 | 进程存活；有脱敏日志 |
| 数据库损坏 | 往 db 中间写垃圾字节 | 启动不崩溃、提示明确、可从备份恢复 | 有错误提示；恢复后可读 |
| 进程强杀 | 写入后 `kill -9` | 已提交的写在重开后仍在 | 重开读到写入值（WAL 保障） |

## 执行与结果

```bash
# 全量连跑三次（R5），结果落文件供 G6/G8 读取
for i in 1 2 3; do
  <测试命令> --json-report --json-report-file=TEST/results/$(date +%Y%m%d)-run$i.json
done
```

结果文件结构（SCHEMAS §14）：

```json
{"run": "2026-10-23T11:00+08:00", "suite": "e2e", "commit": "<基线 commit>",
 "total": 42, "passed": 42, "failed": 0, "timeout": 0,
 "cases": [{"id": "T-101", "status": "pass", "duration_ms": 812}]}
```

判据：三次 `failed=0` 且 `total` 相同（用例数漂移说明有条件跳过）。

## 不许出现的写法

| 不许 | 因为 |
|---|---|
| `sleep` / `Thread.Sleep` / `Task.Delay` 等异步完成（R1） | 把竞态伪装成绿灯 |
| `:memory:` 内存库测持久化（R4） | 测不出「关 App 重开」 |
| `assert task is not None` 这类「非空」断言（R4） | 查不出值错 |
| 只跑单个文件就宣称全绿（R5） | 静态单例跨测试串库会造成单文件假绿 |
| 改断言让它通过（R7 变体） | 等于删掉验收标准 |
| 期望列写「成功」「正常」「刷新」「正确」单独成句 | 不可验收（R11） |
