# WP-xxx · 工作包

> 复制为 `BUILD/WORK-PACKAGES/WP-00x.md`。一个工作包 = **一个能单独运行、能单独验收的最小交付单元**。
> 七项缺一不许开工；`允许改的路径` 与其他 WP 重叠即违规（写作用域隔离）。

## 1. 目标

一句话，可判定。反例：「完善详情面板」。正例：「在详情面板能改日期并落库，改完主列表与三个角标同步，六面过联动门」。

## 2. 允许改的路径

| 类型 | 路径 | 说明 |
|---|---|---|
| 可改 | `src/<具体文件或目录>` | |
| 只读 | `BLUEPRINT/contracts/C-F-xxx.md` | 契约冻结，改要变更单 |
| 禁止碰 | `SPEC/`、`evidence/`、`screens/` | 他人 owner 或只加不改 |

**越界即违规（R16）**：`git diff --stat` 的改动文件必须全部落在「可改」路径内。

## 3. 依赖

| 依赖 | 类型 | 状态 | 不满足时的处置 |
|---|---|---|---|
| `C-F-xxx` 契约 | 蓝图 | `APPROVED`？ | 未 APPROVED 不许开工 |
| 数据接口签名 | 架构 | 稳定？ | 未稳定先落假实现 |
| `WP-00y` | 工作包 | 完成？ | 未完成不许并行（或写清可并行的理由） |
| 表结构 | 架构 | 已建？ | 未建先跑竖切 |

## 4. 验收标准

每条含量化指标，**能被脚本或人一眼判定**。

| # | 标准 | 判定方式（命令/操作） | 期望 |
|---|---|---|---|
| 1 | 功能可用 | 点日期块 → 选「明天」 | 列表行显示「明天」 |
| 2 | 六面联动 | 逐面点一遍 | 6/6 面 `verified` |
| 3 | 数据落库 | 强杀后重开查库 | `dueDate` == 新值 |
| 4 | 无回归 | 跑受影响 `T-` | 全 pass |
| 5 | 构建干净 | 构建命令 | 0 错误 0 警告 |

## 6. 交付证据

| 证据 | 路径 | 判据 |
|---|---|---|
| 测试结果 | `TEST/results/<日期>-run<N>.json` | 对应用例 `pass` |
| 联动状态 | `BLUEPRINT/linkage.csv` | 该功能六面 `verified` |
| 截图 | `clone-screens/<S-id>-<主题>.png` | 与 `screens/` 同尺寸 |
| 构建日志 | 构建输出 | 0 错误 0 警告 |
| 落库查询 | 命令 + 输出 | 断言具体值 |

## 7. 禁止项

| 禁止 | 为什么 |
|---|---|
| 改契约来让代码合规 | 契约不可暗改；有问题走 `CHANGES/` 变更单 |
| 改测试断言让它通过 | 等于删掉验收标准 |
| 触碰其他 WP 的文件 | 写作用域冲突，改动会互相覆盖 |
| 顺手优化邻近代码 | 改动扩散（R16） |
| 用 `sleep` 等异步 | R1 |
| 把还原代码编进产品 | R9 |
| 提交时 `git add -A` | 并发期会把别人文件扫进你的提交 |

## 汇报格式（缺项视为未完成）

```
状态：完成 / 部分完成 / 阻塞
产出：<路径清单>
证据：<命令 + 关键输出> / <文件:行 + 基线 commit>
我跑过的验证：<测试名 + 结果 + 次数>
存疑：<不确定的点>
影响面：<改了哪些别的东西>
```

「已完成」「测试都过了」不是汇报。
