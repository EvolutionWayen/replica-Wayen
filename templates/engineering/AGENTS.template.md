## 3. 分层与职责（不许越界）

| 层 | 能做 | 不能做 |
|---|---|---|
| View | 渲染、事件转发、弹窗 | 写业务逻辑、写 SQL、持有可变业务状态 |
| ViewModel | 状态、命令、串行写链、暴露完成信号 | 直接 new 数据库连接、处理窗口生命周期 |
| Service | 业务规则、算法、解析（可注入时钟） | 弹窗、依赖 UI 框架、依赖真实时间流逝 |
| Repository/Data | SQL 下推、单列更新、索引、事务 | UI 概念、业务默认值、异步写不返回完成信号 |

依赖方向：`View → ViewModel → Service/Data → Model`。反向依赖禁止。

## 4. 红线（详见 `REDLINES.md`，此处只列必守）

1. 禁止用固定延时等待异步完成（R1）
2. 持久化写进串行链并暴露可 await 的完成信号（R2）
3. 关窗/退出前必须冲刷，且返回**结构化结果**（R3）
4. 持久化测试用真文件，断言查具体值（R4）
5. 全量测试连跑 ≥3 次；构建 0 错误 0 警告（R5/R6）
6. 不许注释报错、不许空壳实现、不许把还原代码编进产品（R7/R8/R9）
7. 只改必须改的；指出一处要全量扫同类（R16）
8. 页面完成 ≠ 功能完成：六面联动要有刷新时点与测试（R18）
9. 不得 `A || B` 式放行；BLOCKED 不得当 PASS（R19/R20）

## 5. 写作用域与派工

- **一个文件一个 owner**；每张任务卡写死「允许改的路径」。
- 公共契约文件（`SPEC/`、`BLUEPRINT/` 冻结后）只有一个 owner 能改。
- 并发工作期**禁止 `git add -A` / `git commit`**；必须提交时用显式路径 `git add <具体文件>`。
- 依赖显式化：`blocked_by` 标清，不让下游基于旧版开工。
- 不做超范围优化：只改必须改的；发现同类问题先报告，批准后统一扫。

## 6. 数据库与取证安全（A 档硬约束）

- **默认操作副本**：`cp "<真实库>" /tmp/work.db`，真实库只读（失效模式 07）。
- WAL 未合并时主库读不到最新值：先 `PRAGMA wal_checkpoint(TRUNCATE)` 再拷。
- 反编译/还原代码**只当规格书读**，不编入产品（R9）。
- 任何「原版是这样的」断言，必须指到 `S-xx` / `M-xx` / 证据文件路径（R15）。
- 改二进制前先备份到 bundle 外；改完验 `codesign -v`（失效模式 09）。

## 7. 汇报格式（缺项视为未完成）

```
状态：完成 / 部分完成 / 阻塞
产出：<路径清单>
证据：<命令 + 关键输出> / <文件:行 + 基线 commit>
我跑过的验证：<测试名 + 结果 + 次数>
存疑：<不确定的点，明确列出>
影响面：<改了哪些别的东西>
```

「已完成」「测试都过了」**不是**汇报。

## 8. 验收纪律

- 开发者自测 ≠ 验收；必须独立复现（A 档单人串行时标「自复验（独立性未满足）」）。
- 门禁不过不许进下一阶段；BLOCKED 不是通过。
- 体验要求必须写成数值或检查步骤（R11），形容词一律退回重写。
- 自动化覆盖不到的必须列入「人工确认项」，不许假装覆盖。

## 9. 我的偏好（写给 AI）

- 结论先行，不铺垫；发现问题直接说并给改法。
- 表格优先，不堆 emoji，不注水。
- 文档要能直接执行：动作 + 判据 + 命令，缺一不可。
- 数字与结论必须可溯源：带命令、带口径、带时间。
- 发现更好的做法直接提，不等我问。

## 10. 记忆维护

- 新的偏好/纠正/决策：当天更新本文件或 `DECISIONS.md`。
- 踩坑：写进 `docs/dev/` 并标「当前是否已修 + 时间」（R17），再提炼成红线。
- 现状变化只写 `STATE.md`，正文文档不写「已修复/已完成」。
