## 2 怎么启动

```bash
# 方式一：脚本（推荐）
./scripts/start.sh

# 方式二：直接指定数据目录
DATA_DIR="$HOME/Library/Application Support/<产品名>" ./bin/<可执行文件> --data-dir "$DATA_DIR"
```

| 项 | 值 |
|---|---|
| 首次启动会做什么 | （建目录 / 建表 / 写入默认清单） |
| 怎么确认启动成功 | （窗口出现 / 日志最后一行 / 退出码 0） |
| 常见启动失败 | （见第 7 节） |

## 3 怎么备份

```bash
./scripts/backup.sh
# → 备份到 ~/Backups/<产品名>/<时间戳>/
```

| 项 | 值 |
|---|---|
| 备份什么 | `app.db` + `app.db-wal` + `app.db-shm` **三件一起**，或先 `PRAGMA wal_checkpoint(TRUNCATE)` |
| 多久备一次 | 每周日 + 每次大改数据前 |
| 备份到哪 | |
| **最坏会丢多少** | 距上次备份之间的所有改动 |

验证备份可用（每月一次）：

```bash
ls -la ~/Backups/<产品名>/<时间戳>/                     # checkpoint 后仅 app.db 也算完整
sqlite3 ~/Backups/<产品名>/<时间戳>/app.db "SELECT COUNT(*) FROM <主表>;"
```

> 只拷 `.db` 不拷 `-wal` 会丢最近写入——这是最常见的备份失效原因。

## 4 怎么恢复

```bash
./scripts/restore.sh ~/Backups/<产品名>/<时间戳>
# 脚本会先自动备份当前数据（pre-restore-<时间戳>），防止恢复错了无路可退
```

恢复后必须验证（**不能只说「恢复完成」**）：

| 步骤 | 断言 |
|---|---|
| 启动应用 | 无报错，界面能开 |
| 查一条抽样数据 | 字段值 == 备份时刻的值（具体到 `dueDate`/`title`） |
| **再启动一次** | 值仍是备份时刻的值（排除内存缓存） |

## 5 怎么迁移（换机器/换目录）

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 旧机器执行备份 | 备份目录生成 |
| 2 | 拷备份目录到新机器 | 文件数一致 |
| 3 | 新机器装应用并启动一次（建空库） | 能开 |
| 4 | 新机器执行恢复 | 恢复无报错 |
| 5 | 断言 3 条抽样数据 + 总条数 | 3 条值逐一相同、条数相同 |

## 6 怎么卸载

| 路径 | 处置 | 为什么这么定 |
|---|---|---|
| 主数据目录 | **保留**（先提示已备份） | 本地自用最怕误删数据 |
| 缓存目录 | 删除 | 可再生 |
| 日志目录 | 删除或保留最近 7 天 | 排查需要 |
| 配置（plist/ini） | 删除 | 重装要干净 |
| 单实例锁文件 | 删除 | 否则重启后可能拿不到锁 |

验证命令（实际跑一次并把输出贴回来）：

```bash
ls -la "<主数据目录>" ; ls -la "<缓存目录>" ; ls -la "<日志目录>" ; ls -la "<锁文件>"
```

## 7 出问题怎么办

| 现象 | 可能原因 | 处置（具体命令） |
|---|---|---|
| 启动即退出 | 数据目录无权限 / 库损坏 | `ls -la <数据目录>`；从最近备份恢复 |
| 改动没保存 | 磁盘只读 / 磁盘满 | 看日志 `保存失败` 行；`df -h`；恢复写权限 |
| 数据看起来回退了 | 开了两个实例连不同库 | 检查 `DATA_DIR`；关掉多余实例 |
| 界面卡住 | 后台写阻塞 | 看日志最后 50 行；必要时强杀后重启（已提交的写不会丢） |
