# REDLINES —— 质量红线（R1–R20 权威表）

> 复制为 项目根 `REDLINES.md`。**R 编号的权威定义只在本文件与 `00-体系总纲.md` §9；其他文档只引用，不复制、不改写、不新增编号。**
> 违反任何一条 = 交付不合格，不接受「下个版本修」。

## 用法

1. 派工（`WORK-PACKAGE`）时，把与本任务相关的 R 条目**贴进任务描述**，并写清对应检查命令。
2. 每条验收前跑一遍「怎么自动检出」列的命令；`机器可检？= 否` 的条目必须写进人工复验清单，由验证官逐条判。
3. 一条都不许删。本版不适用的，在最后一列「本版裁剪」写「不触发 + 理由」，**行必须留着**。

## 「机器可检？」三值的含义

| 值 | 含义 | 处置 |
|---|---|---|
| **是** | 一条命令/一条脚本判定，结果为 0 或非 0 | 进 `gates/rules/`，每次跑门自动判 |
| **部分** | 能给关键信号，但要人看细节（如「catch 是否留日志」要看日志内容） | 脚本出**候选清单**，验证官逐条裁定；裁定结果写进验收报告 |
| **否** | 无法自动判定（如「是否只是改了必须改的」的意图判断） | 必须进人工复验清单，写清判什么、谁判 |

> 本表**没有 `否` 条目**是刻意的：R1–R20 全部至少能给出候选清单。若你的项目出现真正无法给出信号的条目，那一列填「否」并在「本版裁剪」写明人工判定方式。

## 放行前必跑（把这九条贴进每次交付说明）

```bash
# 1 无等待式同步
grep -rn "sleep(\|Thread.Sleep\|Task.Delay" tests/ e2e/ | wc -l          # 期望 0
# 2 无内存库
grep -rn ":memory:" tests/ e2e/ | wc -l                                  # 期望 0
# 3 无空 catch
grep -rn -A2 "catch" src/ | grep -c "{}"                                 # 期望 0
# 4 无反编译代码进产品
grep -rn "decompiled\|反编译" src/ | wc -l                                # 期望 0
# 5 构建
<构建命令> 2>&1 | tail -5                                                 # Errors 0 / Warnings 0
# 6 全量测试连跑 3 次
for i in 1 2 3; do <测试命令>; done
# 7 门禁
python3 gates/run.py --stage all --project .                              # 退出码 0
# 8 联动门
python3 gates/run.py --stage G6 --project .                               # 退出码 0
# 9 改动范围
git diff --stat                                                           # 与 WP 允许路径比对
```
