# Replica OS v2.0 · 复制重建体系

> **把一个别人的应用，变成你自己一套能长期运行的独立产品。**
>
> 拆透 → 冻结蓝图 → 逐屏重建 → 证明它真的联动 → 打分告诉你差在哪。

整理：Wayen · 2026-10 · 实证来源：一次完整的本地产品重建实战（案例层已匿名化，见 [`case-todo/`](case-todo/)）

---

## 一、这是什么

一句话：**下次你说「我想做一个比 X 更好的 Y」时，不用重新想一遍流程，也不用担心做出来只有壳、内部不联动。**

它不是一份方法论，是一套**能跑的工作体系**——有自己的门禁引擎、验收工具、模板与自测。

| 你手上会得到 | 具体形态 |
|---|---|
| 一套阶段流程 | 12 个阶段，每个阶段有输入、动作、产出、门、翻车点 |
| 一套硬门禁 | 12 道门（G0–G11），可执行、四态输出、不许假绿 |
| 一套格式契约 | 蓝图 11 份 + 工程 13 份模板，另加 `SCHEMAS.md`（CSV 列名与枚举值唯一定义） |
| 一套验收工具 | 6 个命令行工具（蓝图自检 / 菜单穷举 / 联动矩阵 / 一致性评分 / 契约骨架 / 证据清单）+ 1 个公共库 |
| 一套可复用技能 | 3 个本地技能 + 11 个上游技能（MIT） |
| 一个自证 | 207 项自测（门禁 118 + 工具 89），全绿才允许发布 |

**它不做什么**：不承诺「一次规划消灭全部未知」，不承诺「完美复刻」。给的是**范围 + 分数**，不是「跟原版一样」。

## 二、它解决什么问题

### 1. 「功能清单齐了，做出来内部不联动」

**原因**：需求只列了「有哪些功能」，没列「功能之间怎么互相影响」。

**解法**：`BLUEPRINT/linkage.csv` 强制记录每一行——源事件 → 受影响控件 → **刷新时点** → 保持不变的状态 → 测试号。配 **G6 联动门**：功能标「完成」时，它的所有联动条目必须 `wired` 且有通过的测试。

**六个面必须逐个问**（不适用要写明理由，不是省略）：

```
主列表 · 侧栏角标计数 · 详情面板 · 日历/时间视图 · 搜索结果 · 提醒调度
```

真实例子：完成一个任务，不只是打钩——
① 主列表该行移入「已完成」分组；② 侧栏「今天」角标重算；③ 侧栏「已完成」+1；④ 日历里该条变灰；⑤ 搜索结果标注已完成；⑥ **取消该任务的待触发提醒**。
第 ⑥ 条如果漏了，用户会被已完成任务的提醒打扰，而功能「看起来」完全正常。

### 2. 「多层菜单做出来了，但选项该灰的不灰、该打钩的没打钩」

**原因**：把「显示条件」「可用条件」「选中条件」混成了一句「看情况」。这是三种完全不同的判断。

| 判断 | 决定什么 | 搞错的后果 |
|---|---|---|
| 显示条件 | 节点**在不在** | 显示了不该有的选项 |
| 可用条件 | **能不能点** | 该灰的能点 → 点了静默无效 |
| 选中条件 | **打不打钩** | 打钩错位 → 用户以为设置成功 |

**解法**：`menus.csv` 三列强制分开；**G2 扫禁用词**——写「按原版」「视情况」「同前」「TBD」「待定」直接 FAIL；`tools/menu_walk.py --cards` 逐叶子打印三条件卡，逼你一条条写。

### 3. 「测试全绿，用户一用就丢数据」

**原因**：三个独立缺陷，任何一个都足以丢数据——fire-and-forget 落库（不等待）、防抖 Timer 逃逸出写入链、关窗无冲刷。而早期测试**全是用固定延时等一会儿再断言**，恰好把竞态伪装成了通过。

**解法**：R1（禁固定等待）、R2（串行链 + 可 await 完成信号）、R3（关窗冲刷返回**结构化结果**，不是「方法没抛异常」）、R4（真文件 + 查具体值）、G7（故障注入 + 退出冲刷证据 + 禁内存库）。

## 四、怎么用

### 路径 A · 完整重建（默认）

```bash
# 1) 生成项目骨架（会立刻跑一次 G0，预期失败——模板还没填）
./scripts/new-project.sh ~/projects/my-clone --target "目标应用 8.x" --tier A

# 2) 填 PROJECT.md：一句话定位 / 档位 / 不做清单 ≥5 条 / 制品 SHA-256
# 3) 跑到 G0 通过
./scripts/run-gates.sh G0 --project ~/projects/my-clone

# 4) 按阶段卡顺序推进
open stages/S0-立项.md
open stages/S1-取证.md
open stages/S2-行为蓝图.md      # ← 最耗时，也最值钱
open stages/S3-审查与冻结.md    # ← 硬门槛：这里冻结，后面才允许写代码
```

### 路径 B · 已有产品，中途接入（最高频的真实用法）

先补 S1 + **反向写 S2 契约**（对已实现的代码写契约，逼出「当初没想清楚的地方」），再跑 G6 联动门找洞：

```bash
./scripts/run-gates.sh G6 --project .          # 联动门：找出「页面有、内部没联动」
python3 tools/linkage_matrix.py --project .    # 六面矩阵：哪一面还没 wire
```

中途接入**最容易发现假联动**。页面能点、按钮能按，但数据没有在六个面之间传递——这类问题只有联动矩阵能暴露。

### 路径 C · 单点使用（不走全程）

| 你只想知道 | 只跑 |
|---|---|
| 这个东西值不值得做 | S0 + S10 + 粗 S1 |
| 原版到底有哪些功能 | S1（`recon.md` + `features.csv`） |
| 某个功能到底怎么运作 | S2（单功能契约 16 节） |
| 我的版本差在哪 | S9（parity 分数 + 缺失清单） |
| 为什么用户骂它 | S10（真实评价 → 改进项） |
| 我的界面像不像 | S9 的 imgdiff + S5 的 tokens |

## 五、12 个阶段，每个阶段交什么

| 阶段 | 干什么 | 产物 | 门 |
|---|---|---|---|
| **S0 立项** | 划清「为谁解决什么」与「不做什么」 | `PROJECT.md`（含不做清单 ≥5 条）、`.replica/gate.manifest.yml` | G0 |
| **S1 取证** | 把应用拆成地图：屏幕、入口、流程、菜单、数据模型、未知台账 | `BLUEPRINT/{recon,screens,features,menus,flows,data-dictionary,unknowns}` + `evidence/MANIFEST.csv` | G1 |
| **S2 行为蓝图** ★ | 每个功能写一份 16 节契约；三条件分离；六面联动；状态机 | `BLUEPRINT/contracts/C-F-*.md`、`linkage.csv`、`state-machines.md` | G2 |
| **S3 审查冻结** ★ | 你逐条确认 → 哈希冻结 → 后续改动走变更单 | `BLUEPRINT-LOCK.md`（含逐文件 SHA-256） | G3 |
| **S4 架构** | 技术栈、表结构、命令/路由、竖切验证 | `SPEC/{ARCHITECTURE.md,schema.sql,TRACEABILITY.csv}` | G4 |
| **S5 设计系统** | tokens、组件全状态、开源图标字体替换、对比度检查 | `tokens.json`、`components.md` | G5 |
| **S6 逐屏重建** ★ | 三层状态齐、键盘可完成、过联动门 | 各屏实现 + `BUILD/build-log.md` | G6 |
| **S7 后端** ★ | 真文件持久化、串行写、结构化冲刷、故障注入 | `src/` 持久化层 + 冲刷结果断言 | G7 |
| **S8 测试** | 每流程正/负/边缘；缺陷清零；连跑 ≥3 次 | `TEST/test-plan.md`、`TEST/results/*.json`、`bugs.md` | G8 |
| **S9 一致性** | 功能分 + 界面分 + 缺失清单（实算，不许手填） | `REPORT/parity.md` | G9 |
| **S10 痛点** | 真实评价 → 改进项 → 走契约补写，不许直接进代码 | `REPORT/feedback.md` | G10 |
| **S11 发布** | A 档：本地 runbook（启动/备份/恢复/迁移/卸载） | `REPORT/release/` | G11 |

## 六、门禁：四态，不许假绿

```bash
python3 gates/run.py --project . --stage all
# [PASS] G2.feature-contracts  must 功能均有契约  证据: BLUEPRINT/features.csv:12
# [FAIL] G6.linkage-wired      F-DATE-EDIT 有 linkage 未 wired  修复: 见 BLUEPRINT/linkage.csv:8
__RESULT__ pass=41 fail=2 blocked=0 na=1
```

| 态 | 含义 | 能绕过吗 |
|---|---|---|
| `PASS` | 通过 | — |
| `FAIL` | 不过 | 不能，必须修 |
| `BLOCKED` | 环境/依赖问题 | 不能，**BLOCKED ≠ PASS** |
| `NA` | 已批准的 N/A | 必须带理由；G3 冻结后不许新增 |

退出码：`0` 全通 / `1` 有 FAIL / `2` 只有 BLOCKED。

**12 道门各查什么（一句话版）**

| 门 | 检查点 |
|---|---|
| G0 | 必需文件非占位；不做清单 ≥5 条；档位合法；目标制品可核验 |
| G1 | 清单列齐、ID 唯一；屏幕三态非空；未知项有可执行补验动作；证据受控 |
| G2 | must 功能契约齐全；16 节非空；菜单叶子有三条件与触发命令；联动行有刷新时点 |
| G3 | 冻结表有逐文件哈希；实算与记录一致；阻断级未知为 0；冻结后再改立即 FAIL |
| G4 | 每功能能追到表/命令/路由；schema 与数据字典一致；竖切证据存在 |
| G5 | tokens 通过对比度检查；组件状态齐；资源替换表无空项 |
| G6 | 标完成的功能其联动全部 wired 且测试 PASS；无 TODO 落在 must 路径 |
| G7 | 真文件持久化；冲刷返回结构化结果；故障注入通过；重启读回断言 |
| G8 | 无 S1/S2 缺陷；每功能 ≥1 e2e；全量连跑 ≥3 次结果一致 |
| G9 | parity 报告存在；功能分与 `features.csv` 实算一致 |
| G10 | 痛点带来源与计数；样本量声明；无编造条目 |
| G11 | 启动/备份/恢复/卸载有实测记录；C 档额外过合规扫描 |

## 七、「细节级产出」到底细到什么程度

这是本体系与「普通方法论」最大的区别。**七个产物，每个都有可判定的「够细」标准**：

| 产物 | 够细的标准 |
|---|---|
| `menus.csv` | 每个叶子有完整路径、顺序、类型、三条件、触发命令、契约引用；三列条件不出现「看情况」 |
| `contracts/C-F-xxx.md` | 16 节全填；第 12 节（跨页面联动）能指出具体控件与刷新时点；第 16 节每条断言对具体值 |
| `linkage.csv` | 每行有刷新时点 + 测试号；`affected_control` 写的是「主列表行日期徽标」而不是「界面刷新」 |
| `state-machines.md` | 有非法转换表；有异步结果处理 |
| `data-dictionary.md` | 每个字段有默认值、空值语义、枚举、约束、**本地映射**（双写字段选哪个权威） |
| `flows.md` | 四段齐：正常路径 / 失败与取消 / 边界 / 恢复 |
| `unknowns.csv` | 每条有**可执行的**补验动作，不是「再研究一下」 |

**反例与正例**：

- ✗「日期改了要刷新界面」
- ✓「TaskDateChanged 提交成功 → 主列表行日期徽标就地更新不重排；侧栏「今天」角标重算；详情保留焦点在日期按钮；日历该条移到新日期跨周重排；搜索按新日期重新过滤；提醒调度器重算下次触发时刻。测试 T-103 六面断言」

## 八、角色：谁都不能既当运动员又当裁判

| 角色 | 职责 | 禁止 |
|---|---|---|
| **产品官**（你） | 校正行为理解、确认体验取舍、拍板范围、真机验收 | — |
| **Lead** | 拆解、派工、跑门、关键路径攻坚 | 不写主要业务代码 |
| **蓝图工** | 取证、拆透、写契约、暴露未知 | 不得把推测写成实测 |
| **重建工** | 按契约实现、自测、同类扫描 | 不得自批验收 |
| **验证官** | 独立复现、独立重写测试 | 不改产品代码 |

**你的位置**：AI 负责拆透、举证、暴露未知、提方案；你负责校正与取舍。
未确认的蓝图不得批量开发，确认后冻结。**核心细节未经你确认，不进入批量开发**——这是硬门槛，不是建议。

## 九、生产级判据 vs 商业级判据

**生产级（A 档必须全过）**：真数据闭环 / 并发与生命周期 / 故障注入 / 干净机器装得上开得了卸得干净 / 备份可恢复 / 日志脱敏 / 密钥隔离 / 真机体验确认。

**商业级（C 档额外）**：商标域名核查 / 视觉文案命名全面切割 / 素材来源台账 / 支付退款对账端到端 / 隐私声明 / 支持流程。

**A 档的合规边界（写在这里，避免反复问）**：

- 分析对象**只限自己合法持有并已安装的软件**，目的仅限**个人学习与本地自用**
- **只读**：数据库一律操作副本；不修改原程序的二进制、签名、授权字段
- 还原代码**只当规格书读，不编入产品**（R9）；不搬运文案、图标、字体、素材
- **不绕过付费与授权机制**，不破解，不分发逆向产物
- 不做的事：品牌清扫、商标查询、商店文案、支付集成
- 超出「个人自用」的场景（对外分发、商用、上架）必须转 C 档，并做完整的权利清理

> 一句话：这套体系教的是**怎么把行为看懂、然后自己写一遍**，不是怎么改别人的程序。后者在实证中已被证明是死路——改动即失去签名与权限链，得到的是一副空壳。

```bash
# 门禁引擎自测（118 项）
python3 -m unittest discover -s gates/tests -v

# 工具自测（89 项）

# 上游 11 技能的工具测试
cd replica-skill && python3 -m unittest discover -s tests

# 重新生成单页手册（需 markdown 库）
python3 scripts/build-html.py
```

## 十四、诚实边界

**能做到**：开工前拿到完整产品全景、明确技术路线、细节级契约与依赖清晰的任务包；后续主要是按契约实现和验收；做完了能给你一个真实分数告诉你差在哪。

**不能承诺**：一次规划消灭全部未知、以后完全不改方案。正确的「先规划」是**先降低关键不确定性**，而不是把猜测写成确定方案。所以有 S3 冻结 + 变更单机制。

**也不能承诺**：完美复刻。范围 + 分数才是诚实的交付。
