## 五分钟上手

### 路径 A · 完整重建（默认）

```bash
# 1. 生成项目骨架（会立刻跑一次 G0，预期失败——模板还没填）
./scripts/new-project.sh ~/projects/my-clone --target "目标应用名 8.x" --tier A

# 2. 填 PROJECT.md（一句话定位 / 档位 / 不做清单 ≥5 条 / 制品 SHA-256）
# 3. 跑到 G0 通过
./scripts/run-gates.sh G0 --project ~/projects/my-clone

# 4. 读阶段卡，按顺序推进
open stages/S0-立项.md
open stages/S1-取证.md
open stages/S2-行为蓝图.md      # ← 最耗时，也最值钱
open stages/S3-审查与冻结.md    # ← 硬门槛：这里冻结，后面才允许写代码
```

### 路径 B · 已有产品，中途接入

先补 S1 + **反向写 S2 契约**（对已实现的代码写契约，逼出"当初没想清楚的地方"），再跑 G6 联动门找洞：

```bash
./scripts/run-gates.sh G6 --project .     # 联动门：找出"页面有、内部没联动"
python3 tools/linkage_matrix.py --project .   # 六面矩阵：哪一面还没 wire
```

中途接入**最容易发现假联动**。这是本体系最高频的真实用法。

### 路径 C · 单点使用（不走全程）

| 你只想知道 | 只跑 |
|---|---|
| 这个东西值不值得做 | S0 + S10 + 粗 S1 |

## 这套东西解决的三个具体问题

### 1. 「功能清单齐了，做出来内部不联动」

**原因**：需求只列了"有哪些功能"，没列"功能之间怎么互相影响"。

**解法**：`BLUEPRINT/linkage.csv` 强制记录每一行——源事件 → 受影响控件 → **刷新时点** → 保持不变的状态 → 测试号。加上 **G6 联动门**：功能标"完成"时，它的所有联动条目必须 `wired` 且有通过的测试。

**六个面必须逐个问**（不适用的要写明理由，不是省略）：

```
主列表 · 侧栏角标计数 · 详情面板 · 日历/时间视图 · 搜索结果 · 提醒调度
```

举个真实例子：完成一个任务，不只是打钩——① 主列表该行移入"已完成"分组；② 侧栏「今天」角标重算；③ 侧栏「已完成」+1；④ 日历里该条变灰；⑤ 搜索结果标注已完成；⑥ **取消该任务的待触发提醒**。第 ⑥ 条如果漏了，用户会被已完成任务的提醒打扰，而且功能"看起来"完全正常。

### 2. 「多层菜单做出来了，但选项该灰的不灰、该打钩的没打钩」

**原因**：把「显示条件」「可用条件」「选中条件」混成了一句"看情况"。这是三种完全不同的判断。

| 判断 | 决定什么 | 搞错的后果 |
|---|---|---|
| 显示条件 | 节点**在不在** | 显示了不该有的选项 |
| 可用条件 | **能不能点** | 该灰的能点 → 点了静默无效 |
| 选中条件 | **打不打钩** | 打钩错位 → 用户以为设置成功 |

**解法**：`menus.csv` 三列强制分开，**G2 扫禁用词**——写「按原版」「视情况」「同前」「TBD」「待定」直接 FAIL。`tools/menu_walk.py --cards` 逐叶子打印三条件卡，逼你一条条写。

### 3. 「测试全绿，用户一用就丢数据」

**原因**：三个独立缺陷，任何一个都足以丢数据：
- fire-and-forget 落库（不等待）
- 防抖 Timer 逃逸出写入链
- 关窗无冲刷

而早期测试**全是用固定延时等一会儿再断言**，恰好把竞态伪装成了通过。

**解法**：R1（禁固定等待）、R2（串行链 + 可 await 完成信号）、R3（关窗冲刷返回**结构化结果**，不是"方法没抛异常"）、R4（真文件 + 查具体值）、G7（故障注入 + 退出冲刷证据 + 禁内存库）。

## 「细节级产出」到底细到什么程度

这是本体系与"普通方法论"最大的区别。**七个产物，每个都有可判定的"够细"标准**：

| 产物 | 够细的标准 |
|---|---|
| `menus.csv` | 每个叶子有完整路径、顺序、类型、三条件、触发命令、契约引用；三列条件不出现"看情况" |
| `contracts/C-F-xxx.md` | 16 节全填；第 12 节（跨页面联动）能指出具体控件与刷新时点；第 16 节每条断言对具体值 |
| `linkage.csv` | 每行有刷新时点 + 测试号；`affected_control` 写的是"主列表行日期徽标"而不是"界面刷新" |
| `state-machines.md` | 有非法转换表；有异步结果处理 |
| `data-dictionary.md` | 每个字段有默认值、空值语义、枚举、约束、**本地映射**（双写字段选哪个权威） |
| `flows.md` | 四段齐：正常路径 / 失败与取消 / 边界 / 恢复 |
| `unknowns.csv` | 每条有**可执行的**补验动作，不是"再研究一下" |

**反例**（真实见过）：
- ✗「日期改了要刷新界面」
- ✓「TaskDateChanged 提交成功 → 主列表行日期徽标就地更新不重排；侧栏「今天」角标重算；详情保留焦点在日期按钮；日历该条移到新日期跨周重排；搜索按新日期重新过滤；提醒调度器重算下次触发时刻。测试 T-103 六面断言」

## 12 阶段一句话版

```
S0 立项        为谁解决什么 + 不做清单 ≥5 条 + 档位 + 制品身份
S1 取证        拆成地图：屏幕、入口、流程、菜单、数据模型、未知台账
S2 行为蓝图    ★ 每个功能一份 16 节契约；三条件分离；六面联动；状态机；数据字典
S3 审查冻结    ★ 你逐条确认 → 哈希冻结 → 之后改要先算影响面
S4 架构        技术栈 + 表结构 + 命令/路由 + 竖切验证
S5 设计系统    tokens + 组件全状态 + 开源图标字体替换 + 对比度检查
S6 逐屏重建    ★ 三层状态齐 + 键盘可完成 + 过联动门
S7 后端        ★ 真文件持久化 + 串行写 + 结构化冲刷 + 故障注入
S8 测试        每条流程正/负/边缘；S1/S2 缺陷清零；连跑 ≥3 次
S9 一致性      功能分 + 界面分 + 缺失清单（不许手填，必须实算）
S10 痛点       真实评价 → 改进项 → 走契约补写，不许直接进代码
S11 发布       A 档：本地 runbook（启动/备份/恢复/迁移/卸载）
```

**★ = 不能跳、不能压缩的阶段。**

## 门禁：四态，不许假绿

```bash
python3 gates/run.py --project . --stage all
# [PASS] G2.feature-contracts  must 功能均有契约  证据: BLUEPRINT/features.csv:12
# [FAIL] G6.linkage-wired     F-DATE-EDIT 有 linkage 未 wired  修复: 见 BLUEPRINT/linkage.csv:8
__RESULT__ pass=41 fail=2 blocked=0 na=1
```

| 态 | 含义 | 能绕过吗 |
|---|---|---|
| `PASS` | 通过 | — |
| `FAIL` | 不过 | 不能，必须修 |
| `BLOCKED` | 环境/依赖问题 | 不能，**BLOCKED ≠ PASS** |
| `NA` | 已批准的 N/A | 必须带理由；G3 冻结后不许新增 |

退出码：`0` 全通 / `1` 有 FAIL / `2` 只有 BLOCKED。

## 角色：谁都不能既当运动员又当裁判

| 角色 | 职责 | 禁止 |
|---|---|---|
| **产品官**（你） | 校正行为理解、确认体验取舍、拍板范围、真机验收 | — |
| **Lead** | 拆解、派工、跑门、关键路径攻坚 | 不写主要业务代码 |
| **蓝图工** | 取证、拆透、写契约、暴露未知 | 不得把推测写成实测 |
| **重建工** | 按契约实现、自测、同类扫描 | 不得自批验收 |
| **验证官** | 独立复现、独立重写测试 | 不改产品代码 |

**你的位置**：AI 负责拆透、举证、暴露未知、提方案；你负责校正与取舍。未确认的蓝图不得批量开发，确认后冻结。**核心细节未经你确认，不进入批量开发**——这是硬门槛，不是建议。

## 生产级判据 vs 商业级判据

**生产级（A 档必须全过）**：真数据闭环 / 并发与生命周期 / 故障注入 / 干净机器装得上开得了卸得干净 / 备份可恢复 / 日志脱敏 / 密钥隔离 / 真机体验确认。

**商业级（C 档额外）**：商标域名核查 / 视觉文案命名全面切割 / 素材来源台账 / 支付退款对账端到端 / 隐私声明 / 支持流程。

**A 档的合规边界（写在这里，避免反复问）**：

- 分析对象**只限自己合法持有并已安装的软件**，目的仅限**个人学习与本地自用**
- **只读**：数据库一律操作副本；不修改原程序的二进制、签名、授权字段
- 还原代码**只当规格书读，不编入产品**（R9）；不搬运文案、图标、字体、素材
- **不绕过付费与授权机制**，不破解，不分发逆向产物
- 不做的事：品牌清扫、商标查询、商店文案、支付集成
- 超出「个人自用」的场景（对外分发、商用、上架）必须转 C 档，并做完整的权利清理

> 一句话：这套体系教的是**怎么把行为看懂、然后自己写一遍**，不是怎么改别人的程序。后者在这次实证里已经被证明是死路——改动即失去签名与权限链，得到的是一副空壳。

## 诚实边界

**能做到**：开工前拿到完整产品全景、明确技术路线、细节级契约与依赖清晰的任务包；后续主要是按契约实现和验收；做完了能给你一个真实分数告诉你差在哪。

**不能承诺**：一次规划消灭全部未知、以后完全不改方案。正确的"先规划"是**先降低关键不确定性**，而不是把猜测写成确定方案。所以有 S3 冻结 + 变更单机制。

**也不能承诺**：完美复刻。范围 + 分数才是诚实的交付。
