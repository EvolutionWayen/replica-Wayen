# 用户流程

> 每个流程固定四段：正常路径 / 失败与取消 / 边界 / 恢复。缺一段即视为流程没想透。
> 相关：屏幕 `S-xx`、功能 `F-xx`、联动 `LK-xx`、用例 `T-xxx`。

---

## FL-01 访客预约一个时段

- **目标**：访客在主理人的预约页上选一个时间，填好信息，拿到确认。
- **起点**：收到链接 `https://<host>/<hostSlug>/<eventSlug>`（或扫码、带参链接）。
- **路径**：S-03 预约页 → 选时段 → S-04 信息表单 → S-05 成功页
- **点击数**（happy path）：**5 次** —— 打开链接(0) → 点时段(1) → 点「下一步」(2) → 填姓名(3) → 填邮箱(4) → 点「确认预约」(5)。键盘可完成同样 5 步。

### 正常路径

| # | 动作 | 可见结果 | 数据动作 |
|---|---|---|---|
| 1 | 打开链接 | 主理人信息 + 类型标题 + 时区行 + 日期区；时段网格骨架 80ms 后出现 | 读 eventType / availability / bookings |
| 2 | 点 15:00 槽位 | 该按钮描边+浅底；顶部汇总条出现「7月14日 周二 15:00–15:30（GMT+8）」；底栏「下一步：填写信息」由禁用变可用 | 内存选中，无持久化 |
| 3 | 点「下一步」 | 跳转 S-04，姓名空、邮箱空、时区行显示 GMT+8 | 带 `selectedSlot` 上下文 |
| 4 | 填姓名「张三」+ 邮箱 `z@ex.com` | 字段失焦后行内校验通过（无红框） | 内存草稿 |
| 5 | 点「确认预约」 | 按钮进入 loading 并禁用；约 300ms 后跳 S-05 | **写**：创建 booking + 创建 reminder（同一事务）+ 写 outbox（确认邮件） |

**成功判据**：S-05 上显示确认号、`7月14日 周二 15:00–15:30（GMT+8）`、"添加到日历"按钮。

### 失败与取消

| 情形 | 用户看到 | 系统状态 | 可恢复动作 |
|---|---|---|---|
| 邮箱格式错 | 邮箱字段下方红字「请输入有效的邮箱地址」，输入框描边变红 | 未提交 | 直接改；焦点移到第一个错误字段 |
| 姓名只有空格 | 姓名下方红字「请填写姓名」 | 未提交 | 同上 |
| 提交时该时段已被占 | 跳回 S-03，该时段消失，底部红条「此时段刚被占用，请选其它时间」 | **表单内容保留**（姓名邮箱还在） | 选新时段后再点下一步；或点「返回表单」继续改 |
| 网络断开 | 提交按钮下方灰条「网络不可用，预约未提交」 | 未提交，草稿在内存 | 恢复网络后重试；不丢草稿 |
| 服务器 500 | 红条「提交失败，请稍后重试」+「重试」按钮 | 未提交 | 点重试；或返回 |
| 用户在 S-04 点返回 | 回 S-03，**已选时段保留** | 内存 | 重新点下一步 |
| 用户在 S-04 关页面 | 无提示（草稿不保留，明确为有意差异） | 草稿丢失 | 重新走一遍 |

### 边界

| 边界 | 期望行为 | 依据 |
|---|---|---|
| 时段恰好等于 `now + minNotice` | **可选**（用 `>=`） | 契约 §6 边界表 |
| 访客时区已过该时段 | 槽位不生成 | 契约 §6 |
| 夏令时切换日 | 跳过不存在的钟面时刻 | 契约 §6 / U-002 |
| 访客连点 5 次「确认预约」 | 只创建 **1 条** booking | U-007（幂等键） |
| 邮箱超长（320 字符） | 拒绝并提示「邮箱过长」 | 契约 §7 校验 |
| 姓名含 emoji 与重音 | 允许，显示正确 | 契约 §7 |
| 同一访客二次预约同一时段 | 允许（两个不同邮箱） | 无业务限制 |
| 提交瞬间时段过期（跨过 minNotice 边界） | 服务端重校验失败 → 走「已被占用」分支 | 契约 §10 |

### 恢复

- 提交失败：草稿（姓名、邮箱、时区、已选时段）全保留在内存；重试成功前不跳转。
- 冲突失败：表单内容保留，仅时段失效；需重新选时段。
- 页面刷新：草稿**不保留**（明确为有意差异，已在契约 §14 声明）。若要保留需加持续草稿日志，属独立能力。

**相关**：契约 `C-F-BOOK-PAGE` / `C-F-FORM-SUBMIT` / `C-F-TZ-CONFIRM` / `C-F-BOOK-CONFIRM`；联动 `LK-001`–`LK-015`；用例 `T-101`–`T-115`。

## FL-02 主理人设置每周可约时间

- **目标**：主理人把"每周一三五 9:00–12:00"设为可约，访客侧立即按此生成槽位。
- **起点**：S-01 仪表盘 → 侧栏「可用时段」→ S-07。
- **路径**：S-07 可用时段 → 周视图编辑格子 → 保存 → S-03 访客侧可见
- **点击数**：进入(1) → 点周一格子(2) → 拖选 9:00–12:00(3) → 保存(4) = **4 次**（拖选算 1 次）

### 正常路径

| # | 动作 | 可见结果 | 数据动作 |
|---|---|---|---|
| 1 | 侧栏点「可用时段」 | S-07 周视图，7 列 × 1 周，已有时段显示为浅色块 | 读 availability |
| 2 | 点周一格 | 该格进入编辑态，右侧出现时间范围编辑器 | — |
| 3 | 拖选 9:00–12:00 | 网格上画出连续块；顶部显示「周一 9:00–12:00（3 小时）」 | 内存草稿 |
| 4 | 点「保存」 | 按钮短暂 loading；成功后 toast「已保存」；该格变实色 | **写**：upsert availability（按 weekday 唯一） |
| 5 | 切到访客链接 | 访客侧周一显示 09:00–12:00 之间的槽位 | 读 availability（缓存已失效） |

**成功判据**：访客侧周一的槽位数量 = (12:00−9:00) / duration，且第一天最早槽位 = 09:00。

### 失败与取消

| 情形 | 用户看到 | 系统状态 | 可恢复动作 |
|---|---|---|---|
| 拖到超出该日 24:00 | 拖选被限制在 23:59，边缘显示「已达当天末尾」 | 不写 | 继续调整 |
| 保存时另一窗口同时改了同一格 | toast「该时段已被修改，请刷新后重试」+「刷新」按钮 | 不写 | 点刷新重载，再改 |
| 拖动中点了别的格子 | 提示「当前修改未保存，确定放弃？」 | 未保存 | 确定则放弃，取消则留在编辑态 |
| 保存失败（磁盘满） | 红色 toast「保存失败：磁盘空间不足」，格子保持编辑态 | 未写 | 清理空间后重试 |
| 清空某天 | 右键格子 →「清除此天」→ 二次确认 | 写 delete | 误删可撤销 5 秒（toast 带「撤销」） |

### 边界

| 边界 | 期望行为 | 依据 |
|---|---|---|
| 设为 0 分钟（等于时长） | 不生成任何槽位 | 契约 §7 算法边界 |
| 设为 3 小时但 duration 30 分钟 | 生成 6 个槽位 | 同上 |
| 一个格子跨两个周 | 不允许（拖到日界自动截断） | — |
| 已有预约的时段被清掉 | 已存在的预约**不受影响**，只是不再接受新预约 | 契约 §3 数据写入 |
| 时区与主理人不同 | 顶部提示条「你的时区与访客不同」 | `M-AVAIL-TZ-WARN` |
| 跨午夜窗口 | A 档不支持，输入被拒绝并说明 | U-003 |

### 恢复

- 编辑未保存时关窗：提示「有未保存的修改」，可保存/放弃/取消关闭。
- 保存成功但访客侧未变：访客侧缓存 TTL 60s，最长 1 分钟内自动生效；主理人侧提供「立即刷新访客页预览」按钮。

**相关**：契约 `C-F-HOST-AVAIL`；联动 `LK-024`–`LK-026`；用例 `T-201`、`T-202`、`T-306`。

## FL-03 主理人查看近期预约

- **目标**：主理人打开仪表盘，看到本周的预约，并且**各处数字一致**。
- **起点**：登录后默认进入 S-01。
- **路径**：S-01 仪表盘（列表 + 侧栏角标 + 统计卡）
- **点击数**：0（打开即见）；筛选一次 +1

### 正常路径

| # | 动作 | 可见结果 | 数据动作 |
|---|---|---|---|
| 1 | 打开 S-01 | 侧栏「本周预约 12」；列表 12 行；标题「共 12 个」 | 读 bookings（区间查询） |
| 2 | 点列表行 | 右侧详情展开该预约 | 读单条 |
| 3 | 点侧栏「今天」 | 列表筛为今天的 3 条；角标「今天 3」 | 读（筛选下推） |
| 4 | 新访客预约（另一个标签页） | 本页在 5 秒内自动出现新行 + 角标 +1 | 事件广播 / 轮询 |

**成功判据**：列表行数 == 侧栏角标数 == 标题「共 N 个」== 数据库 COUNT。三处必须**同源同口径**。

### 失败与取消

| 情形 | 用户看到 | 系统状态 | 可恢复动作 |
|---|---|---|---|
| 加载失败 | 列表区显示「加载失败，重试」+ 按钮 | 空列表 | 点重试 |
| 某条预约已被访客取消 | 该行自动移出「近期」并入「已取消」；角标 -1 | 已同步 | 无需操作 |
| 某条预约被访客改期 | 该行时间就地更新并**按新时间重排**；焦点跟随该行 | 已同步 | 无 |
| 某条预约被删除 | 该行淡出移除 | 已同步 | 无 |
| 列表超过 50 条 | 底部「加载更多」；标题仍显示真实总数 | 分页 | 点加载更多 |

### 边界

| 边界 | 期望行为 | 依据 |
|---|---|---|
| 跨周边界 | 「本周」按主理人时区，周一 00:00–周日 23:59:59 | 契约 §6 口径 |
| 访客时区不同 | 列表时间**统一显示主理人时区**，并标注 | 契约 §3 |
| 同一时刻两条预约 | 两条都显示，不合并 | — |
| 角标与列表口径不同 | **不允许**：标题、角标、列表必须同源 | `LK-031` |
| 已取消的预约 | 不计入「本周预约」角标 | 口径定义 |
| 夏令时切换周 | 跨周判断按本地周，不按固定 168 小时 | U-002 |

### 恢复

- 网络中断：保留已加载内容 + 顶部灰条；恢复后自动重拉。
- 列表滚动位置：切到「今天」再切回「全部」，滚动位置保留。

**相关**：契约 `C-F-DASH-UPCOMING`；联动 `LK-008`、`LK-009`、`LK-017`、`LK-021`、`LK-031`；用例 `T-301`–`T-307`。
