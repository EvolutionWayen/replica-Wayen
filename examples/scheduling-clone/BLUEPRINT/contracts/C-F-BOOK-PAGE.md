# C-F-BOOK-PAGE · 访客打开预约页并看到可选时段

> 示例项目：预约调度网站（对标 Calendly 类产品）。本地自用档 A。
> 本契约演示"细节级"标准。真实项目必须按同一颗粒度写。

关联：`F-BOOK-PAGE` / 屏幕 `S-03` / 流程 `FL-01` / 数据 `E01 EventType` `E02 Availability` `E03 Booking` / 联动 `LK-001…LK-015`

---

## 1 目标与入口

**用户意图**：访客拿到一条预约链接，想知道"这个人什么时候有空、我能选哪个时间"。

**全部入口**：

| 入口 | 形态 | 前置上下文 | 备注 |
|---|---|---|---|
| 直达链接 | `https://<host>/<hostSlug>/<eventSlug>` | 无 | 主入口；分享出去的就是这条 |
| 带时区参数 | `?tz=America/New_York` | 无 | 覆盖自动检测；用于邮件签名里给人固定时区 |
| 带预选日期 | `?date=2026-07-14` | 无 | 周视图定位到该周并高亮该日 |
| 主理人预览 | 仪表盘 → 预约类型 → 预览 | 已登录且是该类型所有者 | 顶部多一条「预览模式，不会产生真实预约」 |
| 嵌入式 | 网站 `<iframe>` | 宿主页面上下文 | 必须支持 320px 宽度 |
| 二维码 | 扫码 | 移动端 | 布局按 390px 断点 |

**替代路径**：访客拿不到链接时，可从主理人公开主页 `<host>/<hostSlug>` 进入，先选类型再看时段。该主页不在本契约范围（`F-PUBLIC-PROFILE`）。

**前置上下文**：
- 不需要登录、不需要 Cookie。
- 若链接里的 `eventSlug` 不存在或已下线 → 展示友好 404，**不许**跳到主理人的其它类型（`LK-030`）。
- 若主理人主动关闭了预约（`eventType.active=false`）→ 展示"暂停接受预约"，隐藏时段网格，保留页面标题与主理人信息。

## 2 界面与层级

**从上到下的控件顺序（不可随意调换，这是原版的阅读动线）**：

```
1  主理人头像 + 名称
2  预约类型标题 + 时长徽标（如「30 分钟」）
3  时区行：「时区：Asia/Shanghai (GMT+8) ▼」        ← 可点，展开时区菜单 M-TZ-SUB
4  说明文字（主理人填写的描述，可为空；为空时整行不渲染，不留空白）
5  日期选择区：横向 7 天为一行，可翻页（← 上一周 / 下一周 →）
6  时段网格：按天分组，每天一列或一行（响应式）
7  底栏（sticky）：「下一步：填写信息」按钮
```

**层级与浮层**：

| 元素 | 层级行为 |
|---|---|
| 时区菜单 `M-TZ-SUB` | 点击时区行后在**该行下方**展开（不是模态）；再次点击或点外部收起；Esc 收起并把焦点还给时区行 |
| 时区菜单内的"手动选择" | 展开后在同一浮层内**替换**主列表为搜索框 + 列表（不新开一层），高度固定 320px，内部滚动 |
| 「此时段已不可选」提示 | 内联在该时段按钮下方，**不用** tooltip（触屏无 hover） |
| 加载态 | 时段网格区域显示骨架块，**不显示 spinner**（原版用骨架；spinner 会让页面看起来像卡住） |

**可滚动区**：只有时段网格内部在移动端可滚动（`max-height: 60vh; overscroll-behavior: contain`）；页面本身不锁滚动。桌面端不滚动，靠翻周。

**尺寸策略**：

| 元素 | 桌面 | 移动（<640px） |
|---|---|---|
| 内容最大宽度 | 720px 居中 | 100% - 32px 边距 |
| 日期列宽 | 等分（7 列） | 横向滚动，列宽 88px |
| 时段按钮高 | 40px | 44px（热区下限） |
| 底栏 | 静态在内容末尾 | sticky 底部，含安全区 padding |

**为什么不把时段做成下拉**：原版用网格是因为访客要"一眼扫出这周哪几天有空"，下拉会把这个能力去掉。这是**交互模式**，属于要复刻的部分。

## 3 每个菜单选项

时区菜单（`M-TZ-SUB`）完整结构，逐节点：

| 节点 | 完整路径 | 序 | 类型 | 默认 | 当前项 | 打开/关闭 | 鼠标跨层 | 键盘 |
|---|---|---|---|---|---|---|---|---|
| `M-TZ-AUTO` | 时区 › 自动检测 | 1 | radio | 默认选中 | `tz.mode=='auto'` 时打钩 | 选中后收起浮层 | 移出浮层 200ms 后关闭 | ↑↓ 移动，Enter 选中，Esc 关闭 |
| `M-TZ-DETECTED` | 时区 › 当前检测到：X | 2 | label | — | — | 不可点 | — | 跳过（不可聚焦） |
| `M-TZ-MANUAL` | 时区 › 手动选择 | 3 | radio | — | `tz.mode=='manual'` 时打钩 | 选中后**不收起**，就地展开搜索 | 不关闭 | Enter 展开搜索框并聚焦 |
| `M-TZ-SEARCH` | 时区 › 手动选择 › 搜索框 | 4 | action | 空 | — | — | — | 输入即过滤；↓ 进入列表 |
| `M-TZ-LIST` | 时区 › 手动选择 › 时区列表 | 5 | radio | — | 选中项打钩 | 选中后收起浮层 | 移出 200ms 关闭 | ↑↓ 移动，Enter 选中，Esc 收起 |

**关键细节（必须实现）**：
- 搜索匹配**时区 ID 与城市名两者**（输入 `shanghai` 与 `asia/shanghai` 都要命中）。
- 搜索输入为中文时，用城市的本地化名匹配（`上海` 也要命中）。
- 列表最多 300 项，超出时先按"常用时区"分组（本地时区、GMT±0、常见商务城市），再全量。
- 搜索无结果时显示「没有匹配的时区」，并提供"使用 GMT 偏移"回退入口。

日期区与时段网格不是菜单，但**有等价的"选项"语义**：
- 每个日期格有 4 态：`可选` / `已选` / `已满` / `不可约`（超出可预约窗口或主理人关闭）。
- `已满` 仍然可见且可点——点了展开当天已满提示（`M-SLOT-EMPTY`），**不是禁用**。原版如此，因为"看到这天满了"本身是信息。

## 4 显示条件

| 元素 | 显示条件 | 隐藏后的布局与焦点 |
|---|---|---|
| 说明文字行 | `eventType.description` 非空 | 不占位；下方元素上移 16px，**不做淡出动画**（避免布局跳动感） |
| 日期区 | 始终 | — |
| 「下一周 →」按钮 | 下一周内存在可预约日期 | 隐藏；右侧留白由 flex 吸收，按钮区不留空槽 |
| 「← 上一周」按钮 | 当前不在本周 | 隐藏；同上 |
| 时段网格 | 所选日期存在至少 1 个时段定义 | 隐藏并显示空态「这一天没有可预约时间」；底栏按钮保持禁用 |
| 底栏 | 始终 | — |
| 「预览模式」提示条 | 主理人预览 | — |
| 时区"与主理人不同"提示 | 访客时区 ≠ 主理人配置时区 且 已选时段 | 不显示不占位 |

**隐藏与"禁用"的区别（这条最容易做错）**：
- 「下一周」**隐藏**：因为翻过去也是空的，给按钮会让人误以为有内容。
- 已满的日期**不禁用**：因为"已满"是要传达的信息。
- 底栏按钮**禁用不禁藏**：保持布局稳定，且禁用态要能解释为什么（下方提示"请先选择时段"）。

## 5 可用与选择条件

**这一节的三件事必须分开写。**

### 5.1 可用条件（能不能点）

| 元素 | 可用条件 | 禁用时的解释 |
|---|---|---|
| 「下一周 →」 | 下一周存在 `available` 日期 | 不可见（不是禁用） |
| 已选的时段按钮 | 始终可点（用于取消选择） | — |
| 已满的日期 | 始终可点 | 点了展开「已满」提示，不是灰掉 |
| 「下一步：填写信息」 | `selectedSlot != null` | 禁用 + 下方小字「请先选择一个时间」 |
| 时区行 | 始终可点 | — |
| 时区菜单项 | 见 §3 | — |

### 5.2 选中条件（打不打钩）

| 对象 | 选中依据 | 依据来源 |
|---|---|---|
| 时区「自动检测」 | `tz.mode == 'auto'` | 持久值（本次会话 localStorage） |
| 时区「手动选择」 | `tz.mode == 'manual'` | 同上 |
| 时区列表某一项 | `tz.selected === item.id` | 同上 |
| 时段按钮 | `selectedSlot.startAt === slot.startAt` | **内存态**（不持久化；刷新后不恢复） |
| 日期格 | `viewDate === date` | 内存态 |

**关键：选中态不等于点击历史。** 例如访客先选 14:00 再选 15:00，14:00 必须取消选中——靠"比当前值"判断，不靠"记录点过谁"。

### 5.3 互斥与组合

- 时段：**单选**，必须恰好 0 或 1 个被选中。多选是错的。
- 时区：单选。
- 日期与时段：选日期不改变已选时段？——**改变**。切换日期时，若已选时段不在新日期，取消选中。这条必须写清，否则会出现"显示了 7月15日 但选中的是 7月14日的 14:00"。
- 取消选择：再次点击已选时段 → 取消选中，底栏按钮回到禁用。

## 6 筛选条件

**时段生成本身就是筛选**，规则求值顺序（顺序错会导致结果不同）：

```
1  取主理人的可用规则（按星期几 + 时间范围），展开成候选时段
2  减去已存在的预约（含 status != cancelled 的全部）
3  减去缓冲区：booking 前后各 eventType.bufferBefore / bufferAfter 分钟
4  减去"最小提前通知时间"：now + eventType.minNotice 之前全部不可选
5  减去"预约窗口上限"：now + eventType.maxWindowDays 之后全部不可选
6  按 eventType.duration 切分（步骤 1 的连续性在此被打断）
7  套用访客时区做显示转换（只在渲染层，不影响上面的计算）
```

**边界与语义（逐条必须实测，不许凭直觉）**：

| 边界 | 期望 | 为什么容易错 |
|---|---|---|
| "今天"的时段已过去一半 | 只显示"开始时间 > now + minNotice"的时段 | 用 `date == today` 判断会把已过去的时段也显示 |
| 时段恰好等于 now + minNotice | **可选**（用 `>=`，不是 `>`） | 边界符号 |
| 夏令时切换日 | 该日的真实时长可能是 23h 或 25h；时段按**本地钟面时间**切分，跳过不存在的钟面时刻 | 用 UTC 加秒数会错位一小时 |
| 跨月 31 号 | 周视图跨月正常显示，不隐藏 | — |
| 主理人改了时长（30→45 分钟） | 已存在的预约不受影响；新生成的时段按 45 分钟切分 | 若重算影响已有预约，时间会重叠 |
| 已取消的预约 | **释放**该时段 | 忘记排除 `cancelled` 会永久占用 |
| 时区变更 | 只影响显示；已生成的 `startAt` 是绝对时刻，不变 | 有人会错误地"重算时间" |

**排序**：按 `startAt` 升序；同一天内按时分升序。**不做**任何"智能排序"（原版就是时间序）。

**分组**：按日期分组，每天一个标题（`7月14日 周二`）。

**分页**：不用分页，用周翻页。**这是有意的**：分页会让访客漏看。

**角标口径**：日期格右上角显示该日**可用时段数**（如「5」）。口径：`步骤 1–6 之后剩余的小时段数`；为 0 时显示「满」而不是「0」。

## 7 业务实现逻辑

**时段生成算法**（伪代码，必须能复算）：

```
generateSlots(eventType, fromDate, toDate, tz, now):
    slots = []
    for date in [fromDate, toDate]:                       # 按访客时区的连续日期
        for window in eventType.availability[weekday(date)]:
            cursor = datetime(date, window.start, tz)
            windowEnd = datetime(date, window.end, tz)
            while cursor + duration <= windowEnd:
                candidate = (cursor, cursor + duration)
                if isBookable(candidate, eventType, now):
                    slots.append(candidate)
                cursor += duration + bufferBefore + bufferAfter
    return slots

isBookable(candidate, eventType, now):
    if candidate.start < now + minNotice:      return False
    if candidate.start > now + maxWindowDays:  return False
    if overlapsAnyBooking(candidate):          return False
    if overlapsBuffer(candidate):              return False
    return True
```

**参数与默认值**：

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `duration` | 30 | 5–480，5 的倍数 | 影响切分 |
| `bufferBefore` | 0 | 0–120 | 两个预约之间的间隔 |
| `bufferAfter` | 0 | 0–120 | |
| `minNotice` | 240 分钟 | 0–10080 | 默认 4 小时 |
| `maxWindowDays` | 60 | 1–365 | 默认两个月内可约 |

**校验（提交时）**：
- 时段必须仍在 `available` 集合内（提交时要**重新校验**，因为选择到提交之间可能被占）。
- 访客姓名：1–100 字符，trim 后非空。
- 邮箱：符合 RFC 5322 的实用子集，且**域名必须含点**。
- 时区：必须是有效 IANA ID。

**算法边界**：
- 若 `duration > 可用窗口长度` → 该窗口不产生任何时段（不是报错）。
- 若 `bufferBefore+bufferAfter >= duration` → 允许（时段会更稀疏），但要给出提示"间隔大于等于时长，时段会很稀疏"。
- 若某天可用窗口跨午夜（如 22:00–02:00）→ **A 档第一版不支持**，明确记为 `unknowns.csv` 的 `out-of-scope`，并在设置界面禁用该输入。

## 8 具体效果

**能被具体输入复算的效果表**（这是判定"够不够细"的关键）：

| 操作 | 输入 | 用户看到 |
|---|---|---|
| 打开页面 | 主理人配置 9:00–17:00 工作日，30 分钟，无缓冲，minNotice 4h，访客在 7月14日 10:30 打开 | 今天从 14:30 起显示 5 个时段（14:30/15:00/15:30/16:00/16:30），今天日期格角标「5」 |
| 点 15:00 | — | 该按钮描边 2px 主色 + 背景主色 8% 透明度；其余取消；顶部汇总条出现「7月14日 周二 15:00–15:30（GMT+8）」；底栏按钮变可用，文案「下一步：填写信息」 |
| 再点 15:00 | — | 取消选中；汇总条消失；底栏回禁用 + 小字「请先选择一个时间」 |
| 翻下一周 | — | 网格淡入 120ms（`ease-out`），骨架先出现 80ms；日期标题更新为下周；无整页刷新 |
| 切时区到纽约 | — | 时段按新时区重排；若原选中 15:00(GMT+8) 在纽约已是过去时刻 → 自动取消选中并 toast「所选时间已过去，请重新选择」 |
| 该时段被别人抢走 | 提交时后端返回冲突 | 底栏按钮变红「此时段刚被占用」；网格该时段消失；焦点移到网格首项；**保留表单已填内容** |
| 网络失败 | 断网 | 骨架停留 ≤3s 后显示「加载失败，重试」按钮；重试成功后网格淡入；**不清空已选时段**（若该时段仍可用） |

**文案规范**：
- 时段按钮：`HH:mm`（24 小时制，跟随 `locale`；美区显示 `h:mm A`）。
- 日期标题：`7月14日 周二`（中文）/ `Tue, Jul 14`（英文）。
- 时区：`Asia/Shanghai (GMT+8)`，GMT 偏移随夏令时变化（纽约会显示 GMT-4 或 GMT-5）。
- **不出现**"请稍候""出错了"这类无信息文案。

**计数与位置**：角标位置固定右上角 8px 内边距；数字变化时**不触发**整体重排（用 `min-width` 固定）。

## 9 状态变化

状态机 `SM-01 PageLoadState`：

| 状态 | 含义 | 持久化 |
|---|---|---|
| `IDLE` | 未加载 | 否 |
| `LOADING` | 骨架期 | 否 |
| `READY` | 网格可用 | 否 |
| `EMPTY` | 该周无可用时段 | 否 |
| `ERROR` | 加载失败 | 否 |
| `CONFLICT` | 提交时冲突 | 否 |

| 从 | 事件 | 守卫 | 到 | 附带动作 | 异步结果处理 |
|---|---|---|---|---|---|
| IDLE | 页面挂载 | — | LOADING | 拉 eventType + availability | 失败→ERROR |
| LOADING | 成功且 slots 非空 | — | READY | 渲染网格；写 `viewDate` | — |
| LOADING | 成功且 slots 为空 | — | EMPTY | 显示空态 | — |
| LOADING | 失败 | 重试次数<3 | LOADING | 退避 500/1500/3000ms 重试 | 3 次后→ERROR |
| READY | 选时段 | slot 仍 available | READY | 选中、更新汇总条与底栏 | — |
| READY | 选时段 | slot 已不可用 | CONFLICT | 移除该时段、toast、焦点回网格 | — |
| READY | 翻周 | — | LOADING | 保留旧网格半透明，新网格骨架覆盖 | 失败→保留旧网格 + toast |
| READY | 切换时区 | — | LOADING | 同上 | — |
| CONFLICT | 关闭 toast | — | READY | 清冲突态 | — |
| ERROR | 点重试 | — | LOADING | — | — |
| ANY | 路由离开 | — | IDLE | 取消在途请求 | 迟到结果丢弃（generation 校验） |

**非法转换**：

| 尝试 | 期望拒绝方式 | 用户看到 |
|---|---|---|
| 在 LOADING 时点时段 | 按钮 pointer-events:none | 无反应（不报错） |
| 在 EMPTY 时点底栏 | 按钮 disabled | 小字提示 |
| 快速连点两个不同时段 | 后点的生效，先点的自动取消 | 只有一个选中 |

## 10 数据读取

| 数据 | 实体/字段 | 查询 | 新鲜度 | 空/异常 |
|---|---|---|---|---|
| 主理人信息 | `E04 Host.name / avatarUrl / timezone` | 按 hostSlug | CDN 缓存 5 分钟 | 空→显示占位名「主理人」 |
| 预约类型 | `E01 EventType.*` | 按 (hostId, slug) | 每次加载实时 | 不存在→404；`active=false`→暂停页 |
| 可用规则 | `E02 Availability(weekday, startMin, endMin)` | 按 eventTypeId | 每次加载实时 | 空→EMPTY |
| 已有预约 | `E03 Booking(startAt, endAt, status)` | 区间查询 `[fromDate, toDate]` 且 `status != 'cancelled'` | 每次加载实时 | 空属正常 |
| 访客时区 | 浏览器 `Intl.DateTimeFormat().resolvedOptions().timeZone`，或 URL 参数，或 localStorage | — | 会话内稳定 | 检测失败→回退主理人时区 + 显示提示 |

**派生值**：
- `slotsPerDay`（角标）：由 §7 算法算出，**不在数据库里存**。
- `isPast`：服务端时间与客户端时间可能差几分钟，**一律以服务端时间为准**；客户端只做乐观渲染。

**数据新鲜度策略**：
- 页面停留超过 60 秒后，每次翻周重新拉一次（防止过期）。
- **不做**实时推送（明确的有意差异，写进 `DECISIONS.md`）。

**异常库行为**（这是"细节"里最容易漏的）：
- 预约表为空 → 网格显示全部可用时段。
- 可用规则为空 → EMPTY。
- 存在 `startAt` 为 `null` 的脏数据 → 跳过该行并记日志，不崩溃。
- 时区字符串非法 → 回退 `UTC` 并记日志。

## 11 数据写入

**本功能本身不写持久数据**（只读），但**有两个隐含写入**，必须写清：

| 写入 | 触发 | 字段 | 事务 | 失败 |
|---|---|---|---|---|
| 记住访客时区选择 | 访客手动改时区 | `localStorage.tz = {mode, selected}` | 非事务（localStorage） | 静默失败可接受（下次回自动） |
| 记住视图日期 | 翻周 | `localStorage.lastViewDate` | 非事务 | 同上 |

**真正写入在 `C-F-FORM-SUBMIT`**，但本契约必须明确交接：
- 提交时必须**重新校验** `selectedSlot` 仍可用（防超卖）。
- 校验失败返回 `SLOT_TAKEN`，前端进入 `CONFLICT`。

**必须不变的字段**：本功能不写业务表，故业务字段无"必须不变"的约束。两个 localStorage 写入是**可失败、可丢弃**的纯偏好，不进事务，也不会影响业务正确性——这一点必须显式写出来，否则后续实现者会误把时区偏好当成业务状态去同步。

**交接给 `C-F-FORM-SUBMIT`**：本契约只保证"选中了一个此刻可用的时段"；**不保证**提交时仍可用。防超卖必须在提交侧重新校验（见 §10 数据新鲜度与 T-109）。

## 12 跨页面联动

对应 `LK-001 … LK-015`。逐面列：

**主列表**：本页面无列表。相关联动见 `C-F-DASH-UPCOMING`。

**角标计数**：日期格角标（本页面内）与侧栏「本周可约」是两个不同口径，**必须分别定义**：
- 日期格角标 = 该日剩余时段数（本契约 §6）
- 侧栏角标 = `status=confirmed` 的预约数（在 `C-F-DASH-UPCOMING`）

**详情面板**：不适用。

**日历/时间视图**：本页面的日期与时段变化**不**影响主理人的日历视图（主理人视图按预约查，不按可用性查）。

**搜索结果**：本页面不可搜索。

**提醒调度**：不适用（本功能不产生预约）。但**切换时区时**必须给出提示，因为访客可能误以为时间改了（`LK-004` 的 state_handling 里已写明"取消选中并提示"）。

**时序**：
- 时区切换 → 立即重查（同步等待结果再渲染，不等 60s 轮询）。
- 翻周 → 立即重查。
- 两者都必须带 `generation`，迟到结果丢弃。

## 13 并发与生命周期

| 场景 | 要求 |
|---|---|
| 快速连点两个时段 | 后点生效；先点自动取消；不产生两个选中 |
| 快速连点翻周 | 只保留最后一次请求的结果；用 `generation` 丢弃迟到 |
| 选好时段 → 停留 5 分钟 → 提交 | 提交时重校验；若已失效 → CONFLICT，**保留表单** |
| 两个标签页 | 各自独立状态；不强制同步（`StorageEvent` 只同步时区偏好） |
| 浏览器返回键 | 回到本页时恢复上次选中时段？——**不恢复**（避免选中一个已失效的时段）。明确写为有意选择。 |
| 网络断开 | 显示离线提示条；已加载的网格仍可浏览（不请求）；提交按钮禁用 |
| 网络恢复 | 自动重拉一次；成功则移除提示条 |
| 移动端切后台 5 分钟 | 回到前台时若 > 60s，自动重拉一次 |
| 页面隐藏时到达提醒 | 不处理（本页面无提醒） |
| 组件卸载 | 取消在途请求，避免 setState on unmounted |

**关键**：所有异步回调在提交前必须核对 `generation === currentGeneration`，否则丢弃。

## 14 撤销与恢复

| 操作 | 可撤销 | 恢复方式 | 窗口期 |
|---|---|---|---|
| 选时段 | 是 | 再点一次 | 无限制 |
| 切换日期 | 是 | 点回原日期 | 无限制 |
| 切换时区 | 是 | 菜单里选回 | 无限制 |
