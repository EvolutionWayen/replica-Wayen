# 技术栈决策实录（目标应用案例）

> **本文件的唯一正确用法：学"怎么决策"，不要抄"决策结果"。**
> 下一个项目如果照抄"Avalonia"，几乎一定是错的——除非你的还原码也是 C#。

---

## 1. 当时的候选与打分

| 候选 | 打分维度：还原码复用率 | 苹果式体验 | 跨平台 | 维护性 | 结论 |
|---|---|---|---|---|---|
| **Avalonia + .NET + C#** | **51% 直接移植**（1,487 个文件不依赖 WPF） | 中 | 是 | 高（还原码是 C#） | 当时的答案 |
| SwiftUI + Swift | 0%（还原码是 C#） | **高** | 否 | 中 | 被排除 |
| Tauri + Web UI | 0% | 中 | 是 | 中 | 被排除 |
| Electron | 0% | 低 | 是 | 中 | 被排除 |

**决定性理由只有一条**：还原码是 C#，其中 51% 不依赖 WPF 可直接移植；原程序用的 `sqlite-net` ORM 跨平台，70 个 DAO / 29,125 行几乎零改动。

---

## 2. 这个理由为什么不该被照抄

| 如果下一个项目是 | 照抄 Avalonia 的后果 |
|---|---|
| 一个 Web 应用（如预约调度网站） | 完全用不上——应该走 TypeScript + Next.js |
| 一个原生 macOS 应用，且**体验是硬要求** | 错。Avalonia 的原生菜单/输入法/焦点/拖拽/辅助功能都要自己补，成本比 SwiftUI 高得多 |
| 一个 iOS 应用 | 错。Avalonia 在移动端体验不足 |
| 一个**没有还原码**的原创产品 | 错。"复用率"这一项直接消失，唯一决定性理由不存在了 |

**v1 的评估已经指出这个陷阱**（`01-体系评估与优化清单.md` §4.3）：把 SwiftUI 排除、Avalonia 默认推荐，不能满足所有"macOS 优先 + 苹果式体验"的产品。当时的排除是对的（因为复用率），但**不能变成通用建议**。

---

## 3. 正确的决策顺序（这才是要抄的东西）

```
1. 平台与体验硬约束（先淘汰，不能靠其他维度的高分抵消）
       ↓ 硬约束失败的候选，直接出局
2. 数据/离线/同步需求
       ↓ 决定要不要服务端、要不要本地库
3. 安全与分发（签名 / 公证 / 商店 / 内网）
       ↓ 决定能不能用某些技术
4. 团队可维护性（人和 AI 都算）
       ↓ 决定长期成本
5. 已授权资产复用（还原码 / 已有代码 / 已有组件）
       ↓ 这是加分项，不是决定项
6. 总成本（时间 + 钱 + 维护）
```

**关键**：第 5 项（复用率）在第 4 项（可维护性）之后。v1 把第 5 项放到了第一位，只在"还原码恰好是 C#"这个特定情形下才成立。

---

## 4. 无论选什么栈，这五件事必须在 S4 前验证

这些是 目标应用踩过的，跟语言无关：

| 必须验证 | 怎么验 | 不过的后果 |
|---|---|---|
| **列表虚拟化滚动** | 造 2000 条真数据，滚到底看帧率 | 数据一多就卡，越用越慢 |
| **输入法组合输入** | 用中文输入法打「联系客户」，在组合过程中按 Enter | 误提交半截拼音 |
| **焦点与选中保持** | 切视图、翻页、刷新后焦点还在原处 | 键盘用户无法使用 |
| **关窗/退出冲刷** | 改数据 → 立刻关窗 → 重开 | 数据丢（目标应用真实事故） |
| **真文件持久化 + 重启** | 真文件库，不是内存库 | 假绿，真实场景崩 |

选栈的时候就要问：**这个栈对以上五件事的支持成本是多少？** SwiftUI 前四项几乎零成本；Avalonia 第一、三、四项要写不少代码。

---

## 5. 锁定版本的具体记录（本案）

| 项 | 值 | 为什么 |
|---|---|---|
| Avalonia | **11.2.3** | 12.x 配 net8.0 不可用（`InitializeComponent` 不存在、`WithDeveloperTools` 编译错、`PathIcon` 不支持 `Stroke`、`Path` 不支持 `StrokeLineJoin`、XML 注释含 `--` 报 `AVLN1001`） |
| .NET | 8.0.426 | LTS，与 Avalonia 11.2.3 兼容 |
| ORM | sqlite-net | 原程序同款，跨平台，DAO 几乎零改动 |
| 存储 | SQLite + WAL | 单机自用足够；WAL 提升并发读 |
| 签名 | ad-hoc | 自用档；但**先验证本机稳定运行** |

**注意最后一条的风险**：ad-hoc 签名在改动二进制时会断 App Group（见 X-09）。本案的结论是"**优先走数据层，不改二进制**"。

## 6. 给下一个项目的一张空白决策表

复制这张表，填完再动手：

```markdown
## 技术栈决策（<项目名> <日期>）

### 硬约束（任一不满足直接淘汰）
| 约束 | 具体要求 | 候选是否满足 |
|---|---|---|
| 平台 | | |
| 体验下限 | 输入法/焦点/滚动/热区 | |
| 分发方式 | 本地自用 / 内网 / 商店 | |
| 数据边界 | 能否出设备 / 能否上云 | |

### 候选对比（只对通过硬约束的候选打分）
| 维度 | 权重 | 候选A | 候选B | 候选C |
|---|---|---|---|---|
| 核心任务支持成本 | | | | |
| 系统集成成本（菜单/通知/快捷键/托盘） | | | | |
| 数据层支持 | | | | |
| 可维护性（含 AI 协作） | | | | |
| 已授权资产复用 | | | | |
| 总成本 | | | | |

### 决定
选：____　理由：____　风险：____　否证条件（什么情况下改变决定）：____

### 竖切验证结果（必须实测，不许"应该可以"）
- [ ] 建 → 读 → 重启还在：____
- [ ] 2000 条滚动帧率：____
- [ ] 中文输入法组合输入：____
- [ ] 焦点在切视图后保持：____
- [ ] 关窗冲刷（改完立刻关，重开数据在）：____
```

**"否证条件"这一栏是最重要的**：写下"如果 X 发生，我们就换栈"。没有这一栏的决策，出了问题只会硬扛。
