# 取证路径（目标应用 8.x 实录）

> 目标：从"手上有一个装着别人的应用"到"手上有一份可实现的规格"。
> 本文件是可照做一遍的动作序列，不是原则。每一步都写：命令/动作 → 产出 → 判定"做对了"的标准。
>
> **前提**：A 档本地自用。数据库一律操作副本；反编译产物只当规格书（R9）。

---

## 0. 开工前先决定三件事（20 分钟，别跳过）

| 决定 | 怎么定 | 目标应用的答案 |
|---|---|---|
| 档位 | 自用 / 半自用 / 商业 | 自用 |
| 范围 | 这一版做哪个核心闭环 | 任务管理（增删改查 + 日期 + 重复 + 提醒 + 清单），不做：同步、AI、日历订阅、附件云存储 |
| 形态 | 桌面原生 / Web / Electron | 桌面（原版是混合） |

范围不定清楚，后面一定失控（X-20）。

## 1. 锁定制品（30 分钟）

```bash
# 找到实际运行的那个包（不是快捷方式）
ls -la /Applications/ | grep -i dida

# 记录身份
shasum -a 256 "/Applications/<TargetApp>.app/Contents/MacOS/<TargetApp>"
codesign -dv --verbose=4 "/Applications/<TargetApp>.app" 2>&1 | head -20

# Windows 侧（Electron + .NET 混合）
shasum -a 256 "<TargetApp>.exe"
```

**产出**：`PROJECT.md` 里的「目标制品」段——名称 + 版本 + 平台 + SHA-256 + 获取方式 + 取证日期。

**做对了的标准**：换台机器，拿到同一个包，算出的 SHA-256 一致。做不到就写"未锁定"，不要假装锁定（v1 就是在这一点上含糊，G1 只打印不比对）。

## 2. 判形态：先证伪，不靠猜（1 小时）

```bash
# 是不是 Electron？
ls "<TargetApp>.app/Contents/Resources/" | grep -E "app.asar|electron"
# 是不是 .NET？
ls "<TargetApp>.app/Contents/Resources/" | grep -E "\.dll$" | head
# 是不是原生？
file "<TargetApp>.app/Contents/MacOS/<TargetApp>"
```

**目标应用的实际情况**：Windows 版是 Electron 外壳 + .NET 程序集；macOS 版是原生。

**为什么这一步必须在前面**：形态决定工具链。Electron → 读 asar、读 renderer bundle；.NET → ILSpy/dnSpy 反编译；原生 macOS → class-dump / otool / Mach-O 解析。选错工具链，后面全白做。

## 3. 数据层优先（这是最值钱的资产，2–4 小时）

**规则**：**先复制副本**。

```bash
# 找到库（macOS 常见位置）
find ~/Library -name "*.db" -o -name "*.sqlite" 2>/dev/null | grep -i dida
find ~/Library/Containers -name "*.db" 2>/dev/null | head

# 复制到工作副本
mkdir -p /tmp/replica-work
cp "path/to/app.db" /tmp/replica-work/
shasum -a 256 "path/to/app.db" /tmp/replica-work/app.db   # 必须一致

# 只读导出结构
sqlite3 /tmp/replica-work/app.db ".schema" > evidence/schema/win-sqlite-schema.sql
sqlite3 /tmp/replica-work/app.db "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name;" > evidence/schema/tables.txt

# 每张表的列
for t in $(cat evidence/schema/tables.txt); do
  echo "## $t"
  sqlite3 /tmp/replica-work/app.db "PRAGMA table_info($t);"
done > evidence/schema/columns.txt
```

**产出**：`evidence/schema/` 下的 schema SQL、表清单、列清单；转成 `win-sqlite-schema.json`（tables + models，供复算）。

**做对了的标准**：
- 表数可复算（`len(tables)`）
- 字段数可复算（累加 columns）
- 每个结论有复算命令
- **原始库的 mtime 与 SHA-256 在操作前后一致**（证明你没动它）

**目标应用实测**：68 张具名表 / 814 列；另有 7 张表类型名在 .NET 元数据中损坏，故另一种口径记 75。**这不矛盾，是口径不同——结论性文档一律用可复算的那一个。**

## 4. 代码层：只提取"规格"，不提取"实现"（4–8 小时，按规模）

### 4.1 .NET 侧

```bash
# 用 ILSpy 命令行还原
ilspycmd -p -o win-csharp-recovered "某.dll"
# 统计规模
find win-csharp-recovered -name "*.cs" | wc -l
cat $(find win-csharp-recovered -name "*.cs") | wc -l
```

**必须同时做的三件事**：

1. **识别空壳方法**（X-08）
```bash
# 方法体为空或只有 return null/default
grep -rn -A1 "^\s*\(public\|private\|internal\).*(" win-csharp-recovered --include=*.cs \
  | grep -B1 "^\S*-\s*{\s*}$" | wc -l
```
实测 1,163 个空壳（1.9%），波及 621 个类型。**这些方法读任何属性都是 null/false/0。**

2. **提取数据模型注释与字段语义**——这是最值钱的部分（字段即需求）

3. **提取算法思路，不提取代码**——目标应用里值是 1,647 行的重复规则算法思路、30 行的三路合并

**判定"提取够了"的标准**：你能不看原代码，把重复规则的 `BYDAY`/`BYMONTHDAY`/`INTERVAL` 语义写成一张表，并且这张表能生成正确的下次触发时间。

### 4.2 Electron 侧

```bash
npx asar extract app.asar app-unpacked

# 只找三样东西：路由表、API 常量、i18n 文案
grep -rn "router\.\|path:" app-unpacked --include=*.js | head -50
grep -rnoE "https?://[a-z0-9.-]+/[a-z0-9/_-]+" app-unpacked --include=*.js | sort -u > evidence/api-endpoints.txt
```

**不要做的**：不要试图"运行起来再改"，不要在 renderer 里注入脚本抓网络（那是改别人的服务，越界）。

### 4.3 原生 macOS 侧

```bash
# 类与方法表
class-dump -H "<TargetApp>.app/Contents/MacOS/<TargetApp>" -o evidence/symbols/
# 或者用 otool 看布局（Swift 类的权威来源）
otool -oV "<TargetApp>.app/Contents/MacOS/<TargetApp>" > evidence/objc-layout.txt
```

**三条硬坑**（X-10/X-11）：
1. arm64 chained fixup 掩码 **48 位**，不是 51 位
2. Swift 类 `class_ro_t` 布局不通用，`data` 指针低 3 位带 tag；权威来源 `otool -oV`
3. **下结论前先证明有调用点**：查 `__objc_selrefs`，调用点为 0 的类是死代码，哪怕名字再像也不能写进契约

## 5. 界面与交互取证（这一步决定"像不像"，2–3 小时）

**核心方法：一层层截图 + 逐层记录**。

```bash
# macOS 窗口截图（最可靠）
screencapture -x -l $(osascript -e 'tell app "目标应用" to id of window 1') shot.png
```

**记录表**（直接对着填，别凭记忆写）：

| 层 | 操作 | 截图 | 记录什么 |
|---|---|---|---|
| L0 | 主界面 | 01.png | 整体布局、侧栏、主区、状态栏 |
| L1 | 点日期按钮 | 02.png | 弹出的浮层位置、尺寸、所有选项、哪些灰、哪个打钩 |
| L2 | 浮层里点「重复」 | 03.png | 二级浮层出来的位置（右侧？下方？） |
| L3 | 二级里点「每周」 | 04.png | 三级：选周几的按钮组 |
| L4 | 三级里点「自定义」 | 05.png | 四级：间隔/结束条件 |

**每一层都要记的四件事**：
1. 这个选项**什么时候出现**（显示条件）
2. **什么时候是灰的**（可用条件）
3. **什么时候打钩**（选中条件）
4. 层级怎么展开、怎么收回、Esc 关到哪一层、鼠标移到上一层还在不在

**本次实测的一个具体例子**：日期菜单里 `清除日期` 在"已有日期"时可用；在"只有重复没有具体日期"时**可见但禁用**。这两句话必须分开写，否则实现时一定做错。

**做对了的标准**：把 `menus.csv` 给别人看，他能不看原应用就把菜单做出来，且每个选项的出现/可用/选中行为都明确。

## 8. 规模判断（10 分钟，但决定要不要做）

| 维度 | 数 | 影响 |
|---|---|---|
| 界面 | 638 | 逐屏重建的工作量 |
| 模块 | 10 | 依赖关系复杂度 |
| 数据表 | 68 | 数据层规模 |
| API 端点 | 207 | 只影响"要不要做服务端" |
| 难点 | 重复规则 / 提醒 / 时区 / 虚拟列表 / 多窗口 | 每个难点都要在 S4 前做竖切验证 |

**给结论**：S / M / L / XL。目标应用这种规模 = **L（一个季度量级）**，且必须缩范围才做得完。

**不许承诺**"完美复刻"。给的是**范围 + 分数**，不是"跟原版一样"。

## 9. 归档（30 分钟，不做就白做）

```
evidence/
├── MANIFEST.csv            ← tools/evidence_manifest.py 生成
├── schema/                 ← 数据库结构与列清单
├── symbols/                ← 类与方法表
├── api-constants.txt       ← 端点常量
└── screens-original/       ← 原版截图（或放 screens/）
```

规则：
- **只加不改**（重跑 manifest 只追加新文件；同名文件哈希变化 → WARN，不覆盖）
- 每个文件在 MANIFEST 里有采集时间与采集方式
- 敏感内容（账号、token、真实业务数据）不入库
